# NyoruRPG 0.28.9

무림 인물 준비와 탐험·전투 연결을 보완합니다. 이전 0.28.8의 전투 상태 저장 정의·상태 효과 작성 형식 수정도 포함합니다.

- 무림 신규 인물 준비에 원래 초기 구축 요청이 누구를 위한 것인지 함께 전달합니다. 주인공의 문파·경지·별칭·무공을 새 적의 기본값으로 사용하지 않도록 구분하고, 다른 등록 인물의 이름·별칭이 섞인 응답은 적용 전에 거부합니다. 오류에는 충돌한 인물과 요청 대상을 표시합니다.
- 같은 탐험 조우의 동일 종류·동일 설명 적 여러 개체는 공유 가능한 새 준비 응답을 재사용합니다. 기존 인물의 피해·성장·사용 횟수를 복사하지 않으며, 다른 개체를 가리키는 ID가 든 자료는 재사용하지 않습니다. 저장된 개체와 사용자가 편집한 자료는 다시 만들지 않습니다.
- 탐험 결과의 다음 행동 정보에 발견한 적 ID와 실제 교전용 `rpg_play act` 연결을 추가합니다. 새 전투와 아군끼리 진행하는 전투의 관전 호출을 무림 지침에도 명시합니다. 조우 자체로 전투를 시작하거나 서술 분량·중단 지점을 정하지 않습니다.
- 놓치지마 검사에서 이동·조사 영수증을 공격·제압·처치 결과로 취급하지 않도록 안내합니다. 이미 끝났다고 서술한 전투와 저장된 적 상태가 맞지 않으면 근거 문장·대상·필요한 수정을 미해결 사항으로 남깁니다. 과거 전투를 재연하거나 피해·보상을 꾸며 맞추지 않습니다.
- 호스트 진단의 `toolVerification`에 준비 뒤 전원·모듈 확인(`chatPower`), 대화 이력 확인(`history`), 적용 직전 이력 확인(`historyBeforeApply`)의 시작·완료·실패·소요시간을 기록합니다. 채팅 본문이나 API 인증정보를 추가로 수집하지 않습니다. 확인 절차와 콜백 제한은 변경하지 않습니다.

**플러그인만 업데이트. 모듈 v1은 그대로**

기존 세이브·ID·경지표·직접 편집·영수증은 보존합니다. 이전 버전에서 이미 혼입된 인물 자료나 서술만으로 끝낸 전투는 이번 교체만으로 소급 복구되지 않습니다. 실제 출처를 확인해 현재 상태를 편집하거나 해당 답변 전으로 되돌려 처리해야 합니다.

## 확인 범위

제공된 0.28.7 백업·호스트 진단·채팅을 대조하고 필요한 소스를 수정하여 로컬 배포를 생성했습니다. 별도 최종 검사·자동/모의 전투·브라우저·실제 RisuAI·유료 API 실행은 수행하지 않았습니다. 메인 모델이 실제로 전투 호출을 수행하는지는 실사용 확인이 필요합니다. 기존 진단에서 길었던 확인 단계의 원인이 호스트 응답·저장 접근·화면 중단 중 무엇인지는 확정하지 않았습니다. 2026-10-06 사용자 승인에 따라 0.28.9와 소개글·상세 사용법을 GitHub에 게시합니다. 이 게시 작업에서 추가 실사용·모의 검수를 수행하지 않았습니다.
