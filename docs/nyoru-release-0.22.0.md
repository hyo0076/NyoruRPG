# NyoruRPG 0.22.0 이후 · 연결 모듈 전환 안내

0.22.0에서 도입했으며 GitHub의 0.22.2 배포에도 포함되는 전환 안내입니다. 일반 기능·룰북 지침·카드 디자인은 플러그인에서 관리하고, 새 설치용 모듈은 `NyoruRPG 연결 v1`로 고정합니다. 연결 규약 자체가 바뀌지 않는 한 이후에는 플러그인만 업데이트합니다.

이 안내는 0.22.4의 사용자 요청을 반영했습니다. 별도 진행 지침 선택은 제거하고 적용된 게임의 룰북을 따릅니다. 테마 설정에서 지원하지 않는 호스트 API를 호출하던 문제도 수정했습니다.

## 기존 사용자: 모듈을 지우지 않고 전환

1. 함께 받은 `NyoruRPG.js`로 플러그인을 업데이트합니다. 기존 모듈은 켜 둡니다.
2. **NyoruRPG → 시스템 구축 → 이 채팅의 카드 테마 → 기존 모듈을 연결 전용으로 전환**을 누릅니다. 시스템 재구축은 필요 없습니다.
3. 완료 안내가 나오면 **Risu 웹을 새로 고침하거나 앱을 다시 실행**합니다. 호스트가 동일 ID의 로어를 메모리에 보관할 수 있기 때문입니다.
4. 시스템 구축에서 테마와 예시를 봅니다. 룰북 지침은 이미 적용한 게임을 자동으로 따릅니다. 사용자 수정 지침과 모듈 복원은 **보관한 사용자 설정**에서 관리합니다.

현재 Risu가 부여한 모듈 ID, MCP 주소, 캐릭터·채팅의 활성화 연결을 유지합니다. 같은 모듈을 쓰는 다른 채팅도 연결 전용으로 바뀝니다. 플러그인에 저장된 테마는 유지하고, 아직 옮기지 않은 채팅의 테마는 호스트에서 읽을 수 있는 기존 토글을 가져옵니다. 공식 v3 API가 공개하지 않는 전역 전용 토글은 가져올 수 없어 기본 테마로 시작하며 시스템 구축에서 다시 선택할 수 있습니다. 이전 토글 변수와 원본 모듈은 삭제하지 않습니다.

일반 `.risum` 가져오기는 같은 ID를 교체하지 않고 새로운 ID를 부여하므로, 기존 모듈을 삭제하고 가져오는 대신 위 전환을 권합니다. [Risu 공식 가져오기 구현](https://raw.githubusercontent.com/kwaroran/Risuai/main/src/ts/process/modules.ts)

## 새 사용자

`NyoruRPG.js`와 `NyoruRPG.risum`을 설치하고 사용할 채팅/캐릭터에서 연결 모듈을 켭니다. AI 연결과 시스템 구축은 플러그인에서 진행합니다. 기존 사용자가 새 모듈 파일을 별도로 가져왔다면 기존 모듈을 켠 채 먼저 전환하여 수정 원문을 보존하세요. 중복 모듈을 여러 개 켜 둘 필요는 없습니다.

## 테마와 설정

시스템 구축에서 **카툰 / 로멘스 / 판타지 / 사이버**를 고르면 실제 카드 렌더러로 예시 한 개를 보여줍니다. 예시는 게임 판정이나 API 호출이 아닙니다.

선택은 해당 채팅에 즉시 저장되고 다음 카드 표시 갱신부터 적용됩니다. 이미 표시된 카드가 그대로면 채팅을 다시 열거나 Risu를 새로 고침하세요. 플러그인 창의 라이트/다크는 기존처럼 별도입니다.

테마와 사용자 지침 사용 여부는 채팅별 `/chat-settings`에 저장합니다. 0.22.4부터 기본 진행 지침은 실제 저장 게임의 룰북을 기준으로 합니다. 새 초안을 선택만 하고 적용하지 않았다면 기존 게임의 지침을 유지합니다. 이 변경으로 게임 규칙을 재구축하거나 편집 내용을 덮어쓰지 않습니다. 게임 백업에는 표현 설정을 선택 필드로 함께 저장하며 이전 백업도 읽습니다.

## 그대로 둔 것

- 저장 키 `urpg/v1`, 플러그인 ID `universal-rpg-engine`, MCP `plugin:nyoruRPG`, 모듈 namespace `universal-rpg`.
- 기존 세이브, 편집한 기술·장비·성장·소지품·고유 룰북 규칙. 전환하면서 게임 상태를 다시 쓰지 않습니다.
- 기존 로어 순서 100 / `@@depth 0`의 지침 위치. 사용자가 삽입 순서를 수정했다면 그 값도 보존합니다.
- 여섯 룰북의 지침 본문. 현재 상태와 짧은 행동 안내는 이전처럼 요청 끝의 `[UNIVERSAL_RPG_STATE]`에 둡니다.
- AI 도구 호출 규칙, 아군·적 자동 턴, 전투 계산, MCP 완료 응답/타임아웃 처리, 문장 옆 카드 배치.

표시 단계에서만 CSS를 붙입니다. 원본 채팅·모델 서명은 고치지 않으며, 다른 채팅의 저장 결과를 카드 참조로 읽지 않습니다. 모듈이 꺼진 채팅에는 지침/상태를 넣거나 MCP 게임 작업·자동 저장·카드 표시를 실행하지 않습니다. Risu에서 전역 활성화하면 모든 채팅에서 모듈을 켠 것으로 취급됩니다.

## 사용자 수정본과 되돌리기

전환 전에 모듈 원본 전체를 플러그인 저장소에 보관합니다. 알려진 배포 원문과 다른 지침은 수정본으로 간주해 플러그인에서 계속 사용합니다. NyoruRPG의 고정 룰북·테마 CBS 분기는 로컬에서 선택하지만, 사용자 임의 CBS 전체를 해석하지는 않습니다. 임의 표현식과 원본은 보존합니다. 자동으로 최신 기본 지침으로 덮어쓰지 않습니다. 필요하면 **보관한 사용자 설정 → 최신 기본 지침 사용**을 선택하고, 해제하여 수정본으로 돌아갑니다.

직접 추가한 로어·정규식·트리거·배경 HTML·사용자 토글은 삭제하지 않습니다. 수정된 배경 CSS는 카드 외 장식에 쓰였을 수 있어 모듈에도 보존합니다. 기본 배포 모듈은 지침·CSS·선택 UI를 제거하지만, 사용자 확장은 예외로 남습니다. 원래 지침 위치를 식별할 수 없는 변형과 페르소나 내부 모듈은 강제로 전환하지 않습니다.

**이전 모듈로 되돌리기**는 보관한 모듈을 같은 ID로 복원합니다. 전환 후 모듈을 직접 편집했다면 덮어쓰지 않도록 자동 복원을 멈춥니다. 게임 수치는 변경하지 않습니다. 구형 플러그인으로 돌아가려면 먼저 모듈을 복원한 뒤 플러그인을 교체하세요.

## 모듈에 남기는 최소 범위

MCP 연결 주소, 지침을 채울 로어 표식과 삽입 위치만 남깁니다. Risu에서 활성화된 채팅과 MCP를 연결하고 기존 프롬프트 위치를 확보하는 역할입니다. 배포 `.risum`에는 룰북 본문·테마 CSS·선택 UI가 없습니다.

구형 모듈을 전환하기 전에는 기존 모듈의 선택 지침과 CSS를 사용합니다. 구·신 모듈이 함께 들어와도 요청에는 지침 한 벌만 남깁니다. 전환 뒤부터 플러그인이 그 자리를 채웁니다.

## 실제 확인 범위

0.22.0 당시 소스 확인과 이전 범위에 한정한 자동 검사를 수행했습니다. 여섯 룰북 본문, 지침 위치·메타데이터 보존, 중복 제거, 채팅별 활성화 판단, ID/사용자 필드 보존, 테마 CSS 범위, 저장 키 분리를 다뤘지만 실제 호스트의 미지원 API 호출 문제는 찾아내지 못했습니다. 0.22.4는 사용자 오류 보고와 공식 v3 소스를 바탕으로 수정하고 배포 파일만 생성했으며 별도 최종 검사는 하지 않았습니다.

**실제 Risu 앱/모바일, Provider Manager, 메인 모델·보조 API는 실행하지 않았습니다.** 모듈 전환 권한과 재시작, 최종 요청 반영, 채팅 전환, 실제 카드 표시와 도구 호출은 사용자 환경에서 확인해야 합니다. 자동 검사가 호출 성공이나 타임아웃 해결을 입증하지는 않습니다.

공식 소스의 `beforeRequest`는 호스트의 대화 길이 계산 뒤에 실행됩니다. 본문의 삽입 위치를 유지해도 **컨텍스트 한도에 꽉 찬 대화의 길이 계산까지 이전과 같다고 보장하지는 못합니다.** 채팅을 임의로 잘라 맞추거나 호스트 설정을 바꾸지 않았습니다. 동일 지침을 보내는 것과 메인 AI의 실제 호출 행동은 별개입니다. [공식 요청 훅](https://raw.githubusercontent.com/kwaroran/Risuai/main/src/ts/process/request/request.ts), [대화 길이 계산](https://raw.githubusercontent.com/kwaroran/Risuai/main/src/ts/process/index.svelte.ts)

실사용에서는 기존 게임 전환 전후 수치/테마, 룰북이 다른 두 채팅의 분리, 모듈을 끈 채팅의 비동작, 한 행동의 호출·서술 중간 카드를 우선 확인하면 됩니다. 0.22.2는 사용자의 게시 승인으로 배포하며, 게시 승인이 위 실사용 검증을 대신하는 것은 아닙니다.
