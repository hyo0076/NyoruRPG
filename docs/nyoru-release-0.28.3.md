# NyoruRPG 0.28.3 · 택티컬·지르코트와 답변 롤백

사용자가 GitHub 게시를 승인한 0.28.3 배포입니다. 플러그인 `NyoruRPG.js`만 교체하며 연결 모듈 v1, MCP/IPC 이름, 기존 채팅·인물·세이브 식별자는 유지합니다. 실제 RisuAI 동작 확인 여부는 아래 확인 범위를 따릅니다.

## 택티컬·지르코트

두 룰북은 인물·장비·기술 준비와 전투 경로를 공유합니다. 지르코트의 실물 탄창과 부위 HP는 전용 경로에서 처리합니다.

- 인물 자료에 투척용 나이프 3개처럼 개별 장비의 수량이 들어오면 3개를 각각 저장합니다. 수량을 1개로 잘라 버리지 않으며 복제된 장비를 모두 자동 장착하지 않습니다.
- 임시 준비 세계에서 생성한 인물의 실제 장비·기술 ID를 계획에 보관하고 적용할 때 재사용합니다. 다른 인물의 기존 ID와 충돌하면 새 ID로 바꾸고 새 인물 내부의 연결만 함께 변환합니다.
- 무기·탄창의 한쪽 연결만 제공된 경우 같은 인물의 선언된 물품 ID를 기준으로 맞춥니다. 기존 인물의 무기나 탄창 연결은 수정하지 않습니다. 파츠용 `attachedTo`와 탄창용 `zirkott.weapon.magazineId` / `zirkott.magazine.loadedIn`을 구분하도록 생성 지침과 오류 안내를 보완합니다.
- 빈 선행 조건을 제거하고, 실제 기술로 정의되지 않은 `two_handed` 등 한손·양손 태그를 선행 기술로 요구하지 않습니다. 무기 자체의 사용 가능한 손·부상·방패 판정과 명시적인 실제 선행 기술은 유지합니다. 없는 선행 기술을 생성한 경우에는 기술 이름과 잘못된 참조를 안내합니다.
- 공격·조준에 대상이 없으면 보조 AI를 부르기 전에 `targets`를 지정하도록 반환합니다. 새로 등장한 대상은 이름으로 같은 호출에서 준비할 수 있습니다. 실제 공격은 저장한 전투 방식에 연결하며, 인물 등록이나 단순 시간 기록은 공격으로 처리하지 않습니다.
- 생성·등록 실패가 사용자의 발사 실패와 혼동되지 않도록 준비 중인 인물, 오류 단계, 장비 이름과 연결 정보를 반환합니다. 입력을 고치지 않은 반복 호출이나 다른 인물의 장비 해제를 해결책으로 제시하지 않도록 안내합니다.

첨부 백업에서 `정밀 조준 사격`은 초기 구축에 들어온 기술이었습니다. 고정 내장 기술이라는 근거는 없습니다. 원래 보조 모델의 완전한 응답은 없어 원문의 기술인지 추가 생성한 것인지는 확정하지 않았습니다. `two_handed`와 이후 빈 문자열 선행 조건, 개별 단검 수량 오류는 저장 자료·코드에서 확인했습니다. 탄창 오류를 낸 준비 후보의 전체 원문은 없어 그 발생 입력을 재현했다고 주장하지 않습니다. `attachedTo: null` 자체는 탄창 오류가 아닙니다.

## 답변 리롤

1. 정상적으로 저장된 답변을 Risu에서 다시 생성하면, 사용자 입력 직전까지 연결된 저장 상태를 선택하고 새 답변용 임시 저장을 만듭니다. 버린 답변의 주사위·탄약·체력·보상·인물 등록·전투·탐험·자동 검사 변경을 새 답변의 시작 상태에 남기지 않습니다.
2. 새 답변에서 필요한 도구를 호출하면 새로 판정합니다. 새 주사위가 우연히 이전과 같은 숫자가 나오는 것은 가능합니다.
3. 같은 답변의 도구 재전송·통신 재시도와 이어 쓰기는 기존 결과를 유지합니다. 리롤을 위해 이미 처리한 행동을 새로운 ID로 반복하라는 지침을 추가하지 않았습니다.
4. 다른 대체 답변을 선택하면 그 답변에 연결된 저장본으로 전환합니다. 이전 분기와 결과 카드를 삭제하거나 채팅 원문을 다시 쓰지 않습니다.
5. 사용자가 플러그인·뉴뉴로 직접 편집한 내용은 복원 기준값과 일치할 때 다시 적용합니다. 원래 대상이 사라졌거나 값이 달라졌다면 해당 편집 저장 전체를 보류하고 원본과 변경 내용을 보관합니다. **저장·복구 → 답변 리롤·되돌리기**에서 충돌 항목과 내보내기를 확인할 수 있습니다.

롤백은 공통 저장 경로에 연결하므로 D100·얼터네이티브 헌터·로맨스 판타지·미연시·에렌샤·무림·택티컬·지르코트가 같은 경계를 사용합니다. API 주소·키 같은 전역 설정은 되돌리지 않습니다. 다른 답변에 속한 미해결 검사 항목은 현재 대화에서 숨기되 기록과 사용자의 입력 초안은 삭제하지 않습니다.

### 출력 중단 또는 자동 인식이 되지 않을 때

사용하는 Risu API에는 별도의 리롤/출력 취소 알림이 없습니다. 완료된 출력 이벤트 없이 같은 사용자 입력으로 다시 요청하면 통신 재시도와 중단 후 리롤을 완전히 구분할 수 없습니다. 이를 추측해서 저장된 주사위를 버리지 않습니다.

Risu 출력을 중단한 다음 **저장·복구 → 이 답변 이전으로 되돌리기**를 누르세요. 그 뒤 Risu의 리롤로 답변을 다시 생성합니다. 이 버튼은 게임 상태를 복원하며 채팅 문장을 삭제하거나 모델을 직접 호출하지 않습니다. 버튼 이후 플러그인 화면을 새로 열어도 리롤 대기 상태를 유지합니다. 다른 대화/답변 분기를 선택하면 그 분기 연결을 따릅니다.

이전 답변에서 이미 잘못 서술된 발사·명중을 이번 업데이트가 사실로 바꾸지는 않습니다. 실패한 등록이나 판정은 수정된 입력으로 실제 호출한 결과를 따라야 합니다.

## 확인 범위

첨부 백업·추가 시도 텍스트와 두 룰북의 생성·적용·저장·오류 반환 경로, 공통 생성 경계·직접 편집·검사 알림·복구 UI를 읽고 수정했습니다. 로컬 배포 생성의 기본 구문·포장 절차만 수행했습니다.

사용자 지시에 따라 별도 정적 최종 검수, 브라우저, 모의 호스트, 가상 전투, 실제 RisuAI, 유료 API, 하위 에이전트는 실행하지 않았습니다. 따라서 실제 호스트의 리롤 이벤트 순서, 중단 후 복구, 화면 표시와 실제 모델의 수정 안내 준수는 아직 실사용으로 확인하지 않았습니다.
