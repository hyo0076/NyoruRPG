# NyoruRPG · AI 프록시 연결 방법

Yumi Provider Manager의 **모델 네트워크**에 개인 중계기를 연결하는 방법입니다. 중계기가 메인 AI에게 RPG 도구를 전달하고, 호출 결과를 받아 최종 답변까지 이어 줍니다.

```text
채팅 → Provider Manager → 내 중계기 → 메인 AI
                              ↕
                         NyoruRPG 도구
```

아래는 Risu와 중계기를 **같은 Windows PC에서 사용하는 경우**입니다. 모델 형식은 **OpenAI 호환 · Chat**을 사용합니다. Gemini도 API 제공자가 이 형식을 지원하면 연결할 수 있습니다.

## 1. 중계기 실행

처음 설치한다면 [AI 프록시가 포함된 중계기 ZIP](https://github.com/hyo0076/NyoruRPG/raw/refs/heads/main/Nyoru-Personal-MCP-Relay-0.1.0.zip)을 풀고 `start.cmd`를 실행합니다. Node.js 20 이상이 필요합니다.

기존 중계기를 업데이트한다면:

1. 중계기의 검은 실행창을 닫습니다.
2. 새 ZIP의 프로그램 파일을 기존 **`server.cjs`가 있는 폴더**에 덮어씁니다. `web` 폴더도 합칩니다.
3. **기존 `data` 폴더는 그대로 둡니다.** 연결키를 계속 사용할 수 있습니다.
4. `start.cmd`를 다시 실행합니다.

실행창에 표시된 주소를 브라우저에서 엽니다. 기본 주소는 [http://127.0.0.1:18765/](http://127.0.0.1:18765/)입니다.

실행창에는 두 종류의 키가 표시됩니다.

| 키 | 입력할 곳 |
| --- | --- |
| **Publisher key** | NyoruRPG의 중계기 설정 |
| **Consumer key** | 중계기 안내 페이지와 Provider Manager의 프록시 인증 토큰 |

플레이하는 동안 검은 실행창을 켜 두세요. 최소화해도 실행됩니다.

이미 AI 프록시 중계기로 플레이하고 있다면 중계기는 그대로 사용하고 다음 단계에서 플러그인만 업데이트하면 됩니다.

## 2. NyoruRPG 도구 등록

Risu의 플러그인을 새 **NyoruRPG.js**로 교체합니다. **NyoruRPG.risum은 기존 모듈 v1을 계속 사용**합니다.

플레이할 채팅에서 NyoruRPG를 열고 **AI 연결 → 개인 HTTP 중계기 → 연결 설정**으로 들어갑니다.

| 항목 | 입력·선택 |
| --- | --- |
| 개인 중계기 사용 | 켜기 |
| 프로바이더 연결 | **AI 프록시 · 실험** |
| 중계기 기본 주소 | `http://127.0.0.1:18765` |
| 도구 그룹 이름 | 예: `nyoruRPG1` — 이미 쓰는 이름이 있으면 유지 |
| 등록용 키 · Publisher key | 중계기 실행창의 Publisher key |
| 중계기 전송 | **RisuAI 전송** |
| 도구 결과 대기 (초) | `600` |

**저장하고 연결**을 누릅니다. **도구 등록 완료**가 나오면 아래의 **Provider Manager에 넣을 프록시 URL**을 복사합니다.

그룹 이름이 `nyoruRPG1`이면 주소는 다음과 같습니다.

```text
http://127.0.0.1:18765/ai/nyoruRPG1
```

## 3. Provider Manager에 프록시 추가

Yumi Provider Manager의 **프록시 추가**를 엽니다.

| 항목 | 입력 |
| --- | --- |
| 이름 | `Nyoru Relay` |
| 프록시 URL | 방금 복사한 `http://127.0.0.1:18765/ai/nyoruRPG1` |
| 인증 토큰 | 중계기 실행창의 **Consumer key** |

저장한 뒤 **실제로 채팅에 사용하는 모델**을 편집합니다.

| 모델 설정 | 선택 |
| --- | --- |
| 형식 | **OpenAI 호환 · Chat** |
| 네트워크 | 방금 추가한 **Nyoru Relay** |
| 도구 사용 | **사용 안 함** |

**도구 사용을 꺼도 RPG 도구는 중계기가 메인 AI에게 전달합니다.** 여기서 켜 두면 두 경로의 도구가 겹쳐 요청이 중단될 수 있습니다.

모델의 **API 주소·API 키·모델 ID는 원래 사용하던 값**을 유지하고 저장합니다.

## 4. 평소처럼 채팅

도구 처리가 끝나면 최종 답변이 한 번에 표시됩니다. Provider Manager의 **‘도구 호출 중’ 문구는 표시되지 않을 수 있습니다.**

실행 여부를 보고 싶다면 중계기 안내 페이지에 Consumer key를 넣고 **도구·주소 확인**을 누릅니다. 채팅 전후의 횟수를 비교하면 됩니다.

| 표시 | 확인할 내용 |
| --- | --- |
| AI 요청 | 모델 요청이 중계기에 도착했는지 |
| 도구 실행 요청 | 메인 AI가 도구 사용을 요청했는지 |
| 결과 수신 | 플러그인이 실행 결과를 돌려줬는지 |
| 답변 완료 | 최종 AI 답변이 만들어졌는지 |

‘도구 7개 등록’은 연결 준비 표시입니다. 실제 호출은 **도구 실행 요청·결과 수신**에서 확인합니다.

## 주소를 넣는 위치

| 주소 | 넣는 곳 |
| --- | --- |
| `http://127.0.0.1:18765` | NyoruRPG의 중계기 기본 주소 |
| `http://127.0.0.1:18765/ai/nyoruRPG1` | Provider Manager의 **프록시** → 사용할 모델의 **네트워크** |
| `http://127.0.0.1:18765/mcp/nyoruRPG1` | 기존 **MCP 서버 연결**을 사용할 때의 주소 |

이번 `/ai/` 주소는 **MCP 네트워크 설정이나 MCP 서버 URL 칸에 넣지 않습니다.**

NyoruRPG의 **기본 API → 프록시 주소**는 뉴뉴·초기 구축·놓치지마 검사에 쓰는 보조 API 설정입니다. 이미 연결해 둔 Cloudflare 프록시는 그대로 두면 됩니다.

## 연결이 멈췄을 때

| 표시·증상 | 확인 |
| --- | --- |
| AI 요청 횟수가 늘지 않음 | 실제 사용하는 모델에 프록시가 선택됐는지, 포트가 **18765**인지 확인 |
| `AI_TOOL_CONFLICT` | 해당 모델의 **도구 사용 → 사용 안 함**으로 저장 |
| `AI_NO_TOOLS` | NyoruRPG에서 저장하고 연결, URL 끝의 그룹 이름 확인 |
| `AUTH` | Provider Manager의 프록시 인증 토큰에 **Consumer key** 입력 |
| `AI_CHAT_FORMAT` | 모델 형식을 **OpenAI 호환 · Chat**으로 선택 |

나머지 오류는 같은 페이지의 **최근 중단**과 **최신 진단 내려받기**에서 확인할 수 있습니다.

## 기존 MCP 방식으로 돌아가기

NyoruRPG의 **프로바이더 연결**을 **MCP**로 저장합니다. Provider Manager 모델의 네트워크를 원래 연결로 돌리고, **도구 사용**에서 기존 NyoruRPG MCP 그룹을 다시 켭니다.
