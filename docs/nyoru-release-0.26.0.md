# NyoruRPG 0.26.0 · 로컬 테스트 배포

2026-10-03. GitHub에는 게시하지 않았습니다. 기존 연결 모듈 v1과 세이브를 유지하고 함께 받은 `NyoruRPG.js`로 플러그인만 교체합니다. 새 리얼리티·현실·하드 모드는 기본 OFF이며 탐험은 기존처럼 ON입니다.

## 구축과 오류 복구

- 초기 구축과 최종 초안 확인에서 전투 방식, 행동·지휘관 모드, 전투가 길어, 적 HP 절반과 룰북별 선택을 미리 정할 수 있습니다. 최종 적용 때 함께 저장합니다.
- 무림의 기술 수식·조건·효과·장비·checkStat 등 기계적인 스탯 참조는 OUTER, INNER, SPEECH, PRESSURE, STEALTH, INSIGHT, SENSE, KNOWLEDGE를 사용합니다. 공통 생성기의 STR 기본값을 사용하지 않습니다.
- 기존 무림의 명확한 공용 참조는 STR/CON→OUTER, INT→INNER, DEX/AGI/SEN→SENSE, WIS→INSIGHT, CHA→SPEECH으로 변환합니다. 이전 값과 경로를 보관하고, 해석할 수 없는 참조는 오류로 알립니다. 기술 이름·설명과 과거 주사위 기록을 문자열 치환하지 않습니다.
- D100·헌터·무림 인물의 movement를 정의와 런타임 저장 스키마에 연결했습니다. 이전 저장에 movement가 없어도 읽을 수 있습니다.
- 자동 구축이 실패하면 오류 코드·경로·문구·스택과 보관한 단계 자료를 볼 수 있습니다. 로그 복사·내보내기와 `해당 내용을 제작자에게 보내달라냥!` 안내를 제공합니다.
- 실패한 초안·중간 JSON은 삭제하지 않고 손편집할 수 있습니다. 값의 목적·형식·수치 기준 안내와 뉴뉴 질문을 제공합니다. 손편집 저장 자체로 현재 게임을 덮어쓰지 않으며 최종 초안 적용은 기존 확인 절차를 사용합니다. 중간 자료를 고친 경우에는 해당 구축을 다시 이어갑니다.

## 장비·탐험·직접 연결

- 명확한 갑옷·신발 등은 자연스러운 부위를 우선합니다. 특수 장비는 설명에 `자유 장착`·`부위 무관` 또는 `unusual-slot` 태그를 사용해 예외를 둘 수 있습니다. 과거 장착 상태를 일괄 강제 이동하지 않습니다.
- 진행 설정의 `탐험 사용`을 끄면 탐험 도구·준비·지도 안내가 꺼집니다. 기존 지도는 보관하며 전투·거래·일반 장소 및 시간 기록은 계속 가능합니다.
- Provider Manager 직접 연결 ON/OFF와 도구 결과 대기시간은 바꾸면 저장됩니다. 설정은 채팅별이 아닌 플러그인 연결 설정이므로 채팅마다 다시 켤 필요가 없습니다.
- 시작·채팅·룰북·전원 변경에 맞춰 직접 연결을 갱신하고, 등록 실패는 잠시 기다린 뒤 다시 연결합니다. 수동 `다시 연결`도 남겼습니다. 이 재시도는 도구 등록용이며 이미 실행한 게임 행동을 다시 호출하지 않습니다.

## 놓치지마 검사

- 검사 보완이 기존 자원·소지금·수량·능력치·성장 수치를 낮추려 하면 적용 후보와 결과를 보관하고 사용자 확인을 받습니다. 정상 도구 호출의 전투 피해나 비용에 새 확인 창을 붙이는 기능은 아닙니다.
- 미해결 화면에서 전후 값을 확인하고 적용하면 보관한 변경을 반영합니다. 보조 AI·주사위를 다시 실행하지 않습니다. 관련 상태가 그 사이 바뀌면 오래된 후보를 덮어쓰지 않고 현재 상태 편집을 안내합니다.
- 항목별 삭제·뉴뉴에게 묻기, 최근 결과 삭제와 관련 기록 내보내기를 제공합니다. 삭제는 표시 목록을 정리하며 게임 데이터를 되돌리지 않습니다. 동일 사건의 재처리를 막는 기록은 남깁니다.

## 얼터네이티브 헌터

- 기존 경험치 5배 처리를 유지합니다. 이번 패치에서 다시 5배를 곱하지 않습니다. 리얼리티 모드도 같은 경험치입니다.
- 리얼리티 ON에서 게이트 정산금은 기본 금액의 50%입니다. 도구는 `obtain rewardKind:gate_settlement`로 기본 금액을 전달하며 모델이 미리 절반으로 줄이지 않습니다.
- 신규 전리품의 재료 60%, 마정석 40%, 스킬북 1%를 기본 획득 확률로 사용합니다. 결과는 사건과 함께 저장합니다. 스킬북의 가치는 최소 100만 단위로 취급합니다. 이미 보유한 물품이나 정상 거래를 새 드랍 판정으로 지우지 않습니다.
- 새 게이트에는 절벽·막힌 길·도구가 필요한 장애물이 포함될 수 있습니다. 소유 도구의 적합성을 확인하고, 도구 없이 강행하면 보정치 d100 대신 원시 스탯과 저장 저항값을 비교합니다. 스탯이 저항값보다 커야 성공하며 동률은 실패합니다.
- 실패했다고 새 우회로를 만들지 않습니다. 다른 실제 수단이 없다면 게이트에서 나와야 합니다. 기존 지도는 재생성하지 않습니다. 도구의 물리적 적합성 판단과 새 지도 작성에는 보조 AI가 사용됩니다.

## 에렌샤 현실모드

게임 속 현실 인물의 생활 시뮬레이션입니다. 실제 컴퓨터 사용 시간이나 API 대기 시간으로 진행하지 않으며, 서술의 경과 시간을 기록한 도구 호출만 사용합니다.

| 항목 | 승인한 임시 기본값 |
|---|---|
| 월세 | 500,000원 / 30일 |
| 정기 세금 | 50,000원 / 30일 |
| 게임 이용료 | 접속한 이야기 날짜마다 10,000원 |
| 환전율 | 1골드 = 1원 |
| 환전·현금 판매 수수료 | 원금의 20% |
| 환전·현금 판매 세금 | 원금의 30% |
| 실제 수령액 | 원금의 50% · 원 미만 버림 |

원화는 게임 골드와 별도입니다. 현실 장보기로 식자재를 사고 1개를 한 끼로 소비합니다. 원화가 부족하면 장보기·선택 지불은 실패하며 정기 비용은 미납액으로 남습니다. 시작 자료에 없는 원화·식자재를 임의로 지급하지 않습니다.

피로·허기·갈증·생리현상과 건강을 추적합니다. 경고를 무시하면 몸이 약해져 게임 행동에 불이익을 받고, 건강이 소진되면 현실 인물 사망으로 사용자 아바타의 행동을 막습니다. 게임 내 부활로 현실 사망을 복구하지 않습니다. 식사·물·화장실·수면은 실제 현실 행동을 기록해야 반영됩니다.

생활 수치와 비용 설정은 일반 화면·편집기에서 숨기며 원화와 경고만 제공합니다. 세부값 변경은 **뉴뉴에게 요청 → 제안 확인 → 저장**으로 처리합니다. 예: `월세를 30만 원으로 바꿔줘`, `현재 원화 20만 원과 식자재 5개로 수정해줘`.

초기 시뮬레이션 수치는 시간당 허기 +4, 갈증 +6, 피로 +4, 생리 욕구 +7입니다. 수면 중 피로는 시간당 12 감소합니다. 필요가 누적되면 건강 감소를 계산합니다. 이 값들은 게임을 위한 기본 규칙이며 현실 건강 기준이 아닙니다.

시간은 `record(eventType:clock, minutes)` 또는 `real_life(minutes)`로 한 번 기록합니다. 이미 생활 행동에서 계산한 시간을 시각 표시에 옮길 때는 clock의 minutes를 0으로 전달합니다. 환전은 `real_life action:exchange`, 현금 물품 판매는 `cash_sale`입니다. 일반 게임 내 판매·경매와 구분합니다.

## 에렌샤 하드모드

- 숙련도 다음 레벨에 필요한 경험치가 일반 모드의 3배가 됩니다. 기존 숙련도 레벨·보유 경험치를 초기화하거나 세 배로 덮어쓰지 않습니다.
- 새 탐험 장소 작성 시 35% 확률로 초보자를 노리는 적대 이용자/PK가 등장할 수 있는 구역을 요청합니다. 첫 진입 구역은 기존처럼 안전하게 두고 전투 결과는 미리 만들지 않습니다. 이미 저장된 장소를 교체하지 않습니다.
- 탐험 OFF에서는 이 신규 장소 생성 경로도 실행되지 않습니다. 일반 서술 속 적대 이용자는 기존 인물·전투 호출로 처리합니다.

## 확인 범위

이번 작업은 소스 수정과 로컬 배포 생성입니다. 사용자 지시에 따라 별도 최종 정적 검수·브라우저·모의 전투/호스트·실제 RisuAI 실행·유료 API 호출·하위 에이전트 작업은 수행하지 않았습니다. 패키지의 과거 검사 문서는 해당 과거 버전의 기록이며 0.26.0 실사용 통과를 뜻하지 않습니다.

실제 RisuAI에서의 초기 구축 복구 화면, Provider Manager 자동 재연결, 검사 감소 승인과 각 새 모드의 플레이 확인은 남아 있습니다. 메인 AI가 시간·생활·장소·보상 호출을 누락할 가능성까지 제거했다고 주장하지 않습니다.
