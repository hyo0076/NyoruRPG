# NyoruRPG 0.22.4 · 카드 테마 오류와 룰북 선택 정리

테마 변경에서 `API method parseRisuChat not found`가 발생하던 호출을 제거했습니다. 같은 설정 읽기를 카드 표시에서도 사용했으며, 그 오류를 잡는 코드가 이미 만든 카드까지 버리고 원래 `[NyoruRPG:번호]` 문자열을 반환하고 있었습니다. 이제 테마 부가 처리에 실패해도 저장된 결과로 만든 기본 카드를 반환합니다.

## 변경

- **진행 지침의 별도 룰북 선택**을 제거했습니다. 연결 모듈 전환 후에는 시스템 구축에서 적용한 게임의 룰북을 기준으로 지침을 넣습니다. 초안 선택만으로 현재 게임을 바꾸지는 않습니다.
- 테마는 저장된 채팅 설정을 읽고, 기존 채팅별 토글이 있으면 최초 전환에 사용합니다. 호스트에 없는 템플릿 파서 API를 호출하지 않습니다.
- 사용자 수정 지침·CSS와 이전 모듈 원본은 보존합니다. 관련 선택과 복원은 **보관한 사용자 설정**에 남습니다.
- 자료 다시 읽기에서도 같은 미지원 API 호출을 제거했습니다. 최근 RP 요청에서 캡처한 프롬프트와 이미 저장된 자료를 사용합니다.
- 카드의 문단 배치, 판정 결과, 도구 완료 처리와 저장 식별자는 바꾸지 않았습니다. 실제 결과가 없는 표식에 임의의 주사위 결과를 만들지는 않습니다.

## 원인 근거와 이전 한계

공식 v2026.8.250의 API 목록에는 `parseRisuChat`이 없습니다. 샌드박스의 RPC Proxy는 임의 속성을 호출 함수로 돌려주므로 `typeof api.parseRisuChat === 'function'`으로 지원 여부를 판단할 수 없었습니다. [공식 API 목록](https://raw.githubusercontent.com/kwaroran/Risuai/v2026.8.250/src/ts/plugins/apiV3/risuai.d.ts), [샌드박스 Proxy](https://raw.githubusercontent.com/kwaroran/Risuai/v2026.8.250/src/ts/plugins/apiV3/factory.ts)

이미 플러그인에 저장된 테마는 유지합니다. 공식 API에서 노출하지 않는 구형 모듈의 전역 전용 토글은 자동으로 읽을 수 없어 아직 이전하지 않은 채팅에서는 기본 테마가 선택될 수 있습니다. 이때 시스템 구축에서 테마를 다시 선택하면 됩니다. 이전 모듈의 원문과 토글 변수는 지우지 않습니다.

사용자 수정 원문의 NyoruRPG 룰북·테마 분기는 로컬에서 선택합니다. 사용자 임의 CBS 전체를 평가하는 기능은 아니며, 해당 표현식과 원본을 보존합니다. 연결 전용으로 전환하기 전의 구형 모듈은 호스트가 기존 지침·CSS를 렌더링하는 경로를 유지합니다.

## 설치와 확인 범위

연결 모듈 v1 사용자는 **플러그인 `NyoruRPG.js`만 업데이트하고 Risu를 새로 고침**하세요. 모듈 교체·게임 재구축은 필요 없습니다. 구형 모듈 사용자는 [한 번의 연결 전환](nyoru-release-0.22.0.md)을 이용하세요.

오류 경로의 소스와 공식 API 구현을 읽고 수정했습니다. 배포 파일 생성만 진행하며 별도 최종 검사·브라우저·모의 호스트·실제 RisuAI·모델/API 테스트는 하지 않았습니다. 사용자 환경에서 테마 저장과 기존 결과 카드가 실제 표시되는지는 아직 확인하지 못했습니다.
