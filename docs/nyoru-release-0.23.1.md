# NyoruRPG 0.23.1

연결 모듈 v1은 그대로 두고 플러그인만 업데이트합니다. 기존 세이브·사용자 편집·룰북·전투 옵션·행동 게이지와 카드 배치는 유지합니다. 과거 판정을 다시 굴리거나 재생성으로 버린 답변의 상태를 현재 분기에 복원하지 않습니다.

## 대성공과 전투 대상

에렌샤에서 치명타 보정이 0이면 기본 대성공 피해가 적용되지 않고, 결과도 항상 일반 성공으로 반환하던 부분을 수정했습니다. 기본 대성공 범위는 96~100이고 공격 피해는 ×1.5입니다. 저장된 치명타 보정이 범위를 넓히면 95도 대성공이 될 수 있습니다. 생활·탈출 판정과 공통 탐험의 대성공 결과 이름도 카드로 전달합니다. 생활 보상이나 제작 품질을 새로 배수 지급하지는 않습니다.

같은 이름의 몬스터에 새 instanceKey를 지정해도 targets의 이름을 과거 명단에서 다시 찾아 쓰러진 이전 개체를 고르던 연결을 수정했습니다. 현재 호출에서 준비한 참가자를 우선 연결하고, 명시한 ID는 다른 인물로 바꾸지 않습니다. 살아 있는 동명 대상이 여럿이면 ID나 개체 키로 구분합니다. d100·헌터·무림의 같은 준비 경로도 적용했습니다.

실행 대상이 없어 공격이 실행되지 않았는데 requestedActionApplied가 true로 바뀌고 적 자동 턴이 이어지던 부분을 수정했습니다. 이제 미실행 이유와 attention을 반환하고 그 행동의 턴을 넘기지 않습니다. 실제 명중 실패·상태이상에 의한 행동 스킵·이미 처리한 NPC 단계는 정상 결과로 유지합니다.

## 서술과 탐험의 이어가기

도구 하나의 결과, 묶음 계산 한도의 도달, 전투 종료는 답변 종료 명령이 아닙니다. 원래 봇의 서술 방식과 요청 분량을 유지하고, 상위 RP에서 행동을 위임했다면 같은 답변에서 다음 필요한 도구를 순서대로 호출합니다. 전투가 길어는 반복 공방 묘사만 압축합니다. 지휘관·행동 모드·위임하지 않은 선택과 미결 반응은 여전히 기다립니다.

탐험 시작은 장소 생성·입장입니다. 후속 이동·조사·조작·채집은 각각 실제 행동이 있을 때 호출해야 합니다. 결과와 상태에 보이는 출구 및 다음 작업 안내를 포함하고, 기존 검사도 탐험 누락을 대조하도록 보완했습니다. 일상 대화에 탐험을 강제하거나 호출 횟수를 채우려고 불필요하게 반복하지 않습니다.

첨부된 0.22.9 기록에는 탐험 시작 1회가 약 47초 뒤 반환됐습니다. 해당 답변 이후 같은 사용자 입력으로 새 답변이 생성되면서 이전 상태로 분기가 돌아갔고, 새 분기에는 탐험 호출이 없습니다. 버린 분기의 탐험을 현재 상태에 임의 복원하는 대신 현재 분기에서 필요한 진입·이동을 요청하도록 안내합니다.

## 놓치지마 검사 표시와 순서 기록

검사 시작 알림만 남아 완료 후에도 검사 중으로 보이던 부분을 수정했습니다. 검사·보완 저장·완료 또는 실패 상태를 표시하며 다른 사용자 작업의 알림을 덮어쓰지 않습니다.

실행 경로는 기존처럼 검사와 데이터 보완을 await한 다음 저장 상태를 다시 읽어 메인 AI 요청에 넣습니다. 진단에 reviewRunStarted/reviewRunReturned, requestStatePrepared, beforeRequestReturned와 검사 중 afterRequest/outputReceived 관측을 남깁니다. 진단은 시간과 상태 식별 정보만 기록하며 프롬프트·API 인증을 추가로 저장하지 않습니다. 출력 도착 기록은 첫 토큰이나 모델로 요청을 실제 전송한 시각을 의미하지 않습니다.

첨부 진단의 검사 종료는 모두 답변 완료 전에 기록됐지만, 첫 글자가 나오는 시각이 없어 실제 스트리밍 중첩은 확정할 수 없습니다. 호스트 대기 시간을 임의로 늘리거나 MCP 재호출·출력 차단을 새로 넣지 않았습니다.

## 확인 범위

소스 수정, 제공된 백업·호스트 진단·현재 채팅 분기의 대조와 배포 파일 생성을 진행했습니다. 사용자 요청에 따라 별도 최종 정적 검사, 브라우저·가상 전투·모의 호스트, 실제 RisuAI·유료 API 호출 및 하위 에이전트 검수는 하지 않았습니다. 빌드 생성은 실사용 검증이 아니며, 외부 시간 초과와 모델의 분량 준수가 모두 해결됐다고 확정하지 않습니다.
