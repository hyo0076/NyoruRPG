# NyoruRPG 0.25.3 · 로컬 테스트

GitHub에는 게시하지 않았습니다. `NyoruRPG.js`로 기존 플러그인을 교체하고 Risu를 새로 고칩니다. 연결 모듈 v1과 기존 세이브를 그대로 사용하며 재구축은 필요 없습니다.

## 전투 호출

- 메인 AI가 필요한 행동을 선택해 호출하고, 실제 결과를 읽은 뒤 다음 행동을 선택하는 흐름을 유지합니다. 호출 횟수 할당량이나 중간 응답·자동 재호출은 추가하지 않았습니다.
- 일반 진행은 요청 행동과 주변 아군·적 자동 행동까지 처리하고 다음 사용자 행동을 선택하도록 반환합니다. 다음 행동은 같은 AI 답변 안에서도 호출할 수 있습니다.
- `전투가 길어`가 켜지고 행동이 위임된 경우에만 최대 6라운드, 행동 게이지는 최대 60회 행동을 묶습니다. 지휘관·행동 모드의 사용자 선택이 우선합니다. 수치·승패 규칙을 바꿔 강제로 끝내지 않습니다.
- 기존 인물은 저장 ID를 유지합니다. 같은 이름의 적을 후속 공격마다 새 키로 등록하는 것을 막고, 실제 증원은 `newInstance:true`와 고정 `instanceKey`로 구분합니다.
- 행동 응답의 반복 지침, 전체 등록 인물·완료 퀘스트 목록을 줄입니다. 실제 판정·저장 원본·카드 표식은 유지하며 명시적 조회는 계속 가능합니다.
- 호스트 진단에 새 인물 ID·전투 합류·입력 개체 키와 응답 글자 수를 기록합니다. 글자 수는 실제 모델 토큰 사용량과 다릅니다.

## 추가 요청

- 탐험의 “현재 보이는 장소를 확인했습니다. 이동만으로 장치를 조작하거나 보상을 받지 않습니다.” 문장을 삭제했습니다.
- 적 체력 감소는 등록·조회부터 감소한 현재·최대 HP를 사용합니다. 원래 최대 HP를 보존하며 호출마다 다시 절반으로 만들지 않습니다.
- 전투 종료·탈출 시 참가자의 재사용 대기시간과 준비 중인 시전을 초기화합니다. 사용 횟수, 이미 지불한 자원은 복구하지 않습니다.
- 자동 전술에 방어·회피 기술과 원거리 후퇴를 연결합니다. 시전 중인 강한 공격·낮은 체력·현재 거리를 고려하며, 같은 방어·후퇴만 계속하지 않습니다. 실제 등록 기술과 이동력·사거리 조건을 따릅니다.
- 공통 d100·헌터·무림도 자신의 차례에 방어·회피 기술을 준비할 수 있습니다. 다음 자기 차례까지 유지되며 도착한 공격에 대한 반응과 구분합니다. 준비 방어와 반응 방어를 더해 이중 경감하지 않습니다.

## 시전 대기

기술 편집 → 효과 → **공격 시전 대기**에서 0~20턴을 설정합니다. 뉴뉴의 기술 제안도 `mechanics.castTurns`를 사용할 수 있습니다.

- `0`: 즉시 사용.
- `1`: 시작 행동을 사용하고 다음 자신의 차례에 발동.
- `2`: 시작 → 다음 자기 차례에 준비 지속 → 그다음 자기 차례에 발동.

이는 실제 초 단위가 아닌 해당 인물의 차례입니다. 턴테이블·행동 게이지·자유 진행에 같은 원칙을 적용합니다. 전투 밖에는 전투 차례 대기를 만들지 않습니다.

시작·대기 중에는 피해와 명중을 만들지 않습니다. 발동 때 기존 비용·사용 횟수·재사용 대기·명중·효과를 계산합니다. 즉시 연계·반응으로 시전 대기를 건너뛰지 않습니다. 다른 행동을 고르거나 행동불능·침묵·대상 소멸·사거리 이탈 등이 생기면 취소할 수 있습니다. 시전 상태는 결과·현재 효과·미니보드에 표시합니다.

강한 적의 생성 지침에는 설정에 맞는 높은 위력·명중률·광역 기술과 시전 대기를 포함하도록 안내했습니다. 기존 적·사용자 편집 기술의 수치를 일괄 변경하지 않습니다. 기존 기술에도 사용자가 직접 시전 턴을 넣을 수 있습니다.

## 근거와 확인 범위

제공된 진단에서는 연속 공격의 대상 ID가 많고, 기록된 같은 주사위를 재사용한 결과는 없었습니다. 공통 전투 준비에서 동명 참가자의 새 개체 키를 행동 ID로 생성하는 코드를 발견해 수정했습니다. 실제 호출 인수와 당시 세이브가 없는 진단만으로 82개 대상 전부의 생성 원인을 확정하지는 않습니다.

이미 저장된 인물 중 어떤 개체가 중복인지 추정해 삭제하지 않았습니다. 기존 저장에서 불필요한 적이 전투에 남아 있으면 이 업데이트만으로 자동 제거되지는 않습니다.

이번 작업은 소스 읽기·수정과 로컬 배포 생성 범위입니다. 요청에 따라 별도 최종 검사, 모의 전투·모의 호스트·브라우저, 실제 Risu/Provider Manager·유료 API 실행은 하지 않았습니다. 설치 환경의 호출 지연·최대 토큰 문제 해결, 모델의 지침 준수와 신규 전술·시전 동작은 실사용 확인이 남아 있습니다.
