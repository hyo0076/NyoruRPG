# NyoruRPG 0.28.10 · 구축·전투 누락 복구와 모바일 화면 보완

플러그인만 업데이트. 모듈 v1은 그대로

## 바뀐 동작

택티컬·지르코트의 실패한 구축 초안에서도 능력치·숙련도 등의 수동 편집을 저장합니다. 다른 항목의 오류 때문에 고친 값까지 버리지 않으며, 남은 오류는 다음 수정 대상으로 표시합니다. 초안 저장과 현재 게임 적용은 별개입니다.

편집창 위·아래의 **초안에 저장하고 돌아가기**를 누르면 고친 자료를 보관하고 6단계 초안 목록으로 돌아옵니다. **저장하지 않고 돌아가기**는 입력을 버립니다. 편집 중에는 재시도·최종 가동·5단계로 이동하는 버튼을 함께 표시하지 않습니다.

**저장한 초안 다시 확인 · API 사용 없음**은 이미 생성된 택티컬·지르코트 후보 초안만 다시 확인합니다. 원문을 다시 생성하지 않습니다. 후보가 아직 없을 때의 **저장한 자료로 구축 이어가기**는 보관된 응답·인물 해석 자료를 이용하고, 완료하지 못한 준비에만 기존 구축 API가 필요할 수 있습니다. 이어가는 작업의 새 ID도 초기 설정 6단계에 저장합니다.

오류 화면의 **뉴뉴에게 묻기**는 선택한 실제 구축 자료와 오류를 함께 전달합니다. 손편집을 먼저 열지 않아도 수정 대상이 지정됩니다. 뉴뉴의 제안은 해당 대상의 손편집 화면에서 검토한 뒤 **수정한 자료 저장하고 돌아가기**로 보관합니다. 질문한 뒤 자료가 달라졌다면 오래된 제안으로 덮어쓰지 않습니다.

택티컬·지르코트의 저장된 AI 응답을 직접 고쳤다면 이미 해석한 인물 자료에도 해당 변경을 연결합니다. 이후 자료나 사용자의 손편집과 같은 값이 충돌하면 자동 덮어쓰기 대신 인물 해석 자료의 위치를 안내합니다. 실패한 초안은 일반 게임 요약이 읽히지 않아도 뉴뉴에게 수정 자료로 전달합니다.

## 제보 상황에서 사용하는 순서

1. 같은 채팅에서 구축 6단계의 능력치·숙련도를 편집합니다.
2. **초안에 저장하고 돌아가기**를 누릅니다. 오류가 남아 있다면 고친 값은 보관된 상태로 다음 오류를 확인합니다.
3. 자동 도움이 필요하면 오류 화면의 **뉴뉴에게 묻기 → 보내기 → 수정 제안 카드**를 사용합니다.
4. 제안을 검토해 **수정한 자료 저장하고 돌아가기**를 누릅니다. 중간 해석 자료를 고쳤다면 **저장한 자료로 구축 이어가기**로 후보를 완성합니다.
5. 오류가 없어진 초안 목록에서 **확인, 이대로 가동**을 누르면 실제 게임에 적용합니다.

이미 잃어버린 미저장 입력을 되살리는 기능은 아닙니다. 현재 보관된 초안·원본 세이브와 저장 식별자는 유지합니다.

## 작업 범위

소스에서 실패한 초안의 저장 제한, 오류 질문의 수정 자료 누락, 저장 응답과 해석 자료의 연결, 재시도와 초기 설정의 작업 ID 연결을 확인하고 수정했습니다. 배포 파일을 생성하며, 사용자의 재승인에 따라 GitHub 배포에도 포함합니다.

제보자의 정확한 오류 문구와 설치 버전은 제공되지 않았으므로 모든 택티컬 오류의 해결을 확정하지 않습니다. 사용자 지시에 따라 별도 최종 검사·브라우저·모의 호스트·전투 실행·실제 RisuAI·유료 API·하위 에이전트 작업은 수행하지 않았습니다. 빌드의 기본 구문·패키징 절차와 실제 호스트에서의 저장 확인은 구분합니다.

## 추가 제보 반영

모바일 상단에서 항목 수를 없애고 제목과 버튼 행을 분리했습니다. 현재 효과는 간결한 수치와 줄바꿈으로 보여줍니다. 행동 게이지/턴테이블에 거리 정보를 연결하고 저장된 개체 키 접미사를 표시 이름에서 줄입니다.

전투가 진행 중일 때 탐험 조우가 false가 되어 enemies.map에서 발생하던 D100 공통 준비 오류를 수정했습니다. 도구 진단에서 같은 오류가 반복되었으며 이것을 IPC 타임아웃으로 단정하지 않습니다. 같은 늑대의 완전한 조우 이름에 별도 키가 붙어 아군으로 중복 등록된 저장 패턴도 확인했습니다. 기존 인물을 먼저 찾고, 이 패턴의 중복 기록은 보관하면서 전투 참여에서 제외합니다.

최대 사거리는 장착 무기와 사용 기술 중 높은 값입니다. 장비3/기술2→3, 장비1/기술3→3, 장비4/기술1→4로 적용합니다. 장비·기술 편집 → 효과 → 사거리·거리별 명중에서 **절대 거리값**을 켜면 해당 최대값으로 고정합니다. 둘 다 켜면 사용 기술의 절대값이 우선하며 사거리 증감 효과도 고정값을 바꾸지 않습니다. 명중 보정은 별도입니다. 공통 D100·헌터·무림·에렌샤 경로에 적용되며 택티컬의 미터 계산을 네 거리 체계로 바꾸지 않습니다.

놓치지마 검사는 원문에서 처치가 명확하고 실제 처리가 누락된 경우 현재 처치·전투 종료·해당 구역·저장 보상을 보완합니다. 지난 전투를 재굴리지 않고 원래 처치/획득/구역 보상 표시로 재지급을 막습니다. 새 보상 정의를 추측하지 않으며, 정의가 없는 전리품은 미준비 정보로 남깁니다. 뉴뉴에게 검사 내용을 전달하면 scene_resolution 수정 제안을 편집해서 저장할 수 있습니다. 다른 숫자 감소에는 기존 확인 절차를 유지합니다.

뉴뉴 편집기에서 사라진 제안의 value를 읽는 경로와 중복 저장을 막았습니다. 검사 편집의 비슷한 입력 접근도 보완했습니다. 구축 재시도는 깨진 AI 응답을 다시 요청할 수 있으며 유효한 후보는 그대로 확인합니다. 생성 실패 안내와 장비 오류의 항목 위치를 표시합니다. 무림 신규 인물의 경지/필수 스탯 누락은 해당 정보만 추가 준비합니다.

저장·복구 → 답변 리롤·되돌리기 → 되돌릴 채팅 원문 불러오기에서 사용자 입력과 실제 답변을 보고 선택합니다. 선택한 입력에 답하기 전으로 게임만 복원합니다. 이전 답변을 골랐다면 Risu에서도 그 답변을 다시 생성해야 합니다. 되돌리기 취소는 현재 대화에 맞는 저장을 다시 선택합니다. 다른 채팅의 생성은 건드리지 않습니다.

첨부된 최신 백업의 교전 구역은 solved 표시가 이미 true였지만 적 HP가 남아 있고 전투는 열려 있었습니다. 지점 표시만 고치는 것과 실제 처치·전투 정산은 구분했습니다. 별도 롤백 예외 스택은 첨부 진단에서 확인되지 않았으므로 제보자의 버튼 실패 원인을 단일 원인으로 확정하지 않습니다.

행동 게이지 자체에 전투 전체의 턴 수 제한은 없습니다. 한 호출의 자동 계산에는 제한이 있어 일반 모드는 다음 플레이어 선택 지점에서, 전투가 길어는 최대 60회 자동 처리 범위에서 반환합니다. 내부 처리 단계나 미해결 선택에 따라 먼저 반환할 수 있고, 메인 AI는 권한이 허용되면 같은 답변 안에서 다음 행동을 새 호출로 이어갑니다. 이 제한 수치는 이번 수정에서 변경하지 않았습니다.

필요한 소스 수정·배포 생성과 승인된 GitHub 게시 범위입니다. 실제 RisuAI·모바일·리롤·모델/API 실행 및 별도 최종 검수는 하지 않았습니다.
