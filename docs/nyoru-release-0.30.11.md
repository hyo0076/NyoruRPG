## 뉴뉴 질문 시 장착 조건 오류 수정

질문한 장비가 장착되어 있어도 다른 장비 행동을 함께 읽다가 뉴뉴의 답변이 막힐 수 있는 경로를 수정했습니다. 장비의 설명·수식 질문·편집 제안은 미장착 상태에서도 가능하며, 실제 공격할 때 장착·소유·내구도를 확인합니다. 질문만으로 공격하거나 수치를 변경하지 않습니다.

장비 실행 오류에는 어떤 장비인지와 미장착·파손·소유자 변경 등의 실제 이유를 표시합니다. 뉴뉴 오류의 발생 단계와 해당 장비 상태는 호스트 진단에도 남깁니다.

## 성좌·퀘스트·스트리밍 함께 플레이하기

플레이 설정에서 원하는 기능을 켜면 메인 AI가 그 기능들을 함께 활용하도록 안내합니다. 두 기능만 켜도 연결하며 에렌샤는 원래 퀘스트를 사용합니다.

- **성좌 + 퀘스트:** 새 선택 의뢰의 출처로 적합한 성좌를 우선합니다. NPC에게 직접 받은 의뢰나 전직 퀘스트는 원래 출처와 조건을 유지합니다.
- **스트리밍 + 퀘스트:** 진행 중인 의뢰가 방송 소재가 됩니다. 시청자가 별도로 약속한 도전과 보상은 같은 목표 아래 표시합니다.
- **성좌 + 스트리밍:** 성좌의 부탁을 수행하면서 시청자의 응원·수락한 도전이 이어집니다. 퀘스트 토글을 추가로 켤 필요가 없습니다.
- **세 기능 함께:** 같은 목표를 중복 생성하지 않고, 원래 의뢰와 추가 약정의 성공·실패·보상을 나누어 처리합니다.

예를 들어 늑대 격퇴 목표와 “완료할 때 동료가 생존해 있으면 추가 후원”을 함께 수락했다면 격퇴 성공과 생존 조건을 따로 확인합니다. 추가 도전에 실패해도 달성한 주 목표 보상까지 취소하지 않습니다. 신앙과 방송 후원은 각 약속대로, 몬스터의 드랍과 처치 경험치는 원래 전투 계산대로 지급합니다. 후원금은 기존처럼 출금 버튼에서 20%를 공제합니다.

등록된 적 처치·구역 해결·숙련도 도달은 실제 행동 결과로 확인합니다. 협상 성공처럼 해석이 필요한 목표는 메인 AI 또는 기존 놓치지마 검사가 실제 완료 근거를 전달해야 합니다. 이미 따로 수락한 의뢰를 제목만 보고 합치지 않습니다.

임무 카드에서 목표·추가 조건·약속한 보상·지급 상태를 함께 확인합니다. 신앙 한도나 물품 자료 때문에 지급하지 못하면 **목표 달성 · 보상 대기**로 남습니다. 원인을 해결한 다음 보상 받기를 누르면 미지급분만 처리합니다. 이미 끝낸 전투를 다시 할 필요는 없습니다.

에렌샤 방송은 기본적으로 게임 화면을 송출하며 현실에서는 자리 비움으로 표시합니다. 방송 설정에서 현실 공개 장면을 포함하도록 바꿀 수 있습니다. 성좌는 계속 게임 장면에만 등장합니다.

## 무기 기본 공격·장착 행동

장착한 무기에 기본 공격을 연결합니다. 기존 무기는 기존 룰북의 공격 수치로 시작하며 무기 이름만 보고 지연·연타·추가 피해를 임의로 만들지 않습니다.

- **장비·소지품 → 장착 행동 → 기본 행동 설정**에서 이름·위력·명중·시전 대기·타격 횟수·재사용 대기를 저장합니다. 한 장비에 여러 행동을 두고 공격 하나를 기본 공격으로 지정할 수 있습니다.
- **효과·사용 조건 편집**은 해당 룰북의 실제 기술 편집기를 엽니다. D100·헌터·무림·에렌샤는 기존 시전·다단 공격·연계·발동 효과를 이용하고, 택티컬·지르코트는 기존 무기 공격과 동작 시간·위력·명중 보정을 사용합니다. 방패의 착용 중 피격 효과도 기존 효과 편집을 이용합니다.
- 평타 요청은 현재 장비의 기본 공격을 실행합니다. 무기를 벗거나 파손·양도하면 그 장비 행동을 사용할 수 없고, 다시 장착해도 재사용 대기와 사용 횟수가 초기화되지 않습니다.
- 스킬 제한 ON일 때 주무기 기본 공격은 기존 기본 공격 한 칸을 사용합니다. 추가 행동은 별도로 편성하며 패시브는 슬롯을 쓰지 않습니다. 양손에 다른 무기를 들었다면 다른 무기의 행동을 명시적으로 선택할 수 있습니다.
- 뉴뉴에게 특정 장비의 장착 행동과 효과를 요청할 수 있습니다. 편집 제안을 저장해야 실제 데이터에 적용됩니다.

## 초기 구축 후속 수정

- D100·헌터 구축에서 사거리 같은 효과가 구형 장비 효과 칸에 들어와도 올바른 효과 경로로 연결합니다. 능력치·사거리 수치와 착용 조건을 유지하며, 같은 원인으로 실패한 초안의 재시도도 재생성 없이 보완합니다.
- JEV는 주제마다 근거 하나만 고르지 않고 원문 조각을 각각 판단해 여러 근거를 채택합니다. 첫 플레이어 페르소나는 도입부 뒤의 능력·장비도 확인할 수 있도록 우선 탐색합니다.
- 자동 확장 검색에서는 현재 봇과 무관한 모듈을 제외하고 관련성이 불명확한 모듈은 보류합니다. 직접 선택한 원본은 유지하며 **초기 구축 JEV 질문·답변 보기**에서 모듈별 포함·제외·보류 이유를 확인합니다.
- 다른 자료 묶음의 원문을 생성 단계마다 반복해서 붙이지 않습니다. 필수 페르소나 원문과 앞선 구축 결과는 유지합니다. 탐색 요청 완료와 전체 원문 검토 여부도 구분합니다.

## 초기 구축 JEV · 주제별 원문 탐색

**실험 기능입니다.** `API 설정 → Jev`에서 JEV와 **데이터 준비**를 켜고 초기 구축을 시작하면 선택 자료부터 조사합니다.

- 세계관·화폐·성장 규칙·힘의 규모, 인물의 정체·능력·장비, 무림 경지를 따로 찾습니다. 부족한 주제는 현재 봇·채팅·연결 모듈의 미선택 로어북까지 확장하며 꺼진 항목도 참조합니다.
- 첫 플레이어에는 호스트에서 현재 선택하거나 채팅에 고정한 **페르소나 원문**을 연결합니다. 문장·표·JSON 등 작성 형식을 강제하지 않습니다. 원문 확보가 모든 항목을 정확히 해석했다는 뜻은 아닙니다.
- 한 번 준비한 근거를 이후 구축 단계에서 재사용합니다. 같은 자료·인물·요청·설정으로 다시 시도할 때도 재사용하며 원문이 바뀌면 구분합니다.
- **구축 초안 → 초기 구축 JEV 질문·답변 보기**에서 `사전 탐색 · 전달할 근거`와 각 단계의 `구축에 근거 재사용` 기록을 확인하세요. 주제별 원문·출처·미확인 항목·미검토 범위와 실제 요청 바이트 전후를 볼 수 있습니다.
- 탐색량에 한도를 두며 불확실한 선택 자료는 유지합니다. 답변을 확정하지 못하면 기존 구축이 이어집니다. 비용·속도·정확도 개선을 확인한 수치는 아직 없습니다.

## 에렌샤 생활 시간·욕구·현실 지출

15분이 지나면 생활 시간도 15분입니다. 기존의 숨은 5배 시간을 해제하고, 각 욕구가 필요 알림에 도달하는 시간을 기준으로 조정했습니다.

| 욕구 | 0에서 필요 알림까지 | 시간당 증가량 |
| --- | --- | --- |
| 허기 | 깨어 있는 시간 4시간 | +15 |
| 갈증 | 3시간 | +20 |
| 피로 | 16시간 | +3.75 |
| 생리 부담 | 4시간 | +18.75 |

게임 밸런스 기본값이며 **현재 상태 → 현실 생활 → 편집 → 욕구 속도·생활비·환전 설정**에서 시간을 바꿀 수 있습니다. 부담이 남아 있으면 알림은 더 일찍 옵니다. 실제 현실 수면 중에는 허기·갈증·생리 부담이 1/4 속도로 증가하고 피로가 시간당 12 회복합니다. 과거 누적 시간·수치·비용은 임의로 되돌리지 않습니다.

- 게임 이용료·전기·수도는 **경과 일수**로 정산합니다. 하루씩 일주일을 보내든 한 번에 일주일을 넘기든 같은 기준이며, 긴 경과의 요금은 한 내역에 묶습니다. 새 전기·수도 기본값은 하루 1,000원/500원이고 변경할 수 있습니다. 기존 월세·정기 세금의 30일 주기는 유지합니다.
- 돈이 있으면 자동 납부하며 부족분은 항목별 미납으로 남습니다. **이용료 미납 7일은 접속 정지**, 전기·수도는 기본 7일 유예 뒤 중단됩니다. 단전은 게임 접속도 제한합니다. 공과금의 유예일도 편집할 수 있습니다.
- **현재 상태 → 현실 생활 → 이용 요금·미납**에서 납부합니다. 오래된 요금부터 갚고 제한 기준을 벗어나면 즉시 복구됩니다. 새로운 미납이 유예 안에 남아 있어도 정상 이용할 수 있습니다. 단수 중에는 실제 외부 시설이나 준비된 식수를 사용할 수 있습니다.
- 현실에서 사 먹은 식사는 비용과 식사를 한 번에 기록합니다. 일반 구매·식자재·수입·환전·생활비도 잔액 전후를 남깁니다. **원화 입출금 내역**에서 최근 120건을 20건씩 확인합니다. 놓치지마 검사는 KRW와 영수증을 비교하고 이미 지불한 비용을 다시 차감하지 않도록 확인합니다.
- 이전 버전의 항목을 알 수 없는 체납은 기타 미납으로 보존합니다. 새 공과금은 업데이트 이후 기록한 경과부터 적용하며 과거 기간을 추정해 청구하지 않습니다.

## 성좌들의 시선 · 관계가 쌓인 뒤의 비호

- 처음 성좌 탭에는 **“어느 누구도 아직 당신을 비호하지 않습니다.”**만 표시합니다. 토글을 켰다고 기본 성좌 네 명을 미리 등록하지 않습니다.
- 여러 성좌가 이야기를 구경하며 각자 흥미·의심·감탄·무관심을 드러냅니다. 이름을 밝히지 않은 시선도 있을 수 있습니다. 모두 속사정을 아는 존재로 다루거나 한 성좌만 반복하도록 강제하지 않습니다. 스트리밍 토글은 필요하지 않습니다.
- 성좌 메시지는 선택한 카드 테마에 맞는 **전용 창**으로 나타납니다. 한 창에 여러 성좌의 `이름 | 반응`을 담습니다. 처음에는 간접 반응으로 시작하고, 관계가 쌓인 성좌부터 같은 창에서 직접 말을 겁니다.
- 의미 있는 행동·상호 교류·수락한 부탁 이행으로 **인물별·성좌별 관계**가 쌓입니다. 신앙을 소비해도 관계는 줄지 않습니다. 단순 관찰·인사·화면 조회·채팅 횟수만으로 관계를 올리지 않습니다.
- **비호가 성립할 때 다섯 가지 도움을 구축해 성좌 탭에 추가**합니다. 관찰 중인 후보들은 목록에 나타나지 않습니다. 메인 AI가 그 성좌에 맞는 도움 구성을 제출할 수 있으며, 생략하면 기록한 권능 계열로 구성합니다.
- 첫 사용 가능한 게임 장면에서 중립적인 시선을 안내하고 기존 놓치지마 검사로 실제 서술 반응도 확인합니다. 실제 성좌 창이 있는 답변에는 첫 안내를 겹쳐 표시하지 않습니다. 메시지를 출력하는 것만으로 퀘스트·신앙·보상을 지급하지 않습니다.
- 기존의 미사용 기본 명단만 정리하며 편집한 성좌와 실제 사용 기록은 보존합니다. 관계는 **성좌 → 신앙·관계·충성심 편집**에서 따로 정정할 수 있습니다. 에렌샤 현실에서는 성좌의 관찰·대사·개입을 계속 제한하며 리롤·되돌리기는 기존 저장 경계를 따릅니다.

서술 형식 예시:

```text
<성좌>
이름을 밝히지 않은 성좌|당신의 선택을 지켜보고 있습니다.
재를 줍는 방랑자|무너진 문을 보고 흥미를 드러냅니다.
침묵의 저울|아직 판단을 내리지 않습니다.
</성좌>
```

## 무림 판정 보상 · 초기 구축 JEV 답변 보기

- 무림은 화술·위압·은밀·통찰·감각·지식으로 비전투 판정합니다. 실제 주사위를 굴리면 성공·실패 모두 깨달음 기본 **+0.1**에 경지 배율과 기존 감쇠·상한을 적용합니다. 같은 처리의 재시도는 중복 지급하지 않으며 성장 고정 소환수는 제외합니다. 판정 없는 일상 대화·풍경 관찰은 성장하지 않습니다.
- **초기 구축 → 구축 초안 → 초기 구축 JEV 질문·답변 보기**에서 기록을 선택하면 보낸 질문·선택지, 실제 답변·확신도·확률, 자료 활용 결과와 요청·응답 원문을 볼 수 있습니다. **새로 고침**으로 진행 중 후속 기록도 읽고 **이 구축 로그 내려받기**로 JSON을 저장합니다. 구축 실패 뒤와 적용 완료 화면에서도 볼 수 있습니다.
- JEV를 호출하지 않은 단계는 생략 이유를 표시합니다. 상세 로그 보관이 켜져 있어야 새 기록이 남으며, 최근 200건·16MB 안에서 재시작 뒤에도 보관합니다. 목록은 5건씩, 원문은 선택한 한 건만 읽습니다. 업데이트 전 로그는 기존 API 설정의 JEV 로그 내보내기를 사용합니다.
- 위 후속 변경부터는 주제별 사전 탐색과 생성 AI에 전달한 원문 근거·재사용 기록도 함께 표시합니다. 탐색 한도가 있으므로 전체 로어북을 빠짐없이 읽었다고 표시하지 않습니다.

## 상태창·시간·성장·성좌 후속 수정

- 놓치지마 검사에서 봇 상태창도 저장값과 비교합니다. Status 한 줄·표·HTML 등 원문에 있는 형식을 검사하고, 표시 불일치는 다음 답변에 정정 자료로 전달합니다. 상태창의 숫자만으로 돈·성장·시간을 추가하지 않습니다. 실제로 누락된 사건은 기존 보완 도구를 사용합니다.
- 무림 사건 기록의 기본 성장을 제거했습니다. 실제 배움·도전을 보상할 때만 성장 비중과 근거를 지정합니다. 화술은 불확실한 설득·흥정·중재, 위압은 강압, 통찰은 거짓 간파에 연결하며 일상 대화는 판정하지 않습니다. 다른 상대에게 같은 판정 분류가 재사용되는 경로를 수정했습니다.
- 시간 보완은 실제 경과와 표시 정정을 구분합니다. 답변마다 1시간을 더하거나 단순 꽃 구경을 수련 보상으로 만드는 안내를 제한했습니다. 제보 환경의 개별 호출 원인은 실제 로그가 없어 확정하지 않았습니다.
- 성좌를 켠 뒤 사용 가능한 첫 장면의 반응 안내와 말투 자료를 보강했습니다. 대사는 메인 AI가 작성하며 반응만으로 신앙·보상을 주지 않습니다. 에렌샤 현실에서는 계속 금지됩니다.
- 에렌샤 결과 카드에서 시간 배율 표시를 제거했습니다. 실제 시간 계산과 설정은 유지합니다.
- 이동 연계 기술과 초기 구축 JEV 사전 검색은 [설계안](이동-연계와-초기구축-JEV-설계.md)으로 정리했습니다. 아직 실행 기능을 추가한 것은 아닙니다.

## 화면을 열 때의 메모리 사용 개선

- 일반 RPG 화면에서 과거 저장본·작업 기록 전체를 불러오던 처리를 제거했습니다. **저장·복구**에서는 작은 목록을 먼저 사용하고 실제 복원에 필요한 저장본을 읽습니다.
- 기존 저장의 목록 정보가 없으면 **처음 기록을 열거나 과거 분기를 찾을 때** 하나씩 준비합니다. 기록이 많으면 첫 준비에 시간이 걸릴 수 있으며 원본 게임 기록은 삭제하지 않습니다.
- 미니 상태는 인물 이름과 현재 페이지의 표시 내용만 남깁니다. 게임 상태 전체를 별도로 복제해 계속 보관하지 않으며, 준비된 화면을 펼치는 동작은 유지합니다. 아직 보지 않은 탭·페이지는 선택할 때 준비합니다.
- 저장본·카드·미니 페이지 캐시에 용량 상한을 추가했습니다. 저장 후 확인은 유지하면서 같은 JSON 문자열을 다시 풀고 복사하는 과정을 줄였습니다.
- 놓치지마 검사에서 최근 행동의 인자를 읽을 때 과거 작업 전체를 여러 개 보관하던 처리도 줄였습니다. 저장·리롤·보상·지도 형식은 유지합니다.
- 소스 수정과 로컬 배포 생성 범위입니다. 실제 Risu에서 OOM이 해소됐는지와 실사용 메모리 감소량은 확인하지 않았습니다.

## 파츠 부착·장비 설정 수정

- **장비 → 붙일 장비 카드 → 파츠 붙이기 → 보유 물품 선택 → 부착**으로 사용합니다. 별도의 부착 칸을 먼저 만들 필요가 없습니다.
- 예: **은빛 갈기의 참월도 → 파츠 붙이기 → 고대 장인의 서리 칼끈 → 부착**. 기존 종류가 장신구여도 파츠로 붙일 수 있습니다. 별도로 착용하고 있다면 먼저 착용을 해제합니다.
- 부착 전 저장된 효과와 부착 가능 여부가 표시됩니다. 수치 효과가 없는 물품은 없다고 표시하며 임의 효과를 만들지 않습니다. 이미 지정된 위치·종류·호환 장비 제한은 지킵니다.
- 붙인 장비를 착용하면 파츠의 기존 장비 효과·명중 시 효과와 추가 보정이 연결됩니다. **분리**하면 물품은 소지품에 남습니다. 여러 개가 묶인 파츠는 한 개만 나눠 붙입니다.
- 긴 **장비·소지품 선택 기능** 중복 목록을 제거했습니다. 무게·사거리·장전 등 켜진 기능은 원래 물품 카드의 설정 버튼에서 직접 수정하고 **변경 저장**합니다. 뉴뉴 요청은 별도 버튼이며 자동 AI 호출이 아닙니다.
- 에렌샤 물품 종류에 **파츠**를 추가했습니다. 기존 장신구·재료를 일괄 변경할 필요는 없습니다.

## 채팅 상단에서 펼치는 미니 상태

- 접힌 본체는 **채팅 영역 위로 숨고 공간을 차지하지 않습니다.** 긴 가로 막대나 브랜드 버튼 없이 패널 밑변 가운데가 아래로 삐죽 이어진 부분만 남습니다.
- 돌출부는 패널과 같은 배경·테두리로 연결됩니다. 누르면 본체와 함께 아래로 내려오고, 다시 누르면 위로 접힙니다. 과거 메시지를 스크롤해도 채팅 상단에 남습니다.
- 패널이 펼쳐진 만큼 채팅은 아래의 남은 공간을 사용합니다. 메시지·입력창을 가리지 않으며 패널 높이와 글자·버튼 크기를 키웠습니다. 탭과 페이지 이동은 본문 스크롤 밖에 둡니다.
- 현재 채팅 상태를 미리 준비합니다. 평소 펼치기에는 재로딩 화면·AI 호출·게임 동기화 대기가 없으며, 게임 저장과 되돌리기 뒤에는 표시 자료를 다시 읽습니다. 최초 시작과 채팅 전환 직후에는 준비가 끝난 뒤 돌출부를 표시합니다.
- **상태 / 능력·기술 / 장비 / 소지품 / 탐험 또는 장소 / 전투 / 퀘스트**로 나눕니다. 퀘스트 탭은 해당 기능이 있는 룰북에 표시합니다. 많은 기술·물품은 10개씩 나눠 보고, 항목을 펼쳐 세부값을 확인합니다.
- **탐험** 탭에는 전체 탐험 화면의 2D 지도도 표시합니다. 지도 기능이 켜진 현재 장소의 지형·이모지·현재 위치·이동 흔적을 먼저 보고, **장소 연결**과 **주변 대상·거리**를 펼쳐 확인합니다. 미발견 정보는 숨기며 지도 열기로 이동이나 시간이 진행되지 않습니다.
- 인물이 여럿이면 이름 양옆 화살표로 바꿉니다. **전체**, **설정** 버튼을 누를 때 전체 플러그인 화면을 엽니다.
- 자료는 해당 채팅에 한정하며 전원 OFF·채팅 변경·플러그인 종료 때 이전 패널을 정리합니다. 읽기 오류에는 **다시 읽기**를 제공합니다.
- Risu의 기본 채팅 레이아웃에 연결합니다. 독자적인 채팅 구조는 지원하지 않을 수 있으며, 실제 Risu·모바일 표시와 클릭 반응은 이번 작업에서 실행 확인하지 않았습니다.


## 지도와 등장인물 표시 변경

- 첫 표시부터 사용자와 메인 AI가 같은 지도 정보를 받습니다. 저장 후에는 열린 미니 지도와 전체 화면의 지도도 갱신합니다.
- 지도 프레임을 고정하고 **현재 좌표·최근 이동 거리·이동 흔적·구역 도착**을 표시합니다. 아직 위치 이동이 저장되지 않았다면 **이동 기록 없음**으로 표시합니다. 지형은 같은 장소의 기록을 유지합니다.
- 비전투에서 발견된 목적지를 지정했을 때 한 행동의 전투 이동량만 움직이던 제한을 수정했습니다. 알려진 길을 한 번에 이동하고 함정·출구·막힌 길에서는 실제 처리에 맞춰 멈춥니다. 방향만 지정한 전진과 전투의 이동량·비용은 유지합니다.
- 지도는 **보기 전용**입니다. 방향·앞으로·둘러보기·수색·조작 버튼과 행동 입력칸을 제거했습니다. 평소처럼 채팅으로 플레이합니다.
- 알려진 장소의 연결도와 현재 구역의 지형을 함께 표시합니다. 지형 스킨, 인물·출입구·채집물 아이콘, 이름·거리와 최근 이동 흔적을 사용합니다.
- 새 실내 지도는 방·복도, 거리 지도는 건물 외곽이 구분됩니다. 기존 지도는 저장된 지형과 보상 기록을 유지합니다. 미발견 장소와 숨은 함정·보상은 공개하지 않습니다.
- 메인 AI에도 같은 지도에서 추출한 주변 벽·바닥, 방향별 이동 가능 거리와 대상 방향을 제공합니다. 서술만 진행되고 실제 이동 호출이 없으면 지도 좌표는 바뀌지 않습니다.
- **현재 장면에 표시** 체크 대신 현재 현장·함께 이동 중·다른 장소·등장 미확정을 표시합니다. **등록 인물 → 등장 정보 정정**에서 잘못된 기록을 바로잡을 수 있습니다.
- NPC는 실제 등장 장소에 남으며 명시한 동행만 함께 이동합니다. 오래된 체크만 남아 있는 NPC를 자동 동행시키지 않습니다. 기존 인물 자료를 삭제하거나 다시 생성하지 않습니다.
- 메인 AI는 기존 행동에 scene을 덧붙이거나 rpg_registry scene으로 등장·퇴장·동행을 기록할 수 있고, 놓치지마 검사도 같은 방식으로 누락을 보완합니다. 이름이 언급되지 않은 것만으로 퇴장시키지 않습니다.

## 플러그인이 먼저 알려주는 상태와 기능

### 거래 일부 누락 보완

- 놓치지마 검사에서 판매 물품·제작 재료 차감, 받은 물품·파츠, 골드 정산, 실제 장착을 각각 확인합니다. 재료 차감 한 건만으로 전체 거래를 완료했다고 판단하지 않도록 저장 근거를 나눕니다.
- 검사 화면에 **최근 검사 원문**과 **거래·소지품 확인**을 표시합니다. 검사 AI가 후보를 확인하지 않았거나 처리 방법이 없으면 미해결로 남기며 다음 문맥에도 전달합니다. 후보 탐지는 의미 판단을 대체하지 않으며 모든 누락 검출을 보장하지 않습니다.
- 에렌샤는 이미 성립한 대금만 빠진 경우 `rpg_economy record`로 명시된 골드를 정산할 수 있습니다. 이미 차감한 재료를 다시 판매하지 않고 같은 정산을 반복하지 않습니다. 파츠 생성·부착은 각각 기존 도구로 처리합니다.
- 이미 성공한 선행 작업 때문에 후속 보완이 차단되던 처리를 수정했습니다. 실패 판정·수치 감소 확인·이미 지급한 보상은 유지합니다.
- 검사 생략 사유와 항목별 근거는 진단에 남깁니다. 별도 검사 AI 호출이나 자동 재청구를 추가하지 않습니다. 실제 제보 채팅의 복구·실행 확인을 완료했다는 뜻은 아닙니다.

- 저장된 **현실 욕구·건강 위험·사망·자리 비움, 과적, 생존 부담**을 다음 메인 AI 요청에 짧게 전달합니다. 추가 AI 호출은 없으며 이미 계산한 상태를 알려줍니다.
- 성좌가 켜져 있거나 방송 중인데 여러 차례 활용을 확인하지 못하면 그 설정을 메인 AI에 상기시킵니다. 모든 답변에 성좌·채팅을 강제로 끼워 넣거나 보상·후원을 자동 지급하지 않습니다.
- **놓치지마 검사**를 켜면 기존 검사에 기능 활용 확인도 포함됩니다. 도구 호출이 없어도 실제 대사·반응이 있으면 활용한 것으로 봅니다. 실제로 서술했으나 저장이 빠진 부탁·방송 변화·후원·선택 기능 사건은 기존 도구로 보완할 수 있습니다.
- 무게·거리·장전 등 엔진이 자동 계산하는 기능에 불필요한 갱신 호출을 요구하지 않습니다. 에렌샤 현실에서는 성좌를 안내하지 않고, 방송 OFF에서는 시청자 반응을 요구하지 않습니다.
- 기본 안내는 활용 가능한 3차례 뒤 한 번, 반복 안내는 검사 근거와 최소 6차례 간격을 사용합니다. 한 답변에는 최대 3개를 전달하며, 상태가 해소되면 이전 알림은 제외합니다. 도구가 여러 번 호출돼도 새 차례로 세지 않습니다.
- 검사 화면의 **기능·상태 확인**, **검사 결과·로그 내보내기**에서 관찰과 전달 기록을 볼 수 있습니다. 수치를 낮추는 보완은 기존처럼 변경 전후를 확인한 뒤 적용합니다.
- 알림은 다음 답변 준비 때 전달됩니다. 채팅을 하지 않는 동안 플러그인이 혼자 메시지를 보내거나 시간을 진행시키지는 않습니다.

## 함께 수정한 현실 생활·장면 표시

- **현재 상태 → 현실 생활 → 편집**에서 욕구·건강·사망 여부·자리 비움·경과 시간과 현실 경제·시간 배율을 직접 수정하고 저장합니다. 다른 온라인 이용자는 해당 인물을 선택합니다. 게임 NPC·몬스터는 현실 생활 대상이 아닙니다.
- 같은 게임 장면에서 시각이 진행되면 경과를 계산해 접속 중 배율을 적용합니다. 현실 생활과 실제 현실 수면은 1배입니다. 앞선 생활 행동이 반영한 시간은 후속 시계 갱신에서 중복 적용하지 않습니다.
- `record eventType:clock`의 기본 `timeMode:auto`는 명시한 양수 `minutes` 또는 같은 시계의 차이를 사용합니다. 단순 시각 정정은 `timeMode:display`, 직접 지정한 경과만 사용하려면 `timeMode:elapsed, minutes:...`입니다. 기본 모드에서 `minutes:0`을 보내도 실제 시각의 증가를 무시하지 않습니다.
- 장소만 있고 시각·소요 시간이 없는 기록에는 “시간 정보 부족”을 남깁니다. 대화·조회·접속 전환이나 실제 PC 대기를 임의 시간으로 환산하지 않습니다. 예전 0분 기록을 소급해 재실행하지 않습니다.
- **에렌샤 현실에는 성좌가 등장하거나 개입하지 않습니다.** 메뉴·반응 문맥·도구 실행·가호 보정을 제한하고 게임 복귀 후 기존 기록을 이어 사용합니다.
- 현재 상태의 쓰러진 적·이전 구역의 적은 표시에서 정리합니다. 공통 저장 훅이 일반 행동·놓치지마 보완·직접 편집 뒤에 같은 처리를 수행하며, 추가 AI 호출은 없습니다. 등록 인물·처치·드랍 기록과 살아 있는 현재 전투 상대는 보존합니다.

## 켜는 방법

1. D100·얼터네이티브 헌터·에렌샤·무림에서 **플레이 설정 → 탐험·룰북 옵션**을 엽니다.
2. **탐험 사용**, **2D 지도 · 실험**을 켜고 저장합니다. 초기 구축에서도 선택할 수 있으며 기본값은 OFF입니다.
3. 이야기에서 실제 탐험 장소에 들어가면 기존 `explore start`가 장소를 준비합니다.
4. **탐험** 화면에 지도가 자동으로 나옵니다. 이미 방문 중인 장소에서 처음 켠 경우에도 별도 버튼 없이 표시합니다.

기존 장소는 구역 연결·몬스터·처치·자원·보상 기록을 보존하고 좌표 지형을 덧붙입니다. 새 장소는 프로그램이 시드로 구역 연결을 만들고, AI는 그 연결 안의 이름·설명·출현 종류·장치 자료를 작성합니다. 각 구역의 지형과 오브젝트 좌표는 프로그램이 배치합니다.

기존 **구역 연결 지도**와 현재 구역의 **2D 로컬 지도**를 함께 사용합니다. 통로 끝에 도달하면 연결된 구역으로 이동합니다. 첫 실험의 로컬 지형은 31×23칸, 한 칸 2m입니다. 숲·과수원·들판·동굴·거리·실내·유적의 지형을 구분하며 비행·수영·등반까지 새로 구현한 것은 아닙니다. 기존 장치의 도구 조건·강행 판정·막힌 출구는 유지합니다.

## 자연스럽게 입력하기

| 입력 | 처리 |
| --- | --- |
| 앞으로 나아간다 | 저장된 바라보는 방향으로 행동당 이동력만큼 이동합니다. 벽·인물·장치와 통로 경계를 확인합니다. |
| 저 통로로 간다 | 보이거나 이전에 발견한 대상이 명확할 때 실제 경로를 따라 접근합니다. 한 번에 도착하지 않을 수 있습니다. |
| 주변을 둘러본다 | 현재 시야만 확인합니다. 수색 주사위·이동·시간 경과를 만들지 않습니다. |
| 수상한 곳을 수색한다 | 기존 구역 조사 판정과 단서 발견을 사용합니다. 같은 인물의 같은 구역 조사 결과는 반복해서 굴리지 않습니다. |
| 채집한다 / 장치를 조작한다 | 현재 보이는 대상에 가까이 있어야 합니다. 실제 채집·도구 조건·보상 처리는 기존 탐험 엔진이 수행합니다. |
| 저 문을 열면 위험할까? | 질문으로 분류하면 위치·자원·주사위를 바꾸지 않습니다. |

복수 행동이나 모호한 대상은 임의로 실행하지 않습니다. 미확정 결과가 반환되면 메인 AI가 사용자의 의도를 유지하며 필요한 방향·대상만 확인할 수 있습니다. 한 도구 호출이 답변 길이나 서술 단위를 제한하지 않습니다.

지도 화면은 조작하지 않습니다. 메인 AI의 실제 도구 호출이 이동·수색·상호작용을 처리하며 다음 요청에는 현재 위치와 보이는 지형·대상이 전달됩니다.

## JEV가 맡는 부분

JEV의 `creation` 용도가 켜져 있으면 자연어 행동을 `이동 / 관찰 / 수색 / 조작 / 대화`와 알려진 대상·방향으로 분류합니다. 질문·선택 기준은 영어이고 한국어 입력과 대상 이름은 원문 자료로 전달합니다.

모든 선택이 설정한 확신 기준을 충족하면 그 분류를 사용하며 생성 AI를 부르지 않습니다. 불확실하거나 JEV를 껐으면 기존 플러그인 AI로 해석합니다. 그 응답도 미확정이면 이동하지 않습니다. JEV가 좌표·명중·성공·피해·보상을 작성하지 않습니다. 요청·응답, 기존 처리로 전환한 이유와 `map-intent` 사용 여부는 기존 JEV 진단에 포함됩니다. 유료 실측을 하지 않았으므로 속도·비용 절감 수치를 제시하지 않습니다.

## 전투와 발견 정보

- 지도가 켜진 장소의 전투는 같은 인물 좌표를 사용합니다. 직선 거리와 벽에 가리는지를 계산하고 접근·후퇴는 경로를 따라 이동합니다.
- 미터 옵션 ON이면 실제 m 사거리를 사용합니다. OFF이면 지도 거리 2m 이하=근접, 10m 이하=가까움, 50m 이하=멀리, 그 이상=아주 멀리로 기존 네 단계와 연결합니다.
- 이동력은 기존 m 옵션값을 사용합니다. 네 단계 방식은 이동 1칸당 6m를 초기 환산으로 사용합니다. 한 지도 칸보다 작은 이동력은 다음 이동 행동에 누적합니다.
- 공격·탄약·재사용 대기·행동 게이지·피해·처치 보상은 기존 `act` 흐름에서 처리합니다. 지도 화면을 통한 별도 행동은 없습니다.
- 숨겨진 통로와 함정은 발견 전 표시하지 않습니다. 밟은 함정은 저장된 피해를 한 번 반영합니다. 과거에 본 지형은 흐리게 남고 현재 보이지 않는 인물 위치는 지도 응답에서 숨깁니다.
- 지도 전체 JSON, 미발견 구역 수와 전체 탐험률을 매번 모델에 전달하지 않습니다. 현재 위치·시야 안의 대상·실제 변화만 전달합니다.

## 저장과 이번 범위

실제 지형, 시드, 생성기 버전, 발견 기록, 인물 위치를 기존 게임 데이터에 함께 저장합니다. 재방문 때 재생성하지 않으며 백업과 되돌리기를 따릅니다. 꺼도 지도 데이터는 삭제하지 않습니다. 헌터의 종료된 게이트와 새 게이트 인스턴스 구분도 유지합니다.

택티컬·지르코트는 별도 탐험·전투 구조를 사용하므로 이번 실험에서 활성화하지 않습니다. 로맨스 판타지·미연시도 이번 범위에 포함하지 않습니다. 임의 NPC 대사·전투·보상을 새로 발생시키는 배경 AI는 없습니다.

소스 수정과 배포 생성 범위입니다. 실제 RisuAI·모바일 화면·JEV/API 호출·전투 플레이·별도 최종 검사는 수행하지 않았습니다.
