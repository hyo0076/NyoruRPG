# NyoruRPG 0.25.5 · 행동 게이지 충전

로컬 테스트용입니다. GitHub에는 게시하지 않았습니다. `NyoruRPG.js`만 교체하며 연결 모듈 v1과 기존 세이브를 사용합니다. 시스템 재구축은 필요 없습니다.

## 소스에서 확인한 원인

기존 게이지 계산은 아무도 준비되지 않았을 때만 다음 준비 시각까지 시간을 이동했습니다. 준비된 인물이 행동을 실행하는 동안에는 시간이 흐르지 않아 다른 인물의 게이지도 그대로였습니다. 에렌샤는 선택한 이동 숙련도가 없으면 모두 같은 기본 속도 10을 사용했고, 몬스터에게는 그 숙련도 자체가 없었습니다. 같은 속도·같은 시작 게이지가 겹치면 제보처럼 모두 100에 도달한 뒤 기존 순서로 반복할 수 있었습니다.

단순히 100을 1000으로 바꾸지 않고 충전과 행동 시간, 속도 자료를 함께 수정했습니다. 이미 있던 다음 준비 시각 계산은 유지합니다.

## 적용한 계산

- 일반 행동 한 번에 `10 / 행동 시작 시 충전 속도`만큼 전투 시간이 흐릅니다. 속도 10이면 1, 속도 20이면 0.5입니다. 강해진 인물에게도 고정 1시간을 부여해 모두 즉시 충전시키는 방식은 아닙니다.
- 그동안 행동자를 제외한 참가자는 자신의 `충전 속도 × 경과 시간`만큼 충전합니다. 예를 들어 행동자의 속도가 10이고 대기자의 속도가 12라면, 그 행동 중 대기자는 최대 12포인트를 쌓습니다.
- 100을 먼저 채운 시각을 보관합니다. 여러 인물이 준비돼 있으면 먼저 준비된 인물이 먼저 행동하고, 정확한 동률만 기존 참가 순서로 정합니다. 충전 중 남아 있는 소수점도 다음 행동으로 이어집니다.
- 준비된 인물은 진행 중인 행동이 끝날 때까지 기다립니다. 일반 충전은 100에서 대기하고, 자기 행동의 효과로 얻는 기존 추가 게이지는 유지합니다. 연계·반격·추가 행동의 기존 비용과 턴 처리도 유지합니다.
- 행동 중 효과 만료·지속 피해의 시각에 도달하면 기존 시간 효과를 처리합니다. `combat_time` 1의 기준은 기존과 같은 전투 시간 10이며, 쿨다운·소환 지속의 자기 차례 기준도 유지합니다.
- 실제 API 응답 대기, 사용자 입력 대기, 화면 열기·새로 고침은 전투 시간을 흐르게 하지 않습니다. 충전을 위한 별도 도구 호출은 필요 없습니다.

공통 d100·얼터네이티브 헌터·무림의 공통 엔진과 에렌샤 엔진에 같은 계산을 연결했습니다. 턴테이블·자유 진행은 이 시간 계산을 사용하지 않습니다.

## 에렌샤 속도 편집

`actionSpeed`는 인물별 **기본 행동 속도**입니다. 이동할 수 있는 칸 수와 다르며, 몬스터도 가집니다. 인물 편집, 현재 상태 편집, 구축 초안, 뉴뉴 편집 제안에서 소수점까지 바꿀 수 있습니다.

기존 수식의 `BASE`는 이제 `actionSpeed × sqrt(1 + 이동 숙련도 rating / 50)`입니다. 수식에서 `SPEED`는 인물의 기본 행동 속도, `GRADE`·`MASTERY`는 선택한 이동 숙련도입니다. 기존 가속·둔화 효과는 그 뒤에 적용합니다. d100·헌터의 민첩, 무림의 감각·외공 기본 수식은 유지합니다.

새 인물 준비에서는 원문의 민첩함·반응·움직임을 근거로 기본 속도를 한 번 정하고, 몬스터 재사용 시에는 저장된 속도를 복사합니다. 기존 인물과 사용자가 편집한 수치를 재분석으로 덮어쓰지 않습니다. **과거 저장에 기본 속도가 없으면 종전과 같은 10을 사용하므로, 같은 속도인 인물까지 저절로 서로 다른 속도가 되지는 않습니다.** 필요한 기존 인물의 속도는 편집할 수 있습니다.

## 표시·저장

전체 화면·미니보드·결과 카드의 `기준 차례분`, `준비까지 1 차례분`, `충전 속도 ×1`을 전투 시간과 숫자 충전 속도로 바꿨습니다. 카드에는 해당 실행 단계에서 저장한 상태를 표시합니다.

새로운 준비 시각·행동 시작 속도는 저장 형식의 선택 필드입니다. 기존 진행 중인 전투의 게이지·수식·자원은 보존하며, 과거 준비 시각을 알 수 없는 인물은 현재 저장 시각에서 이어갑니다. 과거 주사위나 행동은 다시 계산하지 않습니다. MCP·IPC 연결과 카드 배치 경로, 직접 조작 설정은 그대로 사용합니다.

## 확인 범위

관련 소스의 계산·생성·편집·저장 연결을 수정하고 로컬 배포 파일을 생성했습니다. 사용자의 요청에 따라 별도 최종 정적 검수·모의 전투·모의 호스트·브라우저·실제 Risu·유료 API·하위 에이전트 검사는 하지 않았습니다. 위 수식 예시는 계산 방식의 설명이며 실제 전투 테스트 결과가 아닙니다. 실사용에서의 행동 순서와 화면 표시 확인은 남아 있습니다.
