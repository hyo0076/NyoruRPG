# NyoruRPG 0.29.10 · Jev 빠른 판단 시험판

플러그인만 업데이트. 모듈 v1은 그대로

Jev를 검색·분류·기존 정의 선택과 생성 보조에 연결했습니다. 새 설명과 고유 설정은 기존 생성 API가 작성하며 최종 자료는 각 룰북의 기존 저장 검사와 엔진을 거칩니다. 0.30 전환은 실제 사용 결과를 본 뒤 결정합니다.

## 테스트 제보 반영 · 같은 0.29.10

- 에렌샤 현실 수면·생활 시간: 접속 중 배율과 분리해 현실 8시간 수면은 480분으로 처리합니다. `sleep`으로 수면·회복을 함께 처리하며, 이후 시각 변경에 같은 구간을 다시 더하지 않도록 이미 반영한 현실 시간을 대조합니다. 시간만 기록하는 수면 구간에도 `clock sleep:true`를 사용할 수 있습니다.
- 현실 사망·자리 비움: 기존 상태창의 원화만으로는 드러나지 않던 `dead`·`canAct`와 경고를 메인 AI의 상태 패킷에도 전달합니다. 새 생활 경고는 결과 카드, 현재 경고는 인물 상태에 표시합니다. 게임 행동의 준비·실행 양쪽에서 행동 불가를 확인합니다. 생활 욕구의 숨겨진 숫자는 공개하지 않습니다.
- 뉴뉴 원인 설명: 현재 저장값과 보관된 최근 생활 영수증을 구분해 전달합니다. 기록이 없다는 이유만으로 식사·수면을 하지 않았다고 단정하지 않도록 했습니다. 이번 대화의 2,850분·사망 누적 원인은 최신 세이브/처리 원문 없이 확정하지 않습니다. 이미 저장된 사망·욕구·돈을 자동 초기화하지 않습니다.
- 네 번째 테스트: 전체진단 (3)의 새 요청 6건은 모두 HTTP 200입니다. 로어 후보를 두 묶음으로 보내 답을 합친 경로도 완료됐습니다. 이후 기존 검색으로 전환한 이유는 입력 초과가 아니라 후보의 낮은 확신도였습니다.
- 뉴뉴의 주제 분류에서 이전 AI 답변을 빼고 최신 사용자 질문을 우선합니다. 원화 요청에 이전 무기 설명이 섞이던 경로를 수정했습니다. 모호한 기능 설명은 빼지 않고 남깁니다.
- **초간단 질문**을 추가했습니다. 현재 저장값을 짧게 조회하며 관련 없는 질문은 고정 대사 없이 반려 상태만 돌려줍니다. 아래 사용 범위를 참고하세요.
- 세 번째 테스트: 새 Jev 기록 4건 중 로어 요청 1건은 전체 입력 62,156바이트로 전송 전에 중단됐고, 3건은 HTTP 200 응답을 받았습니다. 로어 후보에 질문 문구까지 더한 입력량을 계산하도록 고쳤습니다.
- 입력이 크면 여러 번 호출해 달라는 요청에 따라 로어 후보와 질문을 한도 안에 들어가는 묶음으로 나눕니다. 생성 보조의 독립 질문도 나눌 수 있으며 답을 원래 질문 ID로 합칩니다. 한 묶음이 실패하면 기존 검색·생성으로 이어갑니다. 묶음 ID·순서·총수와 각각의 요청·응답·사용량을 진단에 기록합니다.
- 인물 분류를 생략한 몬스터 등록에도 생성 목적을 명시해 기술 효과 선택이 붙지 않도록 했습니다. 기존 기술과 다른 창 투척, 정보가 부족한 보물 상자 등의 정상 판단 보류는 유지합니다.
- 두 번째 테스트: 제공된 호스트 진단 (15)의 새 세션 20호출은 모두 완료됐고 이전 `preparation` 오류와 도구 결과 반환 전 출력 관측은 없었습니다. 이 자료에서 확인한 결과이며 수정 후 직접 실사용한 것은 아닙니다.
- 몬스터 생성 요청에 공통 기술 지침이 포함됐다는 이유로 단일 기술의 효과를 고르는 질문을 덧붙이던 분류를 수정했습니다.
- 생성 준비의 입력량은 최종 state와 질문·선택 기준 전체로 계산합니다. 독립 질문은 여러 묶음으로 나누며, 질문 하나도 들어가지 않아 선택적 Jev 근거를 줄일 때는 검토하지 않은 로어 원문을 기존 생성 요청에 그대로 남깁니다. 확신도 기준은 낮추지 않습니다.
- 전송 전 `JEV_LIMIT`으로 중단한 요청도 상세 진단에 남깁니다. `networkRequest:false`, `stage:preflight`, 실제 입력 바이트·질문 수·제한값으로 서버 요청 실패와 구분합니다. 기존 파일에서 누락된 요청 원문은 소급 복원하지 않습니다.
- `허용되지 않은 필드: preparation`: 내부 준비 옵션을 생성 API의 전송 설정과 분리했습니다. Jev 사용 여부와 관계없이 기존 생성 경로를 막던 공통 오류를 수정했습니다. 초기 인증·출력 스키마 검사와 기존 스키마 호환 처리는 유지합니다.
- 뉴뉴 로어북 검색: `카인에`처럼 조사가 붙은 이름과 제목의 괄호 속 이름을 찾습니다. 후속 검색에는 같은 뉴뉴 대화의 최근 사용자 질문 두 개를 함께 보내며 최신 질문의 대상이 우선입니다. AI가 답변에서 만든 이름은 검색 대상으로 이어받지 않습니다. 초기 미선택·꺼진 로어북의 기존 검색 범위를 유지합니다.
- Jev 로그: 기존 기술과 다른 요청, 관련 후보 없음, 확정 불가를 구분합니다. 새로운 행동을 기존 기술로 억지 연결하거나 확신도 기준을 낮추지 않습니다.

첨부된 진단과 소스에서 원인을 확인해 수정한 배포입니다. 수정 후 실제 RisuAI·유료 API 실행은 하지 않았습니다. 실패했던 전투·보상·소모 기록을 자동으로 다시 실행하지 않습니다.

탐험 구역 수나 진행 규칙은 이번 수정에서 변경하지 않았습니다. 제공된 기록의 18회 탐험 호출에는 같은 구역 사이의 이동·조사·장치 재시도가 포함돼 있습니다. Jev 환경 분류가 새 지도나 이동을 직접 실행하지 않습니다.

## 사용 방법

1. 기존 플러그인을 이번 `NyoruRPG.js`로 교체합니다. 세이브와 연결 모듈은 그대로 둡니다.
2. **AI 연결 → Jev 빠른 판단**에서 주소·키·모델을 직접 입력하거나 **기본 API 사용**을 켭니다. 공유 시 기본 API의 주소·키·인증 헤더·전송 방식을 사용하며 Jev 요청의 모델은 `jev`로 정합니다.
3. **Jev 사용**을 켜고 사용할 다섯 영역을 선택한 뒤 **Jev 설정 저장**을 누릅니다. 처음에는 사용 OFF, 다섯 영역은 선택된 상태입니다.
4. 원하면 **연결 확인 · API 사용**을 누릅니다. 이 버튼은 실제 Jev 요청 한 번을 사용하며 게임 상태는 바꾸지 않습니다.
5. 평소처럼 구축·플레이·뉴뉴·검사를 사용합니다. **사용 기록 새로 고침 → 이번 실행의 사용 기록**에서 요청 수, 응답 시간, 입력 토큰, 캐시·기존 정의 재사용, 생성 입력에서 줄인 문자 수와 기존 처리 전환을 확인합니다.

**Jev 사용**을 끄고 저장하면 기존 API 흐름을 사용합니다. 일부 영역만 끌 수도 있습니다. 제안된 새 수치의 검토·저장 방법은 기존과 같습니다.

기본 모델은 `jev-1.13.0`, 전송은 RisuAI 전송, 최대 대기는 8초, 선택 확신도 기준은 0.85입니다. 모델 ID·전송·대기시간·기준은 편집할 수 있습니다. 기준값은 정답 보장이 아니며 원문이 모호하면 높은 확률처럼 보여도 잘못 고를 수 있습니다. [공식 모델 안내](https://docs.typesafe.ai/models).

### 직접 주소와 기본 API 공유

직접 설정은 TypeSafe 공식 주소뿐 아니라 System One 요청 형식과 Jev를 지원하는 프로바이더의 전체 주소를 입력할 수 있습니다. 주소 아래에 `/v1/systemone` 안내가 표시됩니다. 입력한 모델 ID를 그대로 사용하므로 프로바이더가 안내하는 ID로 바꿀 수 있습니다.

**기본 API 사용**을 켜면 알려진 생성 경로를 제거하고 `/v1/systemone`을 붙입니다. 예를 들어 기본 주소가 `https://api.llmgateway.io/v1/chat/completions`라면 Jev 주소는 `https://api.llmgateway.io/v1/systemone`입니다. `/v1/responses`, `/v1/messages`, 버전까지만 적은 주소와 기존 `/v1/systemone`도 같은 방식으로 처리하고 프록시의 앞 경로는 유지합니다. 이 예시는 주소 변환이며 해당 프로바이더의 실제 Jev 지원을 검증했다는 의미는 아닙니다.

공유 중에는 실제 Jev 주소와 모델 `jev`가 표시됩니다. 기본 API의 원래 모델·주소는 바꾸지 않으며 Jev 대기시간과 확신도는 별도로 유지합니다. 공유를 끄면 직접 입력했던 Jev 주소·키·모델이 복원됩니다. 공유 상태에서 **Jev 설정 저장**을 누르면 화면에서 수정한 기본 API 연결도 함께 저장합니다. 인증정보는 기존 기기별 저장소를 사용합니다. 서비스 계정 JSON을 System One API 키로 변환하는 기능은 아닙니다.

### 질문 언어

Jev에 보내는 `questions`의 질문 지시와 선택 기준은 영어로 통일합니다. 기술명·인물명·수치 원문·효과 이름은 영어 문장에 끼워 넣지 않고 `state`에 원문 그대로 두며 영어 질문에서 후보 번호로 참조합니다. 한국어 채팅이나 로어북을 번역해서 덮어쓰지 않습니다. 전송 직전에도 질문·선택 기준의 언어 형식을 확인하고 잘못된 질문은 보내지 않은 채 기존 처리로 이어갑니다.

### 초간단 질문

메인 AI가 기존 `rpg_state` 도구에 `op:"ask"`, `question:"강철 화살이 몇 개 남았어?"`처럼 묻습니다. 인물 ID는 `actorId`, 물품·기술·퀘스트의 이름이나 ID는 `subject`에 함께 넣을 수 있습니다. 별도 도구나 모듈 교체는 필요 없습니다.

가격·수량·소지금·HP/MP·재사용 대기·퀘스트 진행과 보상·현재 장소·허용된 현실 생활 경고를 조회합니다. Jev에는 필요한 저장 후보와 질문을 보내고, 답으로 고른 후보의 실제 값을 플러그인이 반환합니다. 가격은 개당 저장 기준 가치로 수수료·할인·환전을 포함한 거래 견적과 다릅니다. 재사용 대기 0은 비용·선행 조건·사거리까지 충족했다는 뜻은 아닙니다. 에렌샤의 허기·피로 등 숨겨진 수치는 공개하지 않고 인물별 생활 경고를 사용합니다.

Jev가 모호하게 답하거나 연결할 수 없으면 **기본 API**가 같은 제한된 자료를 해석합니다. Jev 영역을 꺼도 기본 API로 조회할 수 있습니다. 저장값이 없으면 없다고 반환하고, 대상이 애매하면 이름·ID 확인을 요청합니다. 관련 없는 일반 질문이나 행동 실행 요청은 `not_applicable`로 돌려줍니다. 이 상태는 게임 오류가 아니며 메인 AI에게 특정 거절 문구를 말하도록 강제하지 않습니다. 플러그인 API가 별도로 일반 지식 답변을 생성하지 않습니다.

읽기 전용이므로 새 기술·공격·구매·시간 경과·보상을 실행하지 않습니다. 같은 값을 다시 받기 위해 반복 호출할 필요는 없습니다. 조회 중 다른 작업으로 저장 상태가 바뀌면 이전 값을 확정해서 답하지 않고 상태 변경을 알립니다. Jev 요청과 선택 결과는 기존 상세 진단에서 `purpose:questions`로 확인할 수 있습니다.

### 에렌샤 현실 수면과 경고

접속 중 기록한 생활 경과에는 저장된 배율(기본 5배)이 적용됩니다. 현실로 나온 뒤의 생활·수면과 명시적인 수면 구간은 1배입니다. 예를 들어 현실에서 8시간 잤다면 `real_life(action:"sleep",minutes:480)`으로 기록하며, 게임 안에서 캐릭터가 잠든 것은 현실 수면과 다릅니다. 수면은 피로 회복을 포함하지만 식사·물 마시기·화장실을 자동으로 수행하지 않습니다.

`sleep minutes:0`은 수면 시작을 기록하고 이후 공유 경과 시간 동안 회복합니다. 양수 minutes는 완료된 수면 구간이며 회복 뒤 수면 상태를 해제합니다. 현실에 있는 사용자나 자리를 비운 동료가 실제 돌아왔을 때 `return_game`을 기록합니다. 동료의 생활 행동은 사용자 시계의 접속 구분을 바꾸거나 사용자 식자재를 소비하지 않습니다.

한 구간의 경과는 생활 행동 또는 시계 기록 중 한 번만 처리합니다. 수면을 시계 변경과 함께 기록할 때는 `record(eventType:"clock",sleep:true,minutes:480)`으로 회복을 포함할 수 있습니다. 이미 생활 행동으로 처리한 뒤 날짜·시각 표시를 맞추는 호출은 `minutes:0`입니다. 아직 갱신하지 않은 현실 시계에 대해 이미 반영한 분량을 보관하여 뒤따르는 같은 시각 변경의 중복 누적을 차감합니다. 과거 기록을 거꾸로 재생하거나 이미 지나간 식사·수면을 새로 실행하는 기능은 아닙니다.

사망 상태는 게임 HP와 별개입니다. `realWorld.player` 및 다른 이용자 상태에 `dead`, `away`, `sleeping`, `canAct`, 경고를 제공합니다. 아바타가 행동할 수 없는 상태에서는 공격·탐험·사용·거래 등의 게임 행동을 중단합니다. 기록 조회와 뉴뉴 편집은 가능합니다. 저장된 현실 사망을 게임 부활로 해제하거나 새 버전 설치만으로 초기화하지 않습니다. 과거 잘못 누적된 수치의 복구는 원본 기록을 확인해 별도로 편집해야 합니다.

## 연결된 범위

| 영역 | Jev가 처리하는 부분 | 이어지는 처리 |
| --- | --- | --- |
| 초간단 질문 | 질문에 해당하는 저장값 선택 또는 조회 대상 밖인지 분류 | 실제 저장값만 반환. 대상 불명은 기본 API가 해석하며 정보 없음·대상 확인·반려를 구분 |
| 로어북 의미 검색 | 이름 검색으로 부족할 때 관련 후보 선택 | 실제 항목 ID로 원문을 읽음. 결과가 없거나 모호하면 기존 의미 검색 API 사용 |
| 초기 구축·새 인물 | 해당 인물에 필요한 긴 원문 조각 선별, 저장 인물 후보가 제공된 요청에서 정체성 후보 추천 | 기존 생성 AI가 인물과 고유 기술·장비를 작성하고 기존 룰북으로 적용 |
| 기술 준비 | 소유한 기술 중 같은 의미의 기존 기술 선택 | 같은 기술이면 저장 정의 사용. 새 기술·강화·변경 요청은 생성 API 사용 |
| 물품·기술 구성 | 새 단일 물품 종류 선택, 명시된 수치의 원문 근거와 효과 어휘 선택 | 물품의 나머지 필드는 기존 AI가 작성하고 코드로 합침. AI가 원문 근거로 분류를 정정할 수 있음 |
| 일반 판정 | D100·헌터·무림의 허용 능력치와 난이도 분류 | 주사위·성공·피해·비용은 원래 엔진으로 계산. 무림은 무림 전용 능력치만 사용 |
| 새 장소 | 장소의 환경 분류와 관련 원문 선별 | 기존 AI가 장소를 작성하고 원래 지도·조우 저장 절차 사용. 저장된 장소는 그대로 재사용 |
| 뉴뉴 | 질문에 필요한 기능 설명 분류, 관련 로어북 검색 | 기존 API로 설명과 편집 제안 작성. 기존 편집 가능한 범위와 저장 절차 유지 |
| 놓치지마 검사 | 직전 서술과 처리 기록에서 누락 의심 범주 분류 | 기존 검사 AI가 전체 원문·상태·영수증을 확인하고 원래 엔진으로 보완 |

구축과 자료 준비는 D100·헌터·에렌샤·무림·로맨스 판타지·미연시·택티컬·지르코트의 기존 작성 경로에 연결합니다. 각 룰북에서 원래 쓰지 않는 전투·기술 규칙을 새로 추가하지 않습니다. 기존 기술 의미 연결은 기술 준비를 사용하는 D100·헌터·에렌샤·무림·택티컬·지르코트에서 동작합니다.

정확한 이름·ID·준비 결과가 이미 있으면 원래 캐시와 조회를 먼저 사용합니다. Jev에 매 행동이나 매 조회를 보내지 않습니다. 전체 시스템 규칙을 만드는 요청처럼 특정 인물·물품·장소에 한정할 수 없는 자료는 자동으로 줄이지 않습니다.

로어북 검색은 현재 봇·채팅·페르소나·연결된 활성 모듈 범위이며 **초기 미선택·꺼진 로어 항목도 대상**입니다. 읽기 위해 원본 항목을 켜지 않습니다. 의미 검색은 제한된 후보 목록에 대한 비교이므로 모든 원문·별칭을 항상 찾는다는 뜻은 아닙니다. 준비용 원문 선별도 제한된 조각만 판단하고 읽지 않은 나머지 조각은 그대로 남깁니다. 원본 로어북과 저장된 구축 자료는 삭제·축약하지 않습니다.

## 실패·재사용·기록

- 입력 한도를 넘는 후보·독립 질문은 여러 묶음으로 순차 호출합니다. 대기시간은 각 묶음에 적용되므로 호출 수가 늘면 총 대기와 사용량도 늘어날 수 있습니다. 질문 하나의 선택지를 임의로 나누거나 같은 초과 요청을 반복하지 않습니다.
- 허용 후보 밖의 답, 잘못된 응답 형식, 불확실한 판단, 입력 한도, 네트워크 실패·대기시간 초과는 기존 처리로 이어갑니다.
- 연결 실패 뒤에는 60초 동안 Jev 요청을 쉬고 기존 API를 사용합니다. 같은 유료 요청을 무제한 재시도하지 않습니다. 설정을 저장하면 다시 시도할 수 있습니다.
- 같은 채팅·분기·입력·모델·선택 기준의 판단은 실행 중 최대 10분간 재사용합니다. 다른 채팅의 판단을 공유하지 않으며 게임 행동 결과나 주사위 캐시가 아닙니다.
- 요청 취소·채팅 변경·플러그인 종료는 기존 작업 취소를 따릅니다. 늦게 도착한 응답으로 다른 채팅을 수정하지 않습니다.
- API 키는 기기별 인증 저장소에 따로 보관하며 일반 설정·게임 백업·프롬프트에 넣지 않습니다. 기기별 키 저장을 지원하지 않는 호스트에서는 안내대로 현재 실행 동안만 사용할 수 있습니다.
- 호스트 진단에는 목적·응답 시간·입력 토큰·선택 종류 등 요약을 남깁니다. 별도의 Jev 상세 로그에는 요청 본문·응답 원문과 후속 선택을 보관합니다. 인증정보는 가립니다. 화면 사용 집계와 판단 캐시는 재시작 시 초기화되지만 상세 로그는 남습니다.

검사 보조를 켜도 **놓치지마 검사 자체를 자동 활성화하지 않습니다.** 검사 기능이 켜져 실행될 때 보조합니다. Jev의 ‘문제 없음’으로 전체 검사를 건너뛰거나 판단만으로 인물을 합치고 보상·수치를 바꾸지 않습니다. 기존 확인이 필요한 수정은 같은 확인 절차를 거칩니다.

## 버그 제보용 Jev 요청·응답 로그

**AI 연결 → Jev 빠른 판단 → 버그 제보용 요청·응답 로그**에서 내보냅니다. 기본으로 상세 로그 보관이 켜져 있으며 Jev를 실제 사용하는 요청부터 모읍니다. 보관을 끄고 저장하면 이후 새 기록 수집을 멈추며 기존 기록은 별도 삭제할 수 있습니다.

- **현재 채팅 Jev 로그 내보내기**: 해당 채팅의 모든 분기와 연결 확인 기록을 JSON 파일로 받습니다.
- **전체 Jev 로그 내보내기**: 보관 중인 모든 채팅의 Jev 상세 기록을 받습니다.
- **현재 채팅 로그 삭제**: 확인 후 해당 채팅 기록만 지웁니다. 게임과 원본 로어북은 바꾸지 않습니다. 전체 진단 삭제 또는 채팅 저장소 삭제에도 해당 상세 로그 정리가 연결됩니다.

파일에는 플러그인 버전, 요청 ID·실행 세션·채팅 범위, 시간, 용도, 모델·대기시간·확신도 기준, 보낸 state/questions와 실제 응답 원문, 해석된 답·확률·토큰, 후속 선택·기존 처리 전환 이유가 들어갑니다. HTTP 오류의 응답 본문도 보관하며 응답 원문은 건당 25만 자를 넘으면 길이와 잘림 여부를 표시합니다. 캐시 반환은 networkRequest:false와 원래 기록 ID로 구분합니다. 실제 호출의 오류·시간 초과·취소·설정 변경에 따른 폐기도 구분합니다. 이전 실행이 끝나 응답 완료를 기록하지 못한 항목은 내보내기에서 interrupted로 표시합니다.

실제로 전송한 인증 헤더와 키·비밀 키는 가립니다. **채팅·로어북 원문은 포함될 수 있으므로 공유할 파일 내용을 확인하세요.** 자료는 게임 세이브와 분리된 플러그인 진단 저장소에 최근 200건·16MB까지 보관하며 오래된 기록부터 정리합니다. 저장 실패 시 내보내기에 현재 메모리 기록과 누락 안내를 함께 담습니다. 로그 저장 오류 때문에 게임 처리를 실패시키지 않습니다.

## 비용과 확인 범위

기존 기술 연결·판정 분류·로어북 검색을 Jev가 확정하면 해당 생성 API 호출을 줄일 수 있고, 자료 선별은 생성 API에 보내는 원문을 줄일 수 있습니다. 새 인물·기술의 작성과 검사 보조는 기존 API 호출도 필요합니다. 일부 요청은 Jev가 추가되거나 기존 API로 전환되므로 총비용·지연이 늘 수도 있습니다. 메인 서술 AI의 출력 토큰을 직접 줄이는 기능은 아닙니다.

사용 기록의 입력 토큰은 Jev 응답이 보고한 값입니다. 입력 감소 문자는 토큰·요금과 같지 않으며 캐시·재사용 횟수도 절감액으로 환산하지 않습니다. 실제 한국어·각 룰북에서 판단 정확도와 전체 응답 시간을 확인한 뒤 기준과 기능 선택을 조정하세요. [API 계약](https://docs.typesafe.ai/api), [모델·언어 안내](https://docs.typesafe.ai/models).

이번 작업 범위는 소스 연결·수정과 로컬 배포 생성입니다. 사용자 지시에 따라 별도 최종 검사·브라우저·모의 호스트·실제 RisuAI·유료 API 호출은 실행하지 않았습니다. 제공된 진단에서 초기 인증 실패 뒤 Jev 응답 성공을 확인했으며, 수정 후 실사용과 전체 한국어 판별 정확도·총비용·속도 절감은 아직 확인하지 않았습니다. GitHub에는 게시하지 않습니다.
