# NyoruRPG 0.25.1

오류가 반환되는 연결을 소스에서 조사해, 입력·저장·대상 해석의 결함을 수정했습니다. 연결 모듈 v1 사용자는 **플러그인만 업데이트**하면 됩니다. 재구축이나 세이브 초기화는 필요하지 않습니다.

## 발견한 결함과 수정

| 경로 | 원인과 영향 | 수정 |
|---|---|---|
| 놓치지마 검사 → 미해결 목록 | 실패·중단 보고서나 구버전 보고서에는 `issues` 또는 `results`가 없을 수 있는데, 이를 `undefined` 그대로 해시 입력에 넣었습니다. 엄격한 JSON 검사가 거절해 실제 문제를 도움 목록에 저장하지 못할 수 있었습니다. | 보고서 선택 항목의 기본값을 지정했습니다. 기존 목록을 버전4로 옮길 때 현재 채팅의 마지막 보고서를 한 번 다시 수집합니다. 기존 입력 초안·수동 정리·저장된 결과는 보존합니다. |
| 물체 대상 소모품 | 공통 계열의 검사 사전 확인은 실제 `effectObjects`가 아닌 `objects`를 조회했습니다. 에렌샤는 단일 `target` 물체를 인물 등록으로 보냈고 검사도 인물만 조회했습니다. | 공통 d100·헌터·무림과 에렌샤에서 저장된 물체를 사용합니다. 에렌샤 직접 호출과 검사 적용을 함께 연결하고 미해결 편집의 대상 선택에도 물체를 넣습니다. 물품 전달은 계속 인물에게만 가능합니다. |
| 에렌샤 장비 수리 | 실제 내구도와 수리 계산은 소수를 지원하지만 MCP 입력 `amount`는 정수로 제한돼 `2.2` 같은 수리가 형식 오류로 막혔습니다. | 숫자 입력으로 통일합니다. 실제 비용·복구 재료·소지금 조건은 기존 계산을 따릅니다. |
| 직접 편집·미해결 적용의 오류 표시 | 실패 응답은 최상위 `code`와 문자열 `error`인데 일부 소비자는 `error.code/message` 객체만 읽었습니다. 실제 원인이 일반 저장 실패 문구로 바뀌었습니다. | 문자열·객체 실패 응답 모두에서 실제 코드와 원인 문구를 읽습니다. |
| 탐험 장소 초안 재사용 | 추가 지침이 없고 공통 어댑터도 없는 경우, 장소 키의 세계관 지침이 `undefined`가 되어 키 생성이 실패했습니다. 오류가 잡힌 뒤 재사용 기능만 해제돼 이후 재생성에서 불필요한 준비 요청이 생길 수 있었습니다. | 빈 지침은 빈 문자열로 저장합니다. 같은 조건의 완료된 초안을 재사용하며 활성 지도·발견·보상 기록은 별도로 유지합니다. |
| 탐험 AI 응답 형식 | 구역·적 목록의 `null`을 속성 접근 오류로 처리하거나, 장치 접근법에 `possible`이 없는데도 가능하다고 간주할 수 있었습니다. | 문제 구역·적 번호와 접근법 가능 여부 누락을 `EXPLORATION_RESPONSE`로 알립니다. 잘못된 응답으로 판정·피해를 만들지 않습니다. 완료된 응답을 보존하고 자동으로 유료 재요청하지 않습니다. |
| 거리 효과 입력·구축 전 조회 | 배열의 최대 길이만 검사해 네 거리 보정의 최소 길이 조건이 무시됐습니다. 또 구축 전 상태를 검사하기 전에 `w.meta`를 읽었습니다. | 최소 길이도 검사하고, 미구축 상태는 `SETUP_MISSING`으로 알립니다. |

이 조사는 에렌샤만이 아니라 공통 호출·검사와 공통 d100·헌터·무림, 로맨스 판타지·미연시의 준비·조회·오류 연결을 대상으로 했습니다. 위 표는 구체적인 결함을 찾은 부분입니다. 모든 기능이 정상이라는 판정은 아닙니다.

## 업데이트 후 기존 기록

미해결 목록에서 빠졌던 **현재 채팅의 마지막 검사 보고서**를 한 번 다시 읽습니다. 저장소 전체의 모든 과거 보고서를 재생하는 기능은 아닙니다. 기존 보고서가 삭제됐거나 원인이 기록되지 않은 과거 사건을 추측해 복구하지 않습니다.

실제 소지금 부족·선행 조건 부족·잘못된 대상·사용자 선택 대기·분기 충돌은 계속 차단됩니다. 이미 저장된 주사위 실패나 거래·강화·보상을 재실행하지 않습니다. 오류 코드가 있다는 이유만으로 성공 처리하지 않습니다.

## 확인 범위

소스의 반환 형식과 호출·준비·저장·편집 연결을 읽고 수정했으며 배포 파일을 생성했습니다. 별도 최종 정적 검사, 브라우저·모의 호스트·가상 전투·실제 RisuAI·유료 API 호출은 하지 않았습니다.

실제 Risu에서 오류 팝업이 표시되는지, 기존 미해결 항목을 편집해 적용하는지, 물체 대상 사용과 소수점 수리가 정상 완료되는지는 실사용 확인이 필요합니다. 외부 호스트의 타임아웃을 해결했다는 뜻도 아닙니다. 기존 MCP 식별자·실제 완료 대기·카드 배치·채팅 격리·세이브·사용자 편집을 유지합니다.
