# NyoruRPG 0.40.2

2026년 10월 13일. 해적리스에서 답변이 끝난 뒤에도 뉴뉴·직접 편집이 `GENERATION_UNSETTLED`로 막히는 문제를 수정했습니다.

**플러그인만 업데이트. 모듈 v1은 그대로**

## 수정 내용

0.40.1은 호스트가 `isStreaming: false`를 돌려줘야 완료 알림 없이 남은 저장을 복구했습니다. 그러나 제보에서는 해당 필드가 없었습니다. 해적리스 b7612의 `getChatFromIndex`는 SQL에서 읽은 채팅 사본을 반환하므로 실제 생성 상태와 같다고 가정할 수 없습니다. 이전 수정은 이 차이를 처리하지 못했습니다.

- 메인 화면 접근이 허용된 경우 해적리스의 실제 입력창에서 전송·취소 상태를 읽습니다. 취소 버튼이 없다는 사실만으로 완료라고 판단하지 않습니다.
- 전송 가능한 상태이고 저장된 답변·사용자 입력·기존 문맥이 일치하면 밀려 있던 RPG 결과를 확정한 뒤 편집합니다. 업데이트 전에 남은 임시 저장도 같은 경로를 사용합니다.
- 완료 알림을 받았으나 저장 사본의 출력 중 표시가 남은 경우에도 재확인합니다. 알림과 다른 답변 원문을 대신 확정하지 않습니다.
- 실제 생성 중, 저장된 답변 없음, 원문 불일치, 화면 확인 불가를 구분합니다. 생성 상태를 확인하지 못했을 때 새로 고침만 반복하라고 안내하던 문구도 바꿨습니다.

기존 거래·아이템·돈·보상·주사위를 재실행하지 않습니다. 채팅 원문과 호스트 화면을 수정하거나 전송 버튼을 누르는 기능은 없습니다. 여러 채팅 화면이 동시에 보여 대상을 확정할 수 없는 경우에는 화면만으로 완료를 판정하지 않습니다.

## 적용

플러그인을 0.40.2로 업데이트하고 Risu를 새로 고침한 뒤 해당 채팅의 RPG 창에서 다시 편집합니다. 기존 시스템을 재구축하거나 저장을 삭제할 필요는 없습니다. 완료 알림을 받지 못한 해적리스에서는 호스트의 메인 화면 접근 권한과 실제 입력창 상태를 확인할 수 있어야 합니다.

## 확인한 범위

Code Review Graph의 설치된 CLI로 자동 저장·직접 편집의 연결 경로를 확인했습니다. 실제 App·Repository·편집 코드를 사용하고 외부 호스트·저장소·SafeDOM 경계만 대체한 자동 테스트에서 제보와 같은 `hostStreaming: null`, `outputObserved: false` 오류를 먼저 재현했습니다. 수정 후 재시작 복구, 거래 1회 반영, 생성 중 차단, 지연 알림 복구, 미확인·미저장·원문 불일치 차단 등 7개 테스트가 통과했습니다.

설치된 Risu·실제 휴대폰·유료 API로 확인한 결과는 아닙니다. 완료 알림이 사용자의 환경에서 누락된 정확한 이유까지 확정한 것은 아닙니다.
