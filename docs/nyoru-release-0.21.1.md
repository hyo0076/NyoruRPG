# NyoruRPG 0.21.1

0.21.0 점검에서 확인한 미반영 항목을 보완했습니다. **플러그인 JS와 함께 제공한 모듈을 교체하세요. 기존 게임의 시스템 재구축은 필요 없습니다.**

## 뉴뉴에게 수정을 요청하기

기술만 다루던 제안을 다음 항목으로 확장했습니다. 제안 버튼을 누르면 JSON 대신 항목별 편집창이 열립니다. 저장 버튼을 눌러야 실제 게임에 반영됩니다.

| 룰북 | 제안에서 열 수 있는 편집 |
| --- | --- |
| 공통 d100·헌터 | 기술 제작·수정, 보유 장비·소모품, 인물 수치, 전투 옵션 |
| 에렌샤 | 기술·숙련도 추가와 수정, 보유 물품, 본명·닉네임 등 인물 정보, 기존 퀘스트, 전투 옵션 |
| 무림 | 기술 제작·수정, 보유 물품, 수행·능력 수치, 전투 옵션 |
| 로판·미연시 | 인물 수치, 보유 물품, 방향별 관계 |
| 로판 | 기존 설계의 목표·라이프·확보한 준비 수정 |

기존 편집기의 저장 경로를 사용합니다. 인물·물품·퀘스트를 임의로 새로 만드는 관리자 기능은 추가하지 않았습니다. 다른 룰북에 없는 기능을 만들어서 제안하지 않도록 현재 룰북과 편집 가능한 필드를 전달합니다.

뉴뉴에게 룰북별 규칙, 효과·인챈트·성장, 장비·내구도, 전투 옵션, 메뉴 위치와 API 사용 지식을 연결했습니다. 현재 인물의 실제 기술·소지품 정의와 이전 제안도 함께 전달합니다. Nyang-010의 작업 선언, 기계식 보고, 고양이 말투, 자율적인 애정 표현과 거절, 모르는 내용 확인, 계산 정정 성향을 반영했습니다. 뉴뉴를 끄면 대화가 삭제됩니다.

## 에렌샤 재구축과 편집 저장

재구축 때 ID만 비교하던 병합을 본명·닉네임·저장 별칭과 연결했습니다. 명시적으로 같은 인물로 연결된 새 ID는 기존 인물 ID에 합칩니다. 이름이 비슷하다는 이유만으로 합치지 않고, 같은 종류의 몬스터도 서로 합치지 않습니다.

기존 레벨·숙련·현재 자원·수량·착용 상태를 보존하면서 새 인물 설명과 기술·장비 정의를 연결합니다. 돈이나 중복 물품을 두 번 지급하지 않습니다.

시스템 구축 화면을 떠나거나 구축을 적용하면 초안 편집 상태를 정리합니다. 이미 적용한 초안에 편집을 다시 저장하는 경로도 막았습니다. 플레이 편집 저장은 현재 게임 편집으로 처리합니다. 사용자가 보고한 동시 저장 현상을 실환경에서 재현한 것은 아니며, 초안과 플레이 편집 상태가 섞일 수 있는 경계를 수정한 것입니다.

## 놓치지마 검사

검사 AI에 최근 실행 기록의 **실제 호출 인수와 사건 ID**도 전달합니다. 이미 저장된 행동을 확인하는 데 사용합니다.

서술에서 실제 사용했지만 기록이 빠진 **전투 밖의 직접 소모품 사용**은 저장된 아이템 규칙으로 회복·효과·수량을 함께 처리할 수 있습니다. 서술에 적힌 회복량을 그대로 넣지 않습니다. 새 주사위가 필요한 효과, 투척, 전투 중 사용은 소급 실행하지 않고 미해결 내용으로 전달합니다. 계산 도중 주사위가 필요해지면 해당 보완의 변경을 저장하지 않습니다.

이미 기록된 행동 참조와 고정된 사건 키로 중복 처리를 줄였습니다. 모델이 서로 다른 표현을 같은 사건으로 알아보는 데는 여전히 한계가 있습니다. 검사는 기본 OFF이며, 다른 플러그인보다 먼저 실행되는 전역 우선순위는 Risu의 공개 훅에서 지정할 수 없습니다.

## 탐험 준비와 콜백 진단

같은 채팅·룰북·구축 자료·입력 조건에서 장소 생성이 완료됐으면, 답변 재생성 시 그 장소 초안을 재사용합니다. 저장 게임에 이미 존재하는 장소의 방문·보상 기록이 항상 우선입니다. 미래 장소를 임의로 미리 만들거나 추가 API를 호출하지 않습니다.

제공된 0.20.1 진단의 call 12에서는 메인 답변 완료 알림이 플러그인 반환보다 약 **5.9초 앞섭니다**. 긴 준비 단계가 있는 것은 확인되지만, 이 기록만으로 고정된 30초 제한이나 오류를 반환한 계층을 확정할 수는 없습니다. 다운로드된 Provider Manager 사본에는 일부 외부 도구 경로의 기본 30초 제한이 있으나, 해당 경로가 현재 설치된 NyoruRPG 호출에 쓰였다는 증거는 아닙니다.

이번 변경은 완료된 장소를 다시 생성하는 일을 줄입니다. **첫 장소 생성의 대기시간이나 외부 콜백 타임아웃을 해결했다고 주장하지 않습니다.** 15초 처리 중 응답·재호출 방식은 다시 넣지 않았고, 카드 배치와 도구 완료 전달 방식도 바꾸지 않았습니다.

## 작업 범위

소스 수정과 배포 파일 생성만 했습니다. 별도 최종 검수, 브라우저·가상 전투·모의 호스트, 실제 RisuAI, 유료 API 호출 및 경량 모델 비교는 실행하지 않았습니다. 경량 모델의 실제 성공률·성능은 확인되지 않았습니다.
