# 0.30.0~0.30.11 제보 수정의 룰북별 연결 점검

2026-10-12 · 같은 0.30.11 로컬 수정본 · GitHub 게시 보류

사용자가 요구한 범위는 이번 장비 화면만이 아니라, 0.30.0 이후 제보한 문제의 수정이 다른 룰북에도 연결되었는지 확인하는 것이다. 대화의 `3.0.0`은 실제 프로젝트 버전과 앞선 요청을 기준으로 `0.30.0`으로 해석했다. 이전에 제보했고 이 기간에 다시 영향을 준 초기 구축·사거리·카드 문제도 포함했다.

이 문서는 **현재 소스의 호출·표시·저장 경로를 읽은 기록**이다. 테스트 실행, 브라우저, 모의 전투/호스트, 설치된 RisuAI, 유료 모델 호출은 하지 않았다. 따라서 아래의 연결 확인을 실제 호스트에서의 성공이나 모든 버그가 없다는 증거로 표현하지 않는다. 과거 사용자 세이브의 잘못된 수치를 추정해 일괄 변경하지 않는다.

## 룰북 범위와 공통화 기준

| --- | --- | --- | --- |
| D100 | native / native-ui / item-editor-ui | 공통 목록·편집 틀, 미니 UI, 적 개체 표시 | D100 판정·기술 위력·장비 효과 유지 |
| 얼터네이티브 헌터 | native / native-ui / item-editor-ui | 같은 공통 경로 | 헌터 성장·게이트 인스턴스 유지 |
| 무림 | native + murim / native-ui / item-editor-ui | 같은 공통 경로 | 경지·깨달음·무공 유지 |
| 에렌샤 온라인 | erencha / erencha-ui | 공통 목록·편집 틀, 미니 UI, 적 개체 표시 | 아이템 위력·방어·숙련도·현실 생활 유지 |

목록은 얼헌의 장착 장비/물품 카드 구성을 기준으로 하고, 편집은 에렌샤의 항목별 탭·저장/취소 구조를 기준으로 한다. 사용자가 얼헌의 편집창까지 선호했다고 해석하지 않는다. 사회 룰북에 없는 무기 위력·전투·장착 칸을 새로 만들거나 모든 룰북의 계산식을 같게 바꾸지는 않는다.

## 이번에 추가로 발견하여 수정한 경로

1. **내구도 필드 차이:** 공통 장비 상태 확인은 택티컬/지르코트의 숫자형 `durability`와 `maxDurability`를 읽지 않고 일반 장비의 `durabilityCurrent`를 기준으로 판단할 수 있었다. `durability.info`를 연결해 파손 판정·장착 행동 안내가 실제 저장값을 사용하게 했다. 마모는 각 전투 엔진이 한 번만 계산한다.
2. **수리의 실제 회복량 누락:** 택티컬/지르코트의 수리 응답에 전후·최대·남은 내구도와 `fullyRepaired`를 추가했다. 부분 수리를 완전 수리로 설명하지 않도록 결과에 명시한다. 해당 룰북의 원래 수리 비용과 회복 규칙은 바꾸지 않았다.
3. **놓치지마의 물품 사용 사전 검사:** 일반/에렌샤의 인물·물품 필드만 가정한 경로를 수정했다. 택티컬/지르코트의 `actor`·`item`, 사회 룰북의 `record/possession + mode:use`도 실제 소유 물품과 연결한다. 동명 물품·물체는 저장 ID로 구분하고, 실제 사용 가능 여부·비용·효과는 원래 엔진에서 검사한다.
4. **사용 보완 후보 누락:** 일반 소모품 외에 사용 보상이 있는 물품, 효과 준비가 필요한 골드 주머니/상자, 사회 룰북의 보유 물품도 검사 자료에 포함한다. 판매 가격을 개봉 보상으로 바꾸지는 않는다.
5. **적 이름의 개체 번호 누락:** 적 특징 화면, 미니/전체 화면의 일반 턴 순서, 택티컬/지르코트 전투 요약·결과 카드에 공통 `combatName`을 사용한다. 택티컬의 저장 구역도 번호 기준에 포함해 살아 있는 적만 다시 세어 번호를 바꾸지 않는다. 인물의 저장 이름·ID는 변경하지 않는다.
6. **미니 UI 전체 실패와 오류 캐시:** 기술별 표시를 분리해 한 기술 오류가 나머지 목록까지 없애지 않게 했다. 실패한 페이지는 성공 캐시로 보관하지 않고 다시 열 때 읽는다. 오류 진단에는 인물·분류·페이지·기술/물품 ID를 남긴다. 택티컬 물품도 전체 HTML을 먼저 만든 뒤 자르지 않고 현재 페이지의 항목만 렌더한다.
7. **룰북별 목록·편집 동선 분기:** `inventory-ui`의 목록/편집 틀을 모든 룰북에 연결했다. 택티컬/지르코트 편집은 효과·기본 정보·착용/사용·내구도·상세 설정으로 나눴다. 사회 룰북은 목록의 편집 버튼에서 들어가 저장/취소하며, 처음 연 원본을 기준으로 변경 충돌을 확인한다. 공통 장비 설명도 직접 편집한다.

8. **장비 행동과 기술 목록:** equipment-actions의 표시 전용 분류를 여섯 전투 룰북·미니 UI·도구 결과·헌터/에렌샤 상태창·무림 기술 요약에 연결했다. 수동으로 설정한 신발·옷의 행동을 삭제하지 않는다.
9. **한글 검색:** registry-ui/storage-ui가 search-input을 공유하며 IME 조합 중 전체 재렌더를 미룬다. 검색 값과 포커스·커서를 보존한다.
10. **파티 표시:** 모든 룰북 현재 상태에 party-ui를 연결하고 제목을 파티로 통일했다. 실제 등장·동행과 고유 자원·부상·효과를 사용한다. 헌터 다섯 최종 능력치도 표시한다.
11. **행동 실행 창 제거:** optional-feature-operations-ui를 삭제했다. 전 룰북의 재장전·치료·휴식·수련·퀘스트·상점·장소 실행 폼을 제거하고 편집창·MCP·놓치지마는 유지한다. 성좌 내부 진행 배너도 제거했다.
12. **헌터 내장 인물:** hunter-catalog와 구형 전용 목록 UI를 제거했다. hunter-setup은 시작 명단만 준비하고 이후에는 ensure_actor를 이용한다. 기존 세이브 인물을 일괄 삭제하지 않는다.

이와 함께 앞서 수정한 **설명·조회에서 장비 실행 검사를 호출하던 문제**를 유지한다. 설명을 읽을 때 미장착 장비가 섞여도 막지 않지만, 실제 공격은 장착·소유·파손·수량을 계속 확인한다.

## 항목별 소스 확인 기록

표의 ‘기존 연결 확인’은 해당 수정과 공통 호출 경로를 소스에서 확인했다는 뜻이다. ‘이번 수정’은 위 변경을 포함한다. ‘고유 기능’은 다른 룰북에 같은 기능이 없으므로 무작정 복제하지 않는다는 뜻이다.

## 확인 후에도 구분해야 하는 범위

- 이전 수정이 모두 에렌샤 전용이었던 것은 아니지만, **공통 함수가 있다는 사실만으로 모든 호출자가 그 함수를 쓰는 것은 아니었다.** 이번에 내구도·검사 사전 확인·적 이름·화면 구조의 누락 연결을 추가했다.
- AI가 올바른 도구/대상/근거를 제출하는지, 의미를 놓치지 않는지는 소스 확인만으로 성공을 확정할 수 없다. 검사 누락 자체가 자동으로 사라졌다고 말하지 않는다.
- 실제 동시 편집, 모호한 대상, 부족한 돈/수량, 파손·양도한 장비, 다른 원문의 되돌리기를 계속 차단한다. 모든 오류를 숨기거나 검증을 풀어 통과시키는 수정은 하지 않는다.
- 이동과 공격을 합치는 신규 설계, 전략 룰북/GM 확대 등 미구현 설계를 기존 버그 수정 완료 목록에 넣지 않는다.
- 설치된 RisuAI·모바일·사용자 세이브의 재현 여부는 별도다. 이번 결과는 소스 수정과 배포 파일 생성까지이다.
