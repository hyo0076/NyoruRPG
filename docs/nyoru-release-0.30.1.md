# NyoruRPG 0.30.1

**플러그인만 업데이트. 모듈 v1은 그대로**

## 과거 대화 PDF의 두 가지 방식

AI 연결 → **메인 AI · 과거 대화 PDF**에서 사용 여부와 처리 방식을 선택합니다. 설정은 즉시 저장됩니다. 기본 OFF이며 이전 버전에서 켰던 설정은 **유미 연동**으로 유지합니다.

| 메인 AI 연결 | 선택할 방식 | 필요한 설정 |
| --- | --- | --- |
| 유미 Provider Manager | 유미 연동 | 유미 모델의 Gemini PDF, PDF 수동 지정 켜기 |
| Risu 기본 Gemini / Vertex | 독립 PDF → Gemini 원본 API | PDF 입력을 지원하는 Gemini 연결 |
| Risu 기본 OpenAI 호환 Chat의 Gemini | 독립 PDF → OpenAI 호환 Chat | Gemini 모델 ID와 `file` PDF 첨부를 지원하는 중계 |

독립 방식은 Risu의 공식 요청 본문 편집 API로 연결합니다. 기기에서 PDF를 만들며 유미나 별도 AI 생성 호출이 필요하지 않습니다. Risu에 저장한 메인 AI의 주소·인증·모델을 그대로 사용하고 스트리밍·도구 호출·후속 요청은 Risu가 처리합니다. 플러그인의 기본 생성 API·뉴뉴·Jev 요청을 이 기능으로 바꾸지는 않습니다.

Risu에 요청 편집 기능이 없거나 권한을 허용하지 않으면 화면에서 안내하고 원문을 유지합니다. **독립 PDF 요청 연결 다시 등록**으로 다시 연결할 수 있습니다. Responses API·다른 프로바이더 플러그인·문서 미지원 모델을 범용으로 지원하는 기능은 아닙니다. 유미를 메인 AI로 쓰는 경우 기존 유미 방식을 선택하세요.

OpenAI 호환 주소라는 이유만으로 PDF를 지원하는 것은 아닙니다. [LLMGateway 문서 입력 안내](https://docs.llmgateway.io/features/documents)처럼 선택한 중계와 모델이 PDF `file` 입력을 지원해야 합니다. API가 문서 첨부를 거부한 경우에는 옵션을 끄거나 지원하는 연결을 선택하세요. 실패한 도구를 플러그인이 임의 재실행하거나 별도 API로 재전송하지 않습니다.

## 무엇을 PDF에 넣는가

- 최근 사용자 메시지·AI 답변은 기본 4개 블록을 유지합니다. 각각 1개로 세며 2~50개로 조절할 수 있습니다.
- 시스템 지침, 현재 RPG 상태, 도구 호출·결과, 서명, 첨부와 캐시 경계를 제외한 연속 과거 대화가 2,048자 이상인 구간을 선택합니다.
- 독립 방식은 실제 전송 본문에서도 원문과 역할이 정확히 맞는 구간만 교체합니다. Risu 또는 다른 플러그인이 내용을 바꿔 확인할 수 없으면 텍스트로 남깁니다.
- PDF에는 원래 사용자/AI 역할·이름·내용을 시간 순서로 기록합니다. 요약하거나 새 사실을 생성하지 않습니다.
- 저장 채팅, 게임 데이터, 원래 시스템 지침과 최신 도구 프로토콜은 변경하지 않습니다.

유미 방식은 변환 범위만 지정합니다. PDF 전송을 완전히 끄려면 유미의 모델별 PDF 설정도 꺼야 합니다. 기존 유미 표식이 있으면 독립 방식은 중복 변환하지 않습니다.

## PDF 재사용과 진단

독립 방식은 같은 채팅·분기에서 원문이 같은 PDF를 재사용합니다. 원문이 달라지면 새로 만들며 캐시는 최대 16개·16MiB입니다. 채팅 변경·설정 변경·플러그인 종료 시 비웁니다. PDF 전체는 게임 백업이나 호스트 진단에 저장하지 않습니다. 요청은 1,000쪽·인라인 JSON 20MB 한도 안에서 준비하고 초과하거나 생성에 실패하면 원문을 유지합니다.

**AI 연결 → 메인 AI · 과거 대화 PDF**와 호스트 진단의 `mainContextPdfPrepared`에서 선택 분량·생성된 PDF·재사용 수·텍스트 유지 사유를 확인할 수 있습니다. 독립 방식의 `conversionConfirmed`는 기기에서 PDF를 만들어 요청 본문에 넣었다는 뜻입니다. `deliveryConfirmed:false`와 `usage:null`은 서버 수신·토큰·청구를 이 훅으로 확인하지 못한다는 뜻입니다.

PDF를 다시 만들지 않는 것과 서버 캐시 할인은 별개입니다. 비용 절감률은 실제 프로바이더의 문서·입력·캐시 사용량으로 비교해야 합니다. PDF 생성·첨부 준비만으로 성공적인 모델 응답이나 절감액을 확정하지 않습니다.

## 변경 범위

소스 수정과 0.30.1 배포 생성·GitHub 게시를 진행합니다. 요청에 따라 별도 최종 검사·모의 호스트·브라우저 검수·실제 Risu 실행·유료 API 호출은 추가하지 않았습니다. Jev는 계속 실험 중인 선택 기능입니다.
