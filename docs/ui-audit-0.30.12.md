## 작업 우선순위

### P1 · 설정 저장 실패와 재시도 — 이번에 수정

기존 `play-settings-ui.bind`는 저장 시점에만 DOM 값을 읽었다. 저장이 거절되면 `UI.act`가 저장된 상태로 화면을 다시 그려 방금 고른 값이 사라졌다. 실패한 요청을 실제 UI 이벤트 테스트로 재현한 뒤 수정했다.

- 토글, 선택 목록, 속도 수식, 이동 숙련도, 인물 이동력, 지르코트 세부 수치를 현재 채팅·룰북의 작은 임시 입력으로 유지한다.
- 저장 요청 중에는 추가 제출과 입력 변경을 막고 `저장 중…`을 표시한다.
- 실패하면 오류와 입력을 남겨 다시 저장할 수 있게 한다. 성공한 재시도에서는 이전 실패 안내를 제거한다.
- 처음 편집한 설정의 충돌 검사값을 유지한다. 다른 곳에서 바뀐 설정을 조용히 덮어쓰지 않는다.
- `저장된 설정으로 되돌리기`는 임시 입력을 버리고 호스트의 현재 설정을 다시 읽는다.
- 다른 채팅의 실패 입력을 현재 채팅에 복원하지 않는다. 임시 입력은 UI 세션의 자료이며 영구 저장 기능은 아니다.

근거: `src/play-settings-ui.js`의 `bind`, `src/ui.js:196–204`의 `act`. 실제 게임 저장 함수 `play-settings-ui.save`의 관리자·충돌·전투 중 변경 금지 검사는 변경하지 않았다.

### P1 · 긴 장비·소지품 목록 — 수정

기존 adapter가 전체 물품의 카드·파츠 후보·장착 행동 설명을 먼저 만들었다. 이제 공통 `inventory-ui.collection`이 이름·설명 검색 후 12개만 전달한다. 장착 요약은 별도로 유지하고 카드의 위력·방어·수량·효과와 직접 편집은 남긴다. 관리 영역은 한 물품씩 열며 그때 강화·파츠·기본 행동 내용을 만든다. 지르코트 창고와 보관 후보 역시 전체를 검색하고 12개만 생성한다. 미니와 초기 구축 초안에 이 전체 창 페이지 동작을 덮어쓰지 않는다.

29개 보유품 시나리오에서 첫 페이지 12개, 다음 페이지, 마지막 물품 검색과 편집·취소를 8개 룰북에서 확인했다. 실제 OOM 해소나 메모리 감소량 측정은 아니다.

### P2 · 플레이 설정의 설명 밀도 — 수정

`setting-row-ui`로 기능 이름·선택·핵심 설명을 먼저 보여준다. 긴 설명은 별도 `details`로 펼치며 토글 라벨 안에 넣지 않는다. 현실모드의 미납과 사망 조건은 핵심 설명에도 남긴다. 기존 data 속성, 저장 요청 형식, 실패 후 입력 보존은 유지한다. 초기 구축용 prefix는 기존 모양을 유지한다. 새로운 실행 버튼이나 조합 해설 패널은 추가하지 않았다.

### P2 · 현재 상태에서 반복되는 정보 — 수정

실제 파티 카드에 표시된 인물만 선택 인물 영역의 반복 자원·효과·성장값을 생략한다. 택티컬·지르코트 부상과 미연시 체력도 같은 원칙을 적용한다. 부상 안정화와 부위 기능 상실을 파티에 보존했다. 무림 돌파 조건, 직업·명성·현실 생활, 피폭·수납·스트레스·데이트와 편집 진입은 남긴다. 초안과 미니는 파티가 있다는 가정으로 정보를 생략하지 않는다.

### P2 · 편집 방식의 잔여 차이와 오래된 안내

로맨스·미연시의 인물/관계 편집은 `social-ui.js:56–63`의 별도 펼침형 저장·삭제 방식이다. 이미 통일한 소지품 편집과는 구별해서 다뤄야 한다. `ui.js:234`의 헌터 구축 안내에는 삭제한 내장 인물을 사용한다는 문구도 남아 있다.

수정 방향: 인물·관계 편집도 입력 유지와 저장/취소의 동작을 맞추되 필드와 규칙은 보존한다. 구축 안내는 현재의 요청 인물·원문 준비 방식에 맞춘다. 이번 패치에서는 이 영역을 바꾸지 않았다.

### P3 · 키보드로 편집 탭 조작

`effect-editor-ui.js:45–49`는 탭 역할과 클릭 동작을 제공하지만 탭 사이의 키보드 이동 처리는 없다. 이는 장비 편집의 ‘기본 정보 / 효과 / 착용·사용’ 선택에 관한 항목이다. 지도나 캐릭터를 방향키로 움직이는 기능을 뜻하지 않는다. 사용자에게 필요한 저장·탐색 문제보다 먼저 구현하지 않는다.

## Hallmark 디자인 감사

기존 다크/라이트 색과 승인된 여섯 카드 테마가 판단 기준이다. 게임 정보를 비교하기 위한 카드나 성좌의 고유 장식 자체를 결함으로 세지 않았다. 새 테마·폰트는 적용하지 않았으며 기존 토큰을 사용하는 목록·설명용 CSS만 추가했다.

### Major

**Tell: Toasts that shift layout.** 위치: `ui.js:456`, `ui.css:152` 및 `.notice:empty`. 오류/저장 피드백이 본문 앞의 흐름 안에 삽입되고, 오류 상세 패널도 뒤따라 붙는다. 입력하던 내용과 오류 위치가 멀어질 수 있는 구조다. 실제 이동 픽셀은 측정하지 않았다. **Fix:** 해당 저장 영역 가까이에 안정된 피드백 영역을 두고 긴 오류 기록은 접는다. 채팅을 가리는 새 상시 알림 창을 만들지 않는다. 이번 입력 보존 수정으로 이 배치까지 해결했다고 보지 않는다.

### Minor

**Tell: Every section padded the same.** 위치: `ui.css:143–145`, `play-settings-ui.js:8–12`. 짧은 선택과 긴 안내가 같은 패널 무게로 이어져 설정 화면이 길어진다. **Fix:** 선택 행의 밀도와 상세 설명의 여백을 분리한다. 단순히 글자를 모두 작게 만들지 않는다. 후속 수정에서 짧은 선택 행과 펼친 설명을 분리했으며 실제 화면 크기별 렌더 검증은 하지 않았다.

## TDD 기록
