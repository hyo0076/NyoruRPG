# NyoruRPG 0.21.0

플러그인 **NyoruRPG.js**와 모듈 **NyoruRPG.risum**을 함께 교체하세요. 기존 게임을 다시 구축할 필요는 없습니다. 모듈 룰북은 사용자가 직접 고르는 방식을 유지합니다.

## 에렌샤와 기술 편집

- 에렌샤의 기술·숙련도 목록과 구축 초안에 추가 버튼을 넣었습니다. 공통 d100·헌터·무림도 기술 목록에서 새 기술을 추가할 수 있습니다. 항목별 편집창에서 저장합니다.
- 기술 사용 횟수는 **0 또는 빈칸이면 제한 없음**입니다. 1회로 바뀌던 변환을 수정했습니다. 기존에 저장된 1회 제한은 실제 의도와 구분할 수 없으므로 임의로 해제하지 않습니다. 해당 기술에서 0으로 저장하세요.
- 구축 화면에 닉네임 입력칸을 추가했습니다. 등록 인물 편집에서도 본명·닉네임을 지정합니다. 둘을 같은 인물의 별칭으로 사용하며 다른 ID 요청도 기존 인물로 연결합니다.
- 이미 중복 등록된 인물은 본명·닉네임이 명시적으로 연결됐을 때 정리합니다. 선택한 인물의 기존 레벨·자원·소지금·중복 항목 수치는 유지하고 없는 기술·물품을 옮깁니다. 돈과 숙련도를 두 번 더하지 않습니다. 이전 원자료와 과거 결과는 보관합니다. 비슷한 이름이나 같은 종류의 몬스터만으로 합치지 않습니다.
- 저장된 턴테이블 설정을 전투에 적용하고 각 결과에 행동자·피격자 이름을 전달합니다. `combat` 입력을 받으며, 켜진 턴테이블에서 자동 아군·적 턴을 유지합니다. 이미 진행 중인 전투를 `combat:false`로 건너뛰지는 않습니다.
- 상태 문맥에 퀘스트 ID·진행을 전달하고 `rpg_state`의 `quests` 조회를 추가했습니다. 수락·진행·완료는 기존 `record` 경로로 기록합니다. 메인 AI가 반드시 호출한다는 보장은 아니며 아래 선택 검사가 누락 보완을 도울 수 있습니다.

## 내구도와 구축 완료 화면

독·자기 HP 소모 등 공격 피격이 아닌 피해로 방어구가 마모되던 경로를 분리했습니다. 사용자가 요청했던 **무기로 준 실제 피해에 따른 무기 마모**는 유지합니다. 장비 유형과 슬롯이 다를 때 무기/방어구로 중복 분류하지 않습니다.

이미 적용한 구축 초안은 완료 안내로 표시합니다. 플레이 중 기술·장비를 저장한 뒤 옛 초안을 다시 적용하는 화면으로 보이지 않도록 했습니다. 새 구축을 요청하는 기능은 그대로 있습니다.

## AI 연결

| 연결 | 사용하는 곳 |
| --- | --- |
| 기본 API | 처음 필요한 인물·기술·행동 준비, 뉴뉴 대화 |
| 시스템 정밀 구축용 API | 시스템 구축·수정·이어 만들기 |
| 검사용 API | 놓치지마 검사 |

정밀 구축과 검사는 **기본 API 사용**이 기본값입니다. 체크를 끄면 주소·모델·인증을 따로 저장합니다. API 키와 추가 인증 헤더는 역할별 기기 로컬 저장소에 보관합니다.

**Gemini Vertex AI** 형식을 추가했습니다. Express Mode는 API 키, 일반 Vertex는 프로젝트·리전과 OAuth 액세스 토큰을 입력합니다. OAuth 토큰 자동 갱신이나 서비스 계정 JSON 로그인은 포함하지 않습니다. [Google의 엔드포인트 안내](https://cloud.google.com/vertex-ai/generative-ai/docs/start/express-mode/vertex-ai-express-mode-api-reference)

## 놓치지마 검사

AI 연결에서 켭니다. **기본은 꺼짐**이며 켰을 때 다음 흐름으로 작동합니다.

`이전 메인 AI 서술 → 새 유저 입력 → 이전 서술 검사·기록 보완 → 새 메인 AI 서술`

실제 등장 인물, 수락한 퀘스트, 판정 없이 완료된 활동·관계 사건, 소지품·착용 기록의 누락을 보완합니다. 저장 수치와 서술이 다르면 실제 저장 수치를 다음 메인 AI에 알립니다. 이미 계산한 주사위·비용·보상을 다시 실행하거나, 빠진 전투의 승패를 소급해서 만들지는 않습니다. 판정이나 소모품 사용 결과가 아예 없으면 미해결 내용으로 전달합니다.

같은 답변의 검사 계획을 보관하고 보완마다 고정된 호출 ID를 사용합니다. 재생성·재전송 때는 기존 저장 경로의 중복 방지를 사용합니다. 검사 요청이 실패했다고 자동으로 유료 호출을 반복하지 않습니다. 보완에 처음 보는 자료 준비가 필요하면 기본 API를 추가로 사용할 수 있습니다. 최근 검사 요약은 **저장·복구**에서 확인합니다.

다른 플러그인의 요청 전 처리보다 우선 실행되는 것은 보장할 수 없습니다. 검사 자체도 모델의 의미 판단을 사용하므로 모든 누락을 발견하거나 모든 설명을 정확히 해석한다고 보장하지 않습니다.

## 뭐든지 물어봐 뉴뉴 AI

준비 메뉴의 **뉴뉴 AI**에서 켜고 질문합니다. 현재 룰북과 선택한 인물의 저장 상태를 읽습니다. 기술 제작·수정을 요청하면 제안 버튼으로 기존 편집창을 열고 항목별로 수정·저장합니다. 제안만으로 게임을 바꾸지 않습니다. 대화는 플러그인의 메모리에만 두고, **뉴뉴를 끄거나 채팅을 바꾸면 삭제**합니다.

현재 직접 편집 제안은 기술을 대상으로 합니다. 다른 기능은 사용법을 설명합니다. 뉴뉴가 임의의 게임 명령을 실행하는 만능 관리자 도구는 아닙니다.

## UI와 도구 응답

첨부한 refined CSS를 반영해 버튼 크기·간격, 입력창, 패널, 사이드바, 모바일 카테고리, 편집창과 미니 창을 정리했습니다. 팔레트와 기존 플러그인 틀을 유지합니다. 전달받은 GitHub `preview/nyoru-ui.css`는 작업 시 404였으므로 함께 붙여 준 CSS를 기준으로 했습니다.

0.20.2의 **15초 처리 중 응답과 같은 도구 재호출 요구**를 제거했습니다. 기존 직렬 실행이 끝난 실제 결과를 반환합니다. 결과 카드·출력 연결은 0.18.8에서 복원한 방식을 유지합니다. 이 변경만으로 외부 호스트의 콜백 타임아웃 원인이 해결됐다는 뜻은 아닙니다.

## 경량 모델 선택

Flash-Lite와 GPT-6 Luna는 경량 처리용 모델로 제공됩니다. [Google 모델 목록](https://ai.google.dev/gemini-api/docs/models), [OpenAI GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)

NyoruRPG에서는 저장된 명중·피해 계산 자체에 모델을 쓰지 않습니다. 단순 인물/기술 준비와 뉴뉴 질문에는 경량 모델부터 사용해 볼 수 있습니다. 복잡한 효과를 조립하는 정밀 구축, 긴 서술과 기존 기록을 대조하는 검사는 더 강한 모델을 따로 두는 것을 권합니다. 이는 작업 성격에 따른 권장 구성이며 실제 모델 비교 시험 결과가 아닙니다.

## 이번 작업 범위

소스 수정과 배포 파일 생성만 진행했습니다. 사용자의 요청대로 별도 최종 검수, 브라우저·모의 호스트·가상 전투, 실제 RisuAI, 유료 API 호출은 실행하지 않았습니다. 실사용 결과와 성능은 확인되지 않았습니다.
