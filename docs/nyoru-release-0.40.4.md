# NyoruRPG 0.40.4 · 개인 API 프록시 설정

AI 연결에 **개인 프록시 주소**와 **프록시 토큰** 입력을 추가했습니다. 기존의 ‘직접 전송’은 브라우저에서 API에 직접 요청하는 기능이고, ‘키 없는 프록시 사용’은 API 키 검사를 생략하는 옵션이었습니다. 별도 프록시 주소를 설정하는 기능은 없었습니다.

**플러그인만 업데이트. 모듈 v1은 그대로**

## 설정 방법

1. **AI 연결 → 기본 API**를 엽니다.
2. **API 형식·API 주소·모델 ID·API 키**에는 원래 생성 API의 값을 입력합니다. API 주소를 프록시 주소로 바꾸지 않습니다.
3. **전송 방식 → 개인 프록시**를 선택합니다.
4. **개인 프록시 주소**에 본인이 사용하는 프록시의 기본 주소를 입력합니다. `?url=`은 플러그인이 자동으로 붙입니다.
5. 프록시 접속 토큰이 없는 서버라면 **프록시 토큰**을 비워 둡니다. 원래 LLM API 키는 계속 필요합니다.
6. **연결 설정 저장**을 누릅니다. 직접 연결 확인을 원하면 **연결 확인 · API 사용**을 누릅니다. 이 버튼은 실제 모델 요청을 보냅니다.

‘기본 API 사용’을 켠 초기 구축·놓치지마 검사·JEV는 같은 프록시 주소와 인증을 사용합니다. 기본 API를 공유하지 않는 별도 연결에는 그 연결의 프록시를 따로 입력합니다. 기존 RisuAI 전송·직접 전송 설정은 자동 전환하지 않습니다.

**API 키 없이 요청 · 서버가 API 인증을 대신할 때만**은 예전 ‘키 없는 프록시 사용’ 옵션입니다. 프록시 접속 토큰이 없다는 이유로 켜는 옵션이 아닙니다. API 인증을 서버가 대신하는 경우에만 사용합니다.

## 지원하는 프록시 규격

이 기능은 **외부 생성 API로 나가는 요청**을 전달합니다. 개인 HTTP MCP 중계기의 `/mcp` 주소·Publisher key·Consumer key를 넣는 곳이 아닙니다.

- 목적지: `https://본인-프록시.example/?url=<원래 API 요청 주소>` 형태입니다. 기본 주소의 경로는 유지하고 목적지 URL을 인코딩합니다.
- 요청: 원래 HTTP 메서드·본문·Content-Type과 `Authorization`, `x-api-key`, `x-goog-api-key` 등 API 형식에 맞는 인증을 유지합니다.
- 프록시 토큰: 입력했을 때만 `X-Proxy-Token` 헤더로 보냅니다. 프록시가 이 헤더를 검사하도록 구현되어 있어야 합니다. 토큰 입력만으로 서버에 인증 기능이 생기지는 않습니다.
- 프록시는 목적지로 API 인증 헤더와 본문을 전달하고, 응답의 HTTP 상태와 본문을 반환해야 합니다. 브라우저의 CORS 사전 요청과 사용한 인증 헤더도 허용해야 합니다. `X-Proxy-Token`은 프록시에서 검사한 뒤 목적지로 넘기지 않는 접속용 헤더입니다.
- Vertex 서비스 계정 방식은 Google의 고정 토큰 발급 요청도 선택한 프록시를 거칩니다. 이 경우 폼 본문과 해당 Content-Type도 보존해야 합니다.
- YumiProxy2의 `Yumi-Headers` 등 별도 전용 규격으로 자동 변환하지 않습니다. 선택한 프록시가 실패했다고 다른 경로로 생성 요청을 자동 재전송하지 않습니다.

프록시 토큰은 API 키와 같은 기기별 인증 저장소에 보관합니다. 일반 설정·게임 백업·모델 프롬프트에 넣지 않으며 오류와 JEV 상세 로그에서 가립니다. 저장된 기기 인증은 API 주소·형식·선택한 프록시 주소가 맞을 때만 불러옵니다.

## 확인 범위

소스 수정과 배포 파일 생성을 진행했습니다. 요청한 범위에 따라 추가 자동 테스트·브라우저·가상 호스트·설치 Risu·휴대폰·유료 API 호출은 실행하지 않았습니다.

보고서의 Worker 소스를 확보하지 않았으므로 실제 헤더 전달이나 HTTP 401 해소를 확인한 것은 아닙니다. HTTP 400·415·401은 서버의 거절 응답을 받은 기록이며, 그 기록만으로 프록시 없는 연결이 불가능하다고 단정할 수는 없습니다. 이 업데이트는 프록시를 명시적으로 설정하는 경로를 제공합니다.
