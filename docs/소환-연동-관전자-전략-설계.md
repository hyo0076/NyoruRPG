# 다음 시스템 설계 · 소환, 인물 연동, 관전자, GM, 전략

2026-10-09 · **소환수는 0.30.3에 구현하며, 인물 간 자원 공유·관전자·GM·전략은 설계안입니다.**

0.30.2에서는 사용자가 선택한 **기존 문제 수정 + 신규 기능 설계**를 따랐습니다. 이후 소환사부터 업데이트하라는 요청으로 등록·유지 시간·비전투 행동·성장·소환자 능력 보정을 0.30.3에 구현합니다. [실제 사용법과 적용 범위](nyoru-release-0.30.3.md). 그 밖의 신규 토글과 전략 룰북은 아직 사용할 수 있는 기능으로 안내하지 않습니다.

## 함께 유지할 원칙

메인 AI는 대사·감정·관전자 반응·사건의 서술을 맡습니다. NyoruRPG는 저장한 조건, 행동 가능 여부, 비용, 시간, 판정과 실제 결과를 처리합니다. 토글을 켰다는 이유로 별도 AI가 매 턴 퀘스트·벌칙·적을 생성하지 않습니다.

기존 인물·기술·자원·퀘스트·경험치 공유·턴 진행·행동 게이지·롤백 경로를 재사용합니다. 새 기능 때문에 사용 전에 조회 도구를 여러 번 호출하게 만들지 않습니다. 한 번의 실제 행동에서 필요한 처리를 함께 끝내고 변경된 내용만 돌려줍니다.

새 선택 기능은 기본 OFF입니다. 초기 구축과 **플레이 설정 → 선택 기능**에서 같은 이름과 순서를 사용하고, 관련 편집은 기존 인물·기술 화면에서 엽니다. 기능을 끌 때 원본 데이터를 삭제하지 않습니다.

## 1. 소환수: 등록된 인물을 불러오기

0.30.3 구현 범위: 아래의 등록·해제·비전투 사용·고정형/독립 성장·파티 경험치 참여·소환자 수치 보정입니다. 게이지 논리 시간을 사용하는 별도 유지 방식과 여러 개체를 한 번에 복제하는 생성 기능은 제안으로 남깁니다. 새 소환수 기본은 행동 5회·고정형이며 직접 설정할 수 있습니다.

### 기본 흐름

1. 소환수의 이름·HP·자원·능력치·기술·효과를 한 번 등록합니다. 소환 전에는 전투·현재 장면의 활성 대상에서 제외합니다.
2. 소환 기술에는 소환수 ID, 소환 비용, 유지 방식과 동시 소환 수를 연결합니다.
3. 기술 사용 시 비용·사용 조건을 확인하고 저장한 인물을 활성화합니다. 같은 소환수를 부를 때마다 생성 AI를 실행하지 않습니다.
4. 해제 시 장면·전투 참가만 정리하고 성장과 고유 데이터는 보존합니다.

**원본 소환수와 현재 소환 상태를 구분**합니다. 고유 사역마 하나는 같은 ID를 재사용합니다. 같은 종을 여러 마리 부르는 기술은 공통 정의를 재사용하되 각 개체의 HP·상태·남은 시간은 별도 ID로 관리합니다. 이름만 같다고 현재 개체를 합치지 않습니다.

재소환만으로 HP 회복·부활·재사용 대기 초기화가 생기지 않게 합니다. 해당 효과가 필요한 콘셉트라면 기술에 회복·재생성 규칙과 비용을 따로 저장합니다. 전투 종료 시 기존 룰북이 수행하는 재사용 대기 정리는 그대로 따릅니다.

### 유지 방식과 시계

| 사용자 선택 | 감소·종료 기준 | 전투 밖 동작 |
| --- | --- | --- |
| 행동 횟수 | 소환자의 실제 행동 완료마다 1회 | 판정·기술·조사 등 처리된 행동에서 감소 |
| 전투 중 상시 | 현재 전투가 종료되면 해제 | 전투 밖 소환은 허용하지 않는 것으로 명시 |
| 계속 상시 | 수동 해제·해제 조건까지 유지 | 계속 활동 가능 |
| 이야기 시간 | 명시한 경과 분만큼 감소 | 휴식·이동 등의 저장된 경과 시간으로 감소 |
| 전투 시간 | 행동 게이지의 논리 시간만큼 감소 | 이 방식을 선택할 때 별도의 전투 밖 유지 규칙 필요 |

0.30.3 편집기는 **행동 횟수 / 전투 중 상시 / 계속 상시 / 이야기 시간**을 사용하며 **소환수의 전투 차례**로 구형 타이머도 유지합니다. 게이지 전투 시간 자체를 소환 분 단위로 임의 환산하지 않습니다. 행동 횟수는 전투 중에는 완료된 소환자 차례, 비전투에서는 실제 처리된 행동을 셉니다.

비전투에서는 **이야기 시간**이 기본 추천입니다. 시간 기록 없이 행동 중심으로 플레이한다면 **행동 횟수**를 고릅니다. 한 소환에 두 기준을 동시에 적용해 이중 차감하지 않습니다. API 응답 대기·현실 컴퓨터 시각·화면 새로 고침·상태 조회는 유지 시간을 줄이지 않습니다.

시간·행동 중 어느 기준이든 소환을 실행한 바로 그 행동을 첫 유지 차감으로 세지 않습니다. `결과만`이나 자동 진행에서는 내부에서 실제 완료한 행동을 기준으로 감소합니다. 종료 시 진행 중 시전, 전투 순서, 보호·공유 연결과 대상 참조도 함께 정리합니다.

### 비전투 도움

소환수도 일반 인물과 같은 판정·기술 사용자로 지정할 수 있습니다. 예를 들어 까마귀가 정찰하거나 골렘이 막힌 문을 밀 수 있습니다. 누가 행동했고 어떤 능력치를 썼는지 결과에 남깁니다.

보조 행동은 등록한 보정이나 도움 기술을 적용합니다. 소환되어 있다는 사실만으로 모든 판정에 공짜 보정을 주지는 않습니다. 물건 운반·도구 사용도 그 소환수에게 저장된 기능과 실제 대상에 따라 처리합니다.

### 성장

| 성장 설정 | 처리 방법 |
| --- | --- |
| 고정형 | 등록 수치를 유지 |
| 독립 성장 | 소환수 자신의 실제 행동·처치에 해당 룰북 성장 규칙 적용 |
| 경험치 공유 | 기존 파티 경험치의 분배·동일 지급 설정에 참여 |
| 소환자 능력 연동 | 0.30.3 소환수 설정에서 소환자 기준 수치 × 계수를 더함. 일반 인물 연결과 별도 |

경험치 성장과 능력치 연동은 서로 다른 설정입니다. 독립 성장과 주인 능력 보정을 함께 쓰려면 두 항목을 명시적으로 켭니다. 레벨 경험치가 없는 무림에 일반 캐릭터 레벨을 새로 넣지 않습니다. 경지·수련 또는 고정형으로 해당 룰북에 맞춥니다.

소환수는 기본적으로 파티 경험치 수혜 인원에 추가하지 않습니다. 사용자가 **경험치 공유 참여**를 켠 소환수만 분배 인원에 포함합니다. 소환수 전용 지급과 기존 파티 지급을 따로 실행하지 않고 한 번의 처치 분배에서 처리해 중복 지급을 막습니다.

### 저장과 연결 위치

- 인물 데이터는 기존 `actors`, 기술은 `definitions.skills`를 사용합니다.
- 유지·성장 설정과 남은 시간은 `meta.summons`, 인물 자료는 기존 `actors`에 보관합니다. 기술의 `mechanics.summon`에는 저장 설정 사용 또는 기술별 유지 기준을 연결합니다.
- `combat-features`, `optional-feature-actions`, 기존 엔진의 소환 종료 처리를 공통 수명 관리 함수로 모읍니다. 새로운 세 번째 소환 실행기를 추가하지 않습니다.
- 구형 `permanent/cast` 설정은 기존 의미대로 읽고, 새 편집기가 저장할 때 명확한 유지 기준을 붙입니다.
- 소환 해제는 인물 삭제와 다릅니다. 이미 있는 고유 사역마의 장비·성장·부상을 자동 초기화하지 않습니다.

## 2. 인물 사이의 능력치·자원 연결

소환수 전용으로 만들지 않습니다. 인물 편집의 **다른 인물과 연결**에서 쌍둥이, 계약자, 사역마, 영혼 결속을 같은 방식으로 설정합니다.

### 서로 다른 세 가지 연결

| 연결 종류 | 예 | 저장·계산 방식 |
| --- | --- | --- |
| 자원 공유 | A와 B가 같은 HP를 사용 | 하나의 실제 자원 원본을 참조 |
| 비용 대납 | B의 기술이 A의 MP를 소비 | 기술 비용의 지불 대상만 변경 |
| 수치 보정 | A의 공격에 B의 힘 ×0.5 추가 | 행동 시점의 B 능력치를 읽어 계산 |

**공유 HP와 피해 전가는 별개**입니다. 현재 보호 효과처럼 피해 일부를 전달하는 방식은 두 개의 HP를 유지합니다. 자원 공유는 표시 대상이 여러 명이어도 실제 잔량은 한 개입니다.

공유 자원은 기준 인물과 자원을 반드시 고릅니다. 기본 최대치는 기준 인물의 최대치이며, 연결했다는 이유로 A와 B의 최대 HP를 합산하지 않습니다. 원래 각 인물의 자원은 보관하고 연결 해제 때 복구 방식을 명시합니다. 반복 연결·해제로 무료 회복이 생기지 않도록 해제 시 잔량은 저장된 원래 잔량과 공유 잔량 중 더 낮은 비율을 기준으로 제한하는 방안을 제안합니다.

한 번의 피해·회복 처리는 공유 원본에 한 번만 적용합니다. 광역 공격이 실제로 A와 B 각각에게 명중했다면 두 번의 피격입니다. 이를 한 번으로 줄이는 것은 별도 보호 규칙으로 정해야 합니다. 공유 HP가 0이면 연결된 인물에게 해당 룰북의 행동 불가 처리를 반영하되, 단순 잔량 동기화를 새로운 처치·보상 사건으로 생성하지 않습니다.

비용 대납은 지불자가 없는 상태이거나 잔량이 부족하면 그 이유를 반환합니다. 동의 없는 다른 자원 차감이나 새 자원 생성으로 우회하지 않습니다. 자기 HP를 비용으로 쓰는 기술의 사망 방지 조건도 지불자 기준으로 확인합니다.

### 보정값의 계산 순서

제안하는 기본 수식은 `대상 값 + 원본 인물의 기준 값 × 계수 + 고정값`입니다. 편집기에서 계산 예시를 함께 표시합니다. 예: `A의 공격 + B의 STR 30 × 0.5 = +15`.

1. 각 인물의 기초 능력과 자신의 장비·상태 효과를 계산합니다.
2. 인물 간 연결을 적용하기 직전 값을 하나의 계산 묶음으로 고정합니다.
3. 연결 보정을 적용하고 실제 행동의 비용·피해를 계산합니다.

A가 B를 참조하고 B가 A를 참조하더라도 연결 보정이 다시 자기 자신으로 돌아와 무한히 증가하지 않게 합니다. 첫 구현은 **다른 연결로 증가한 값에 재연동하지 않는 방식**을 제안합니다. 연결된 자원 원본도 하나로 확정하며 순환 연결은 저장 전에 설명과 함께 거부합니다.

대상 인물이 사망·소환 해제·장면 이탈했을 때 유지할지 중지할지도 설정에 포함합니다. 영구 계약과 같은 장면의 지원을 구분하며, 기본값은 실제 행동 가능한 연결 인물이 있을 때만 적용입니다.

### 룰북과 편집

무림은 OUTER·INNER 등 무림의 키, 에렌샤는 존재하는 자원·숙련도·레벨, 택티컬은 실제 지원하는 능력·신체 상태를 선택합니다. 없는 스탯이나 전체 HP를 임의로 만들어 다른 룰북 수식을 그대로 끼워 넣지 않습니다. 첫 구현의 자원 공유는 실제 수치 자원이 있는 항목부터 지원하고 택티컬의 신체 파괴 공유는 별도 규칙이 생기기 전까지 제외합니다.

뉴뉴는 연결 대상과 수식·비용을 제안하고 기존 편집 적용 경로로 저장합니다. 연결을 매 행동마다 AI가 다시 해석하지 않습니다. 삭제된 인물·기술을 가리키는 연결은 자동으로 다른 이름에 붙이지 않고 연결 끊김으로 표시합니다.

## 3. 성좌 토글

플레이어를 지켜보는 초월적 존재라는 설정을 메인 AI에 전달합니다. 설정 항목은 성좌 이름·성격·관심사·개입 가능 범위 정도로 시작합니다. 성좌에게 전투용 인물 시트를 의무적으로 생성하지 않습니다.

반응·훈수·대사만 있는 경우 도구 호출이 필요 없습니다. 실제 시스템에 개입할 때만 기존 경로를 사용합니다.

| 실제 사건 | 도구 처리 |
| --- | --- |
| 성좌가 퀘스트를 제시 | 퀘스트와 출처, 조건·보상을 등록 |
| 달성하여 보상을 지급 | 저장된 달성 조건과 중복 지급 여부를 확인해 처리 |
| 저주·벌칙이 실제 발동 | 대상·기간·효과를 가진 상태 변화 처리 |
| 후원 아이템 수령 | 실제 소지품·수량·소유자에 반영 |

토글을 켠 사실만으로 자동 퀘스트, 주기적 벌칙, 서사 방향을 만들지 않습니다. 등장한 성좌의 반응은 서술 AI가 결정합니다. 시스템 개입 영수증에는 출처를 남겨 놓치지마 검사와 롤백이 같은 사건을 찾을 수 있게 합니다.

## 4. 스트리밍 토글

방송 콘셉트, 시청자 유형, 채팅 분위기를 설정합니다. 예: 초보 모험 방송, 생존 전문 시청자, 장난 많은 응원 채팅. 설정은 메인 AI의 표현 자료이며 도구가 채팅 문장을 생성하거나 매 행동마다 별도 AI를 부르지 않습니다.

시청자의 도전 과제·후원·벌칙이 실제 게임에 영향을 주면 성좌와 같은 **출처가 있는 시스템 사건** 경로를 재사용합니다. 두 토글은 함께 켤 수 있지만 성좌와 일반 시청자의 이름·권한·보상 출처는 구분합니다.

시청자 수·방송 수익·구독자 경제 같은 별도 시뮬레이션은 이번 요청에 없으므로 기본 시스템에 추가하지 않습니다. 나중에 필요하면 등록된 자원이나 거래 기능으로 확장합니다.

## 5. GM 플레이: 세계 조작과 시간 진행을 구분

GM 모드의 차이는 “GM처럼 말해도 된다”는 문구가 아니라, **사용자의 기본 조작 대상을 캐릭터 한 명에서 세계로 바꾸는 것**입니다.

| 조작 | 동작 |
| --- | --- |
| 배치 | 인물·몬스터·물체·던전을 작성하고 배치 |
| 부여 | 퀘스트·선택지·사건의 실제 조건을 저장 |
| 조정 | 뉴뉴·편집 화면으로 현재 상태를 변경 |
| 진행 | 사용자가 지정한 행동·전투 구간·경과 시간만 계산 |

새로 배치하는 것과 활동을 시작하는 것을 분리합니다. 몬스터를 만들었다고 즉시 공격하거나 시간·보상이 진행되지 않습니다. 준비한 세계에서 “이제 저 인물이 행동한다”, “하루 진행”처럼 실제 진행을 요청하면 해당 범위만 계산합니다.

플레이어 아바타의 다음 행동을 묻는 기본 흐름 대신 현재 조작 대상·대기 중인 결정을 반환합니다. 기존 지휘관 모드처럼 모든 아군의 행동을 하나씩 지정하는 방식과도 구분합니다. GM은 필요할 때 개입하고, 위임한 구간은 기존 자동 진행 규칙을 사용합니다.

일반 행동의 비용·명중·피해는 룰북대로 계산합니다. GM이 직접 값을 바꾸는 요청은 판정 성공으로 위장하지 않고 **상태 편집**으로 기록합니다. 세계를 편집하는 행위가 게임 시간이나 캐릭터 경험치를 올리지는 않습니다.

화면은 새 메뉴를 여러 개 만들기보다 플레이 설정의 GM 토글과 현재 상태 화면의 **대상 선택·배치·사건·시간 진행** 단축 동작을 제안합니다. 각 동작은 기존 등록·편집·탐험·퀘스트 경로로 연결합니다.

## 6. 새 전략 룰북

개인보다 세력·거점·생산·부대를 중심으로 운영합니다. 개인 인물도 세계 안에 계속 존재하며 부대장·작업 담당자 등으로 연결합니다. GM 모드와는 독립적입니다. 영주 한 명으로 플레이하면서 전략 룰북을 사용할 수도 있습니다.

### 첫 구현 범위

| 항목 | 핵심 데이터와 동작 |
| --- | --- |
| 세력·거점 | 이름, 소속, 사용자가 정한 상태 |
| 공동 자원 | 곡물·목재·철 등의 수량과 단위, 예약·사용 가능량 |
| 건설·작업 | 비용, 필요한 작업량·시간, 담당자, 진행·중단·완료 |
| 임명·겸직 | 아군 NPC의 건물·지역·장소 담당, 직무 적성과 업무 분산 |
| NPC 태도 | 유저에 대한 충성·신뢰, 스트레스, 성격 태그와 카르마에 따른 변화 |
| 부대 | 소속 인물, 리더, 병력, 등급·숙련과 실제 손실 |
| 개인 성장 | 경험·훈련, 승급·진화·전직 조건과 변화 |
| 시간 | 명시적인 경과 시간과 예약된 완료 사건 |

외교·세금·전염병·무작위 침공·복잡한 식민지 AI 등 요청하지 않은 하위 시스템은 기본으로 붙이지 않습니다. 필요한 사건이 실제로 등장하면 기존 사건·자원·판정 기능으로 처리합니다.

### 건설과 시간

“제재소를 짓는다”는 요청은 완료가 아니라 작업 등록입니다. 예를 들어 목재 100, 작업 20시간이 필요하다면 비용을 예약·차감하고 남은 작업 시간을 저장합니다. UI에는 **진행 중 · 남은 작업 시간 · 담당자 · 중단 이유**를 보여 줍니다.

경과 시간 요청이 들어왔을 때 다음 완료 시점까지 계산합니다. 1분마다 AI나 도구를 호출하는 반복 방식은 사용하지 않습니다. 작업 중간에 인력이 이탈하거나 재료가 부족해지면 그 시점부터 멈추고 이유를 남깁니다. 완료 보상과 생산물은 작업 ID당 한 번 지급합니다.

일반 이동·휴식 등으로 실제 경과 시간이 저장된 경우도 같은 시계를 사용합니다. 이미 반영한 6시간을 메인 AI의 다음 시각 설명 때문에 다시 더하지 않습니다. 취소 시 반환 가능한 재료는 처음 저장한 작업 규칙에 따라 계산하고 무조건 전액을 복구하지 않습니다.

첫 버전은 고정 작업 시간과 작업자 조건부터 시작합니다. 인원수별 건설 속도, 생산 속도, 훈련량의 정확한 계수는 전략 룰북 수치 설계 단계에서 정해야 하며 현재 기존 룰북에 적용하지 않습니다.

### 큰 자원과 개인 소지품

목재 1,000과 철 200은 하나의 자원 계정에 저장합니다. 통나무 1,000개의 개별 아이템을 생성하지 않습니다. 단위가 kg인지 개수인지 품목 정의에 고정하고 입력·출력에 함께 표시합니다.

개인이 자원을 가져가거나 거점에 맡기는 행위는 계정 간 이동입니다. 개인 인벤토리와 공동 창고 양쪽에 같은 양을 복제하지 않습니다. 건설에 예약한 자원은 사용 가능량에서 제외합니다. 부족하면 어느 자원이 얼마 필요한지 반환합니다.

### 부대와 인물

한 아군 NPC가 건물·지역 책임자와 부대장 등을 겸직할 수 있습니다. 모든 임명을 같은 인물 ID에 연결하고 업무 분산·겸직 부담을 함께 계산합니다. 일반 병력 수나 개인의 실제 노동 시간은 복제하지 않습니다. 부재·이탈·행동 불가, 해당 업무에 실제 현장 참여가 필요한지도 반영합니다.

병사 모두에게 완전한 개인 시트를 만들 필요는 없습니다. 이름 있는 인물은 기존 인물, 일반 병력은 집계 수량으로 관리합니다. 대규모 전투도 모든 병사를 하나씩 도구 호출하지 않고 부대 단위 결과를 계산하는 방식을 제안합니다. 구체적인 전투 수식은 후속 수치 설계 대상입니다.

부대 훈련·실전에서 실제로 얻은 숙련을 기록하고 정해진 조건에 도달하면 승급 가능한 상태로 표시합니다. 리더의 개인 성장과 부대 전체 성장은 다른 값이며 자동으로 같은 경험치를 복제하지 않습니다.

개인 진화·전직·계급 상승은 이름, 요구 조건, 변화할 능력과 기술을 데이터로 저장합니다. 여러 진로가 있으면 선택하고, 확정된 자동 승급 규칙만 자동 적용합니다. 레벨 숫자만 오르면 AI가 매번 새 직업을 작성하는 방식은 피합니다.

### 건물·지역·장소에 NPC 임명

**현재 아군인 NPC만 임명할 수 있습니다.** 중립·적 NPC는 먼저 실제 관계 변경이 있어야 합니다. 임명 시뿐 아니라 업무 처리 시에도 아군 여부·활동 가능 여부를 확인합니다. 배신·이탈한 NPC의 효과를 계속 생산량에 더하지 않습니다.

건물뿐 아니라 지역·장소도 같은 임명 구조를 사용합니다. 임명 대상에는 담당 직무, 선호 능력치와 가중치, 관련 숙련·성격 태그, 정상 업무량, 현장 참여 필요 여부를 저장합니다. 인물은 기존 능력치·숙련을 사용하고, 직업 이름만으로 적성을 확정하지 않습니다.

| 임명 대상 예시 | 선호하는 능력의 예 | 과학자 NPC를 임명했을 때 |
| --- | --- | --- |
| 기사 훈련장 | 무예, 지휘, 훈련·교육 능력 | 연구 중심 인물이라면 훈련 효과가 낮음 |
| 아카데미 | 지식, 연구, 교육 능력 | 관련 능력이 높다면 연구·교육 효과가 높음 |
| 공장 | 관리, 기술, 작업 지휘 | 생산 기술·관리 능력에 맞는 만큼 효과 적용 |
| 지역·장소 | 그 지역에서 맡긴 직무의 선호 능력 | 경비·행정·연구 등 실제 임무에 따라 달라짐 |

표의 능력 이름은 역할 예시입니다. 아래의 기본 능력 6개와 전문 숙련을 조합하는 안을 제안하며, 최종 스탯 키와 계수는 아직 확정하지 않았습니다. 과학자라도 무예와 교육 능력이 뛰어나면 훈련장을 잘 운영할 수 있고, 직함만 과학자라고 아카데미 보너스를 무조건 받지는 않습니다.

계산 순서는 **직무 적성 → 업무에 쓸 수 있는 시간·집중도 → 충성에 따른 이행 → 스트레스에 따른 수행 저하 → 실제 자원·시설 한도**로 제안합니다. 신뢰를 생산 효율에 직접 곱하지 않습니다. 사람에 대한 신뢰가 높고 충성이 낮은 NPC가 일을 대충 하면서 유저를 감싸는 성격을 유지하기 위해서입니다.

적성은 시설에 저장된 기준 능력치에 대한 가중 합과 관련 숙련·태그 보정으로 계산합니다. 비교 기준은 다른 NPC의 현재 최고 수치가 아니라 해당 직무의 저장 기준을 사용합니다. 새 유능한 인물이 등장했다고 기존 담당자의 적성이 자동으로 낮아지지는 않습니다. 임명 전에는 예상 효과와 어떤 능력이 반영되는지 보여 줍니다.

### NPC 능력치 제안

**아직 논의 중인 안: 기본 능력 6개 + 실제로 배운 전문 숙련 + 성격 태그.** 충성·신뢰·스트레스·카르마는 별도의 상태와 관계 값으로 둡니다.

| 기본 능력 | 주로 사용하는 일 |
| --- | --- |
| 무력 | 개인 전투, 무예 시범, 기사·병사 훈련의 실기 |
| 통솔 | 부대 지휘, 훈련 조직, 여러 사람의 협업 지휘 |
| 지력 | 연구, 학습, 분석, 전술·문제 해결 |
| 정무 | 시설·지역 운영, 생산 계획, 자원 배분과 행정 |
| 매력 | 설득, 교섭, 인재 포섭, 면담·교육의 전달력 |
| 인내 | 업무 부담과 압박을 견디는 능력, 과로 위험의 보정 |

기본 능력은 **0~100 정수 척도**를 제안합니다. 예를 들어 20은 미숙, 40은 보통, 60은 숙련, 80은 전문가, 95는 매우 뛰어난 수준입니다. 이는 초기 수치 기준안이며, 초인적 성장·진화가 있는 세계관의 상한은 별도로 정할 수 있습니다. 기존 다른 룰북의 수치를 이 척도로 덮어쓰지는 않습니다.

전문 숙련은 검술·군사교육·연구 분야·건축·생산 기술·의술·교섭처럼 해당 인물에게 필요한 것만 등록합니다. 기본 능력이 잠재력과 일반 역량이라면 전문 숙련은 실제 배운 분야입니다. 연구자에게 지력이 높다는 이유로 의술과 모든 생산 기술까지 자동으로 부여하지 않습니다.

| 직무 | 우선 반영할 기본 능력 | 관련 전문 숙련 |
| --- | --- | --- |
| 기사 훈련장 | 통솔·무력 | 군사교육, 해당 무기술 |
| 아카데미 연구 | 지력 | 해당 연구 분야 |
| 아카데미 교육 | 지력·매력 | 해당 학문, 교육 |
| 공장 운영 | 정무·통솔 | 생산 기술, 해당 공정 |
| 지역 행정 | 정무·매력 | 행정, 교섭 |

시설의 직무별로 능력 가중치와 필요한 숙련을 저장합니다. 동일한 아카데미에서도 연구 책임자와 교육 담당자는 다른 적성을 사용할 수 있습니다. 능력 가중 합과 전문 숙련 보정으로 기본 적성을 계산한 뒤 기존의 겸직·업무 이행·스트레스 보정을 적용합니다. 최종 가중치와 효율 곡선은 후속 밸런스 대상입니다.

인내가 높아도 충성이 낮으면 일을 거부할 수 있습니다. 충성이 높아 명령을 계속 따르더라도 인내가 낮으면 먼저 과로할 수 있습니다. 인내·충성·신뢰 어느 것도 과로 면역을 주지 않습니다. 매력 또한 상대의 충성·신뢰를 직접 덮어쓰지 않고 실제 면담·교섭의 성과에만 보정합니다.

능력치는 초기 등록 때 로어북·명시된 설정을 우선해 한 번 작성하고, 전문 숙련은 실제 경험과 훈련으로 성장시킵니다. 기본 능력 성장은 장기 훈련·승급·진화처럼 정한 조건에서 처리하는 방안을 제안합니다. 건물 담당자로 임명했다고 관련 없는 능력까지 매번 상승시키지 않습니다. 과로의 일시적 수행 저하는 원래 능력치를 깎아 저장하지 않고 상태 보정으로 둡니다.

### 전쟁 중 NPC의 부상과 사망

전략 룰북의 실행 코드는 아직 없으며, 기존 택티컬·지르코트의 부상·사망 처리와 별도로 연결할 설계입니다. 기본 능력 6개만으로 생사를 표현하지 않고 **생명력, 부상, 행동 가능 상태, 사망 여부**를 따로 저장하는 안을 제안합니다. 최대 생명력의 성장식·부상 문턱·전사 판정 수치는 후속 결정 대상입니다.

| 상태 | 전략 플레이에 미치는 영향 |
| --- | --- |
| 경상 | 부상 내용에 맞는 전투·업무 수행 저하, 치료·휴식으로 회복 |
| 중상 | 출전 또는 관련 현장 업무 제한, 치료와 회복 시간 필요 |
| 전투불능·위독 | 전투·업무 중지, 구조·치료가 필요하며 상태 악화 시 사망 가능 |
| 사망 | 행동·임명 효과·지휘 효과 종료, 기록은 보존 |

전투불능과 사망은 구분합니다. 생명력이 소진되면 우선 전투불능으로 처리하는 안을 기본으로 검토하되, 명시된 치명상이나 구조·치료 실패로 사망할 수 있게 합니다. 전쟁에서 승리했다고 모든 NPC가 생존하는 것은 아니며, 패배했다고 모든 지휘관을 자동으로 죽이지도 않습니다. 실제 출전, 전방 노출, 전투 결과, 부상과 치료 상황에 따라 이름 있는 NPC의 결과를 계산합니다.

일반 병력은 부대의 생존·부상·사망 인원으로 집계하고, 이름 있는 인물은 개별 기록을 유지합니다. 같은 지휘관을 부대 손실 인원과 별개의 추가 병사로 이중 차감하지 않습니다. 세부 부위가 필요한 부상은 기존 신체 기능의 구조를 활용할 수 있지만, 전략 전투 전체를 병사별 상세 공격 호출로 확장하지 않습니다.

부상에 따른 수행 저하는 원래 능력치를 영구적으로 깎는 것과 구분합니다. 예를 들어 다리 부상으로 현장 이동은 제한되어도 가능한 연구·행정 업무가 있을 수 있습니다. 중상·전투불능에서는 필요한 치료가 우선이며, 인내가 높거나 충성이 높다는 이유로 부상·사망을 무효화하지 않습니다.

치료·구조·회복에는 해당 세계관의 의료 기술·물품·시간을 적용합니다. 전투가 끝났다는 이유만으로 부상·출혈·전투불능을 초기화하지 않습니다. 회복하면 임명·지휘 효과를 현재 상태에 맞춰 다시 계산합니다. 과로로 쓰러졌을 때의 충성·신뢰 패널티와 전쟁 중 부상은 별개 사건이며, 전쟁 부상만으로 동일한 관계 패널티를 자동 부여하지 않습니다.

전사 시 인물 데이터를 삭제하지 않고 사망 시점·원인과 이전 임명·소속 기록을 남깁니다. 생산·지휘 효과는 그 시점부터 중지하고 임명 후보에서 제외합니다. 세계관에 부활 규칙이 있다면 명시된 사건과 비용으로 복귀할 수 있지만 일반 치료나 새 인물 등록으로 조용히 되살리지 않습니다. 부상·치료·사망·부활도 사건당 한 번 반영하며 롤백 시 함께 복원합니다.

### 겸직은 허용하고 부담을 계산

**같은 NPC를 여러 건물·지역·장소에 중복 임명할 수 있습니다.** 이전 설계의 일괄 중복 배치 금지는 적용하지 않습니다. 임명 기록은 여러 개지만 NPC의 능력·충성·신뢰·스트레스는 하나를 공유합니다.

겸직 패널티는 각 직무에 쓸 시간·집중도 감소와 조정 업무로 인한 스트레스 증가입니다. 정상 업무량의 직책 두 개를 맡기면 한 개보다 부담이 크게 늘어납니다. 같은 직무의 중복 입력으로 동일 효과가 두 번 생기는 것은 별도로 막습니다.

배분 예시로, 전담 때 효과가 100인 인물을 동등한 두 직무에 임명하면 각 직무에 50씩 배분하고 여기에 겸직 조정 손실을 적용할 수 있습니다. 이는 계산 방향을 설명하는 예시이며 고정된 최종 밸런스 값은 아닙니다. 직무별 정상 업무량과 지역 이동 부담이 다르면 그에 따라 나눕니다.

공장에 **150% 가동을 요구**하면 요구 강도와 스트레스가 올라갑니다. 자원·시설·담당자의 실제 능력이 받쳐 주지 않으면 생산량이 150%가 되지는 않습니다. 겸직 상태의 과잉 가동이나 반복 출전은 함께 부하에 반영합니다. 효율 요구를 변경할 때 예상 생산·스트레스 변화도 보여 줍니다.

### 충성과 신뢰

두 값은 모두 **유저에 대한 해당 NPC의 태도**이며, 중립값 0을 기준으로 **−100~+100**입니다. 전체 세력의 평판이나 NPC 사이 호감도와 합치지 않습니다.

- **충성:** 유저의 명령을 우선 실행하려는 정도와 업무 이행 태도. 높으면 명령을 따르려 하고, 낮으면 태만·불이행·거부가 나타날 수 있습니다.
- **신뢰:** 유저에게 무언가를 맡길 수 있는지, 잘못을 보아도 믿거나 옹호하고 곁에 남을지에 대한 태도. 높아도 업무 성실성을 대신하지 않습니다.

| 충성 | 신뢰 | 사용자가 의도한 NPC의 태도 |
| --- | --- | --- |
| 낮음 | 높음 | 일은 제대로 하지 않으면서 유저를 감싸고 옹호함 |
| 낮음 | 낮음 | 명령을 잘 따르지 않고 유저를 의심함. 배신 기회를 보거나 떠날 수 있음 |
| 높음 | 높음 | 유저를 믿고 명령을 우선함. 목숨을 건 명령까지 따르려는 헌신이 가능 |
| 높음 | 낮음 | 맡은 일은 수행하지만 개인적 신뢰 때문은 아님. 유저를 감시하고 약점을 찾으며 명분에 따라 모략·배신할 수 있음 |

충성이 높다는 것은 명령을 **실행하려 한다**는 뜻이며, 불가능한 명령을 성공시키거나 시설 한도를 무시한다는 뜻은 아닙니다. 신뢰가 낮은 고충성 NPC는 현재의 직무·명령에는 충실하면서도 유저 개인에게는 적대적인 의도를 품을 수 있습니다. 대사와 실제 행동에 이 차이를 전달합니다.

낮은 충성은 업무 효율 저하·불이행과 연결하고, 사고·횡령은 성격·스트레스·업무 기회 등 관련 조건까지 함께 사용합니다. 충성이 낮다는 한 가지 이유만으로 모두가 횡령하거나 즉시 배신하도록 정하지 않습니다. 배신·이탈은 가능한 결과이며 수치만으로 이미 발생한 사건처럼 기록하지 않습니다.

### 스트레스

스트레스는 인물별 한 값으로 저장합니다. **0~100을 초안 범위로 제안**하며 확정 수치는 후속 밸런스 단계에서 조정합니다. 정상적인 단일 임명은 부담이 작고 일반적인 휴식으로 균형을 유지할 수 있게 합니다.

주요 증가 원인은 정상치를 넘는 가동 요구, 여러 직무·지역 겸직, 연속 출전, 회복 없는 장기 업무입니다. 실제 이야기 속 업무 시간과 완료된 전투·사건을 기준으로 누적합니다. 도구 호출 횟수·조회·화면 열기·현실 API 대기 시간은 스트레스를 올리지 않습니다.

높은 충성은 의무와 명령 때문에, 높은 신뢰는 유저를 믿기 때문에 버티는 데 영향을 줍니다. 두 값은 스트레스 누적 자체를 지우지 않습니다. **참는 정도와 쌓인 부담을 분리**하여, 묵묵히 버티는 NPC도 계속 혹사하면 수행 저하나 사고 위험이 남도록 합니다.

충성·신뢰가 낮은 상태에서는 같은 스트레스라도 반발·거부가 쉽게 나타날 수 있습니다. 화를 표현하는 방식은 성격 태그와 메인 AI가 담당합니다. 휴식·업무 강도 완화·겸직 해제는 이후 스트레스 회복에 영향을 주되, 임명을 해제했다는 이유만으로 누적값을 즉시 0으로 만들지 않습니다.

### 과로와 쓰러짐

사용자 추가 요구에 따라 높은 스트레스는 **과로 등의 실제 패널티**로 이어집니다. 단계별로 집중력·업무 효율 저하, 실수·사고 위험 증가, 심한 과로에 따른 행동 제한을 두고 한계를 넘겨 계속 일하면 쓰러질 수 있게 합니다. 단계 문턱·노출 시간·발생 확률은 아직 미정입니다.

쓰러짐은 단순 경고가 아니라 회복이 필요한 상태입니다. 해당 인물의 업무·출전을 중지하고 담당 시설과 부대의 실제 효과를 갱신합니다. 임명 기록 자체는 남겨 회복 후 다시 이어갈 수 있게 합니다. 충성이나 신뢰가 아무리 높아도 쓰러진 상태에서 업무를 계속 처리하지 않습니다.

**과로로 쓰러지는 사건이 발생하면 충성과 신뢰가 모두 감소합니다.** 기본 하락량에 과로의 심각도, 경고를 무시한 지시, 반복 발생, 성격 등을 반영하는 방식으로 설계합니다. 높은 기존 수치를 이유로 이 패널티를 없애지 않습니다. 동일한 쓰러짐 사건에는 한 번만 적용하고, 쓰러진 채로 상태를 조회할 때마다 다시 감소시키지 않습니다.

과로·쓰러짐은 관련 업무 시간과 실제 사건을 처리하는 중에 판정합니다. 긴 기간을 한 번에 진행할 때 중간에 쓰러졌다면 그 이후 시간에는 정상 생산·전투 효과를 계속 더하지 않습니다. 쓰러짐으로 인한 상태와 관계 변화는 같은 기록으로 저장하고 롤백에도 함께 포함합니다.

### 유저의 개입과 회복

| 회복 방법 | 스트레스와 업무에 미치는 영향 |

| 유저가 직접 만나 면담·위로 | 실제 만남의 내용과 NPC의 성격·관계에 따라 스트레스 감소 |
| 휴식 지시 | 쉬는 시간 동안 업무 부담을 중단하고 경과 시간에 따라 회복 |

대사를 만드는 것은 메인 AI, 실제 스트레스 감소와 업무 중지는 도구가 처리합니다. 만나겠다는 계획만으로 회복시키지 않고 실제 면담이 이뤄진 사건에 반영합니다. 같은 대화를 여러 번 전달해도 회복은 한 번이며, 동일한 위로만 반복해 즉시 모든 과로를 없애는 식의 누적 회복은 제한하는 방안을 제안합니다.

면담은 스트레스를 줄일 수 있지만 쓰러진 몸의 회복 시간을 대신하지 않습니다. 과로·쓰러짐 상태는 필요한 휴식과 회복 조건을 충족한 뒤 해제합니다. 휴가 중에도 임명과 성장 데이터는 보존하며, 복귀하면 현재 적성·겸직·잔여 스트레스로 효과를 다시 계산합니다.

회복과 관계 회복은 별개입니다. 쉬어서 스트레스가 내려갔다고 쓰러질 때 감소한 충성·신뢰를 자동으로 되돌리지 않습니다. 유저가 실제로 돌보고 약속을 지키거나 업무 환경을 개선한 경우, 그 사건을 성격·관계 규칙에 따라 별도로 평가할 수 있습니다.

### 성격 태그와 카르마에 따른 변화

각 NPC에 성격 태그와 카르마를 저장하고 유저의 실제 판단·행동을 이 기준과 비교합니다. 유저의 카르마와 NPC 자신의 카르마는 구분합니다. 태그 예시는 원칙적·실리적·잔혹함·온정적·야심가·의리 중시·권위 복종·자율 중시 등이며 봇의 설정과 사용자 편집을 우선합니다.

| 유저의 행동 예 | 반응 차이 |
| --- | --- |
| 포로를 풀어 줌 | 온정적 NPC는 지지할 수 있고, 잔혹하거나 손익을 중시하는 NPC는 불만을 가질 수 있음 |
| 부하를 보호하려 손해를 감수 | 의리·신뢰를 중시하는 NPC에게 긍정적. 손실 규모를 문제 삼는 성격에는 다른 반응 가능 |
| 약속한 보상을 지급하지 않음 | 신뢰 하락의 근거. 높은 충성 때문에 계속 일하는 것과 신뢰 회복은 별개 |
| 무리한 증산을 지시 | 권위에 복종하는 NPC는 수행하면서 스트레스가 오를 수 있고, 자율을 중시하는 NPC는 충성도 하락·거부로 이어질 수 있음 |

이 예시는 사건별 방향을 설명하며 아직 고정된 증감표는 아닙니다. 카르마가 비슷하다는 이유만으로 매번 충성과 신뢰가 동시에 오르지 않습니다. 행동의 내용, 그 NPC에게 미친 영향, 성격 태그에 맞춰 두 값을 따로 변경합니다.

같은 사건의 재호출·놓치지마 보완·상태 조회로 반복 증감하지 않습니다. 단순한 유저의 의문·계획과 실제 결정·실행을 구분합니다. 성격·의도가 모호하면 해석이 필요한 부분만 기존 AI 흐름에서 정리하고, 확정한 사건 분류와 증감 근거를 저장해 같은 판단을 다시 호출하지 않습니다.

### 시스템 처리와 서술의 연결

도구는 임명 효과·업무 이행·생산 손실·자원 증감·충성·신뢰·스트레스의 실제 변화를 계산합니다. 메인 AI에는 관련 인물의 태도와 이번 변화 이유를 짧게 전달합니다. 불평, 옹호, 감시, 갈등의 대사는 메인 AI가 맡습니다.

횡령·사고·이탈·배신이 실제 사건으로 확정되면 그 결과를 같은 저장 작업에서 반영합니다. 횡령은 존재하는 접근 가능한 자원 범위에서 차감하고, 이탈·배신은 아군 상태와 담당 업무·부대 지휘 효과를 함께 갱신합니다. 위험이 높다는 반환값만으로 자원을 미리 없애거나 미래 사건을 확정하지 않습니다.

저장에는 임명 대상과 인물 ID, 업무 강도·배분, 직무 적성 근거, NPC별 충성·신뢰·스트레스·태그·카르마, 생명력·부상·사망 및 치료 기록, 과로·쓰러짐 상태와 사건 ID, 휴식·휴가 기간, 마지막으로 반영한 사건·시간을 포함합니다. 수치가 바뀌거나 임명이 추가·해제될 때만 관련 효과를 다시 계산하고 매 NPC·매 턴마다 별도 AI를 호출하지 않습니다.

### 공통 UI 위치

다른 룰북과 같이 현재 상태 → 능력·기술 → 장비·소지품 → 탐험 → 퀘스트 → 등록 인물의 공통 순서와 명칭을 유지합니다. 전략의 세력 자원·작업·부대는 현재 상태에서 펼쳐 보는 관리 영역으로 제안합니다. 관련 있는 내용만 노출하고 새 메뉴와 같은 정보를 중복 표시하지 않습니다.

건물·지역 행에서 **담당 NPC → 임명·교체·해임**을 엽니다. 목록에는 아군 NPC만 보이고 직무 적성, 현재 겸직 수, 예상 효과·부담을 비교할 수 있습니다. NPC 상태에는 `충성 +60 · 신뢰 −20 · 스트레스 48 · 겸직 2곳`처럼 핵심 값을 한 줄로 표시하고, 펼치면 담당 목록·성격·카르마와 변화 이유를 봅니다. 임명과 관계를 위해 별도 중복 카테고리를 만들지 않습니다.

과로·쓰러짐·휴가 중인 경우 같은 NPC 행에 상태와 남은 회복 기간을 표시하고 **직접 만나기·휴식·휴가** 동작을 연결합니다. 직접 만나기는 메인 AI의 실제 만남으로 이어지는 요청이며 버튼을 누른 즉시 면담을 완료한 것으로 계산하지 않습니다. 기본 능력과 전문 숙련은 기존 인물 상세 영역에서 확인·편집합니다.

## 7. 저장·도구·복구의 공통 계약

새 시스템은 기존 MCP 도구의 인수·내부 동작을 확장하는 방향으로 설계합니다. 기능마다 새 도구와 별도 사전 호출을 만들 필요가 있는지는 실제 구현 때 판단합니다. 모델은 필요한 순간의 실제 행동을 요청하고, 코드는 연결된 비용·시간·성장·종료 처리를 같은 저장 작업 안에서 계산합니다.

각 변경에는 원본 사건 ID, 적용 대상, 실제 비용·증감, 완료 상태를 남깁니다. 조회로 시간이 흐르거나 같은 결과 재전송으로 보상을 또 받지 않습니다. 놓치지마 검사는 저장 영수증을 기준으로 누락만 보완하고 이미 계산한 공격을 재연하지 않습니다.

롤백에는 소환의 활성 상태·남은 시간·성장, 공유 자원·연결, 관전자 보상, 전략 자원 예약·작업 진행·임명·충성·신뢰·스트레스·카르마 변화·과로·쓰러짐·휴가를 모두 포함합니다. 이탈·배신에 따른 진영 변경도 함께 복원합니다. 리롤로 다른 분기를 만들면 이전 답변에서 생성한 결과를 그대로 이어받지 않고 해당 시점에서 새로 계산합니다.

기존 세이브에는 새 기능이 없는 상태로 호환합니다. 기존 소환 설정을 읽는 변환은 원래 의미만 보존합니다. 토글 OFF는 신규 자동 처리를 중지하는 선택이며 이미 지급한 보상을 회수하거나 인물 데이터를 삭제하는 기능이 아닙니다.

## 8. 권장 구현 순서와 나중에 확인할 사례

1. 기존 소환 경로를 정리하고 등록·해제·유지 시간·비전투 사용을 연결합니다.
2. 인물 연결을 공통 효과·비용·자원 경계에 넣고 소환수 성장과 함께 연결합니다.
3. 성좌·스트리밍의 설정과 사건 출처, GM 조작·진행 구분을 추가합니다.
4. 전략 룰북의 자원·작업·시간과 아군 임명·겸직을 만든 뒤 충성·신뢰·스트레스·성격 반응, 부대·개인 성장·전투 수치를 연결합니다.

후속 구현에서 확인할 사례입니다. 이번 작업에서 실행한 시험 목록은 아닙니다.

- 같은 사역마 재소환 시 성장·부상 유지, 여러 마리 소환 시 개별 수명과 HP 분리.
- 자동 전투·행동 게이지·결과만 진행에서 만료 처리 일치, 상태 조회·API 대기로는 시간 감소 없음.
- 파티 경험치와 소환수 공유를 동시에 켜도 처치 지급 중복 없음.
- 공유 HP의 피격·회복·0 도달, MP 대납 실패, A↔B 능력 연동에 재귀 증가 없음.
- 성좌·시청자의 같은 보상을 재요청해도 한 번만 반영, 반응만 있는 서술에는 추가 호출 없음.
- 건설 중단·취소·시간 건너뛰기·담당자 이탈과 완료 지급, 자원 예약과 개인 인벤토리 중복 없음.
- 아군만 임명 가능, 과학자의 훈련장·아카데미 적성 차이, 겸직 허용과 실제 집중도·시간 분산.
- 단일 임명·150% 증산 요구·겸직·연속 출전에 따른 부담 차이와 휴식 후 회복, 호출 횟수에 따른 중복 누적 없음.
- 과로로 쓰러진 시점 이후 업무 중지, 충성·신뢰의 사건당 한 번 하락, 면담·휴식·휴가의 실제 회복과 복귀.
- 승리한 전쟁에서도 NPC 부상·전사 가능, 전투불능과 사망 구분, 구조·치료·전사에 따른 실제 업무·지휘 효과 중지와 복원.
- 높은 인내와 낮은 충성, 높은 충성과 낮은 인내의 차이, 지력이 같아도 전문 숙련에 따른 직무 적성 차이.
- 충성·신뢰 네 조합의 태도 차이, 성격·카르마에 따른 사건별 증감과 실제 이탈 후 임명 효과 중지.
- 저장 재열기·백업 복원·리롤·분기 변경에서 관련 상태가 함께 복원됨.

각 단계의 화면과 수치 결정을 구현 전에 구체화하되, 기능 하나를 쓰기 위한 호출 수와 메뉴 수가 불필요하게 늘지 않는 것을 우선합니다.
