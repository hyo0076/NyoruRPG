# NyoruRPG 0.23.2

지역과 저장 상태가 실제로 바뀌었을 때 필요한 호출을 구체적으로 안내하고, MCP가 서술 분량과 묘사 방식을 지시하던 문구를 정리합니다. 연결 모듈 v1 사용자는 플러그인만 업데이트합니다.

## 호출과 서술

- 새 공격·기술·판정과 실제 저장 상태 변경은 해당 동작으로 처리합니다. 기술을 알고 있거나 쉬운 행동이라는 이유로 실행을 생략하지 않습니다.
- 결과의 `steps`에 포함된 공격·자동 반격·연계는 그 발생 건의 실행 기록입니다. 같은 기술이나 대상을 사용한 다음 행동까지 처리됐다는 뜻은 아닙니다.
- 결과 조회에 있던 “서술만 이어가세요”를 제거했습니다. 이후 새 행동은 새 `actionId`로 호출하고, 동일 호출의 전송 재시도는 기존 ID로 처리합니다.
- 문체·전체 분량·반복 공방 묘사 압축 지시는 제거했습니다. 전투가 길어는 기존 계산·횟수 상한을 유지하고 실제 결과를 반환합니다. 지휘관·행동 모드의 사용자 선택 대기는 계속 적용합니다.

## 탐험과 위치

공통 d100·헌터·무림·에렌샤에서 실제 필드·숲·사냥터·던전·유적·채집 구역 입장은 `rpg_play explore start`, 저장된 구역 이동은 `move`, 단서 조사는 `investigate`, 조작·채집은 `interact`, 퇴장은 `end`입니다. 다른 탐험 지역에 들어가면 기존 장소 종료 결과를 읽고 새 장소를 시작합니다. 새 지역의 이름 언급이나 계획만으로 입장을 실행하지 않습니다.

탐험이 없을 때 `exploration`은 계속 `null`이며, 상태의 `explorationEntry`가 실제 입장 시 사용할 경로를 안내합니다. 이 안내 자체는 장소 생성·전투·API 호출을 실행하지 않습니다. 기존 지도·발견·보상·채집 수량을 초기화하지 않습니다.

에렌샤 탐험의 실제 입장·이동은 게임 위치도 함께 기록합니다. 일반 도시·상점·주거지 방문과 날짜·시간·현실/게임 전환은 다음처럼 알려진 변경 필드만 직접 전달할 수 있습니다.

```json
{
  "op": "record",
  "actionId": "visit-shop-1",
  "eventId": "visit-shop-1",
  "actor": "루미",
  "action": "잡화점 도착",
  "eventType": "clock",
  "location": "루미나 잡화점"
}
```

`date`, `time`, `realm`(`game`/`real`), `days`도 알려진 변화만 선택적으로 보냅니다. 날짜를 모른다고 `NA`를 보내거나 메시지 수로 경과 일수를 추정하지 않습니다. 탐험 결과가 이미 기록한 위치는 다시 기록하지 않습니다. 기존 자연어 `record`도 사용할 수 있습니다. 인물과 전달 필드가 준비돼 있는 이 직접 기록은 별도 사건 해석 AI 요청을 만들지 않습니다.

놓치지마 검사는 같은 구분으로 직전 답변을 확인합니다. 현재 입력의 미래 행동을 실행하거나 과거 전투·탐험을 재연하지 않으며, 이미 처리한 결과는 유지합니다.

## 확인 범위

사용자가 제공한 최신 스크린샷에는 바람결 숲 외곽의 활성 탐험, 현재 구역, 출구와 채집 수량이 표시됐습니다. 탐험 시작·표시 경로 전체가 막혔다고 볼 수는 없습니다. 이 화면만으로 후속 이동·조사·채집 호출이나 최신 모델의 호출 생략 원인을 확정하지 않았습니다.

소스에서 확인한 것은 모호한 호출 예외, 반복된 서술 지시, 조회 후 “서술만” 안내, 탐험 위치와 에렌샤 시간/장소 기록의 분리입니다. 이번 수정·배포 생성과 실제 모델의 준수 여부는 별개입니다. 별도 최종 검사, 가상 전투·모의 호스트, 실제 RisuAI·모바일·유료 API 호출은 하지 않았습니다.

게이지 기준 100, 전투 계산과 자동 NPC 행동, 도구 식별자, 카드 배치·호스트 완료 연결은 유지합니다. 진단의 `moduleGuidanceSelected`는 지침 삽입 여부와 구형 모듈 유지 여부를 보여 주며, 모델이 실제로 그 지침을 따랐다는 증거는 아닙니다.
