# NyoruRPG 0.30.12 · 별도 최적화 버전

0.30.11에서 수정한 기능을 바탕으로 창 열기, 누적 기록 읽기, 배포 파일 크기를 줄이는 버전입니다. 작업 브랜치는 `codex/optimization-0.30.12`입니다. 변경 전 소스는 로컬 기준 커밋 `158dd64`, 기존 배포는 `release/NyoruRPG v0.30.11`에 보존합니다. GitHub 배포는 보류합니다.

**플러그인만 업데이트. 모듈 v1은 그대로**.

## 해적리스 미니창 표시 보완

- 해적리스 자체 채팅 탭과 미니창의 접힌 돌출부가 겹칠 수 있는 배치를 고쳤습니다. 탭 아래, 채팅 스크롤 바로 위에서 펼쳐지며 채팅 가장자리 장식에 가려지지 않도록 했습니다.
- 첫 상태 읽기나 화면 표시가 잠시 실패한 뒤 미니창 표시가 멈추는 경로를 보완했습니다. 실패한 준비만 간격을 두고 다시 읽으며 RPG 전체 창을 닫을 때도 표시를 다시 시도합니다.
- 접힌 높이 0, 패널과 이어진 돌출부, 펼칠 때 채팅 공간 확보 방식은 유지합니다. 삼선 메뉴 미니 항목은 다시 추가하지 않습니다.

해적리스 b7612 공개 소스와 플러그인 소스를 바탕으로 수정했습니다. 로컬 배포 생성까지 진행했으며 설치된 해적리스에서의 표시 복구는 아직 확인하지 않았습니다. GitHub 업로드는 보류합니다.

## 개인 HTTP 중계기 · 실험

해적리스 등 IPC 연결이 제한된 환경을 위한 **AI 연결 → 개인 HTTP 중계기**를 추가했습니다. 사용자가 실행하는 별도 Node 프로그램으로 연결하며 Provider Manager 파일·allowed-ipc 헤더를 수정하지 않습니다. 공용 서버를 운영하지 않아도 되고, HTML이나 다른 도구도 같은 클라이언트 규격에 어댑터를 연결해 사용할 수 있습니다.

별도 중계기는 0.1.0 실험판, RPG는 0.30.12를 유지합니다. 기본 주소는 `http://127.0.0.1:18765`입니다. 기존 개인 Risu 서버와 폴더·포트·키 파일을 분리하며 이미 사용 중인 포트라면 중계기만 시작하지 않습니다. 브라우저 HTML만으로 서버가 생기는 것은 아니며 Node.js 20 이상이 필요합니다.

[배포 묶음](../dist/Nyoru-Personal-MCP-Relay-0.1.0.zip)에는 중계기·HTML 예제·수정 RPG 플러그인·안내가 들어갑니다. [사용법](../personal-relay/README.md)을 따라 Publisher key는 RPG에, Consumer key는 PM의 Bearer에 설정합니다. 이번 중계기 작업은 소스 작성·배포 생성만 수행했으며 해적리스·포켓리스·모바일 등 실환경 연결, 별도 자동 검사·유료 API 실행은 하지 않았습니다. GitHub 보류를 유지합니다.

## 놓치지마 검사 연결 안내

- 기본 API 공유 시 실제 사용할 모델·전송 방식과 인증 누락을 표시합니다. 공유 상태에서도 같은 연결로 확인할 수 있습니다. 여기서 기본 API는 이 플러그인에 설정한 API입니다.
- 검사 자료 읽기, API 설정·인증, 요청 전송, HTTP 응답, 결과 해석 오류를 구분해서 화면과 검사 로그에 남깁니다. API에 요청하기 전의 오류도 구체적인 이유를 보관합니다.
- 같은 답변의 예전 검사 실패를 다시 표시할 때 새 API 호출이 없었다는 사실을 표시합니다. 자동 재호출로 비용을 추가하지 않습니다.

이번 제보는 정확한 오류 로그가 없어 연결 장애의 원인과 실사용 복구 여부를 확정하지 않았습니다. 소스 수정과 로컬 배포 생성만 진행하며 실제 Risu·유료 API·추가 테스트는 실행하지 않습니다. 플러그인만 업데이트. 모듈 v1은 그대로입니다.

## 초기 구축·JEV·모바일 창 수정

- 구축이 끝나거나 실패했는데 `요청 전 · 0회`가 남아 다음으로 진행할 수 없는 표시 오류를 수정했습니다. 업데이트 후 새로 고침하면 최신 저장 초안과 적용 또는 오류 안내를 표시합니다. 기존 초안을 먼저 지울 필요는 없습니다.
- JEV OFF일 때 초기 자료 찾기·확인 문구·선별·자동 호출·새 준비 로그를 생략합니다. OFF는 즉시 반영하고 이미 기다리던 JEV는 중단한 뒤 기존 구축으로 이어갑니다. OFF에서 연결 확인 API도 호출하지 않습니다. 이전 기록은 남겨 둡니다.
- 브라우저의 뒤로가기에 RPG 전체 창 닫기를 연결했습니다. 닫았다 다시 열거나 여러 번 열어도 창 하나의 뒤로가기 단계만 사용합니다. 실제 휴대폰의 시스템 뒤로가기는 아직 실기기 확인 전입니다.
- 삼선 메뉴의 미니 창 항목을 제거했습니다. 채팅 상단에서 펼치는 미니 UI는 유지합니다.

이번에 승인한 구축·JEV·창 경계의 자동 테스트 10개가 통과했습니다. 화면과 외부 요청을 로컬에서 확인한 결과이며 실제 Risu·유료 API·휴대폰 실행 결과는 아닙니다.

장착 행동의 편집 버튼 명칭을 모든 룰북에서 `기본 행동 설정`으로 통일했습니다. 이미 행동이 있는 장비에는 `행동 추가·기본 행동 설정`으로 표시합니다.

## 장비 기본 위력 편집

얼터네이티브 헌터·무림·공통 d100에서 **장비 → 편집 → 기본 정보 → 기본 위력**으로 무기·방어구·장신구의 수치를 직접 수정합니다. 장비 카드와 미니 UI에도 표시합니다. 기본 위력은 강화 전 수치로, 장착 중 기본 공격과 공격 기술의 위력에 더해집니다. 기존 위력 효과와 같은 값이므로 두 번 더하지 않으며 조건·지정 기술·배율 등 다른 효과는 보존합니다. 뉴뉴의 장비 위력 수정 제안도 같은 경로를 사용합니다.

에렌샤·택티컬·지르코트에서도 장비 편집을 열면 **기본 정보**가 먼저 나와 기존 위력 수치를 바로 찾을 수 있습니다. 각 룰북의 피해·방호 계산 방식은 유지합니다. 장착 행동의 전체 수식과 시전·연타 설정은 기존 **기본 행동 설정**에서 편집합니다.

## 플레이 설정 저장 실패

플레이 설정을 저장하다 오류가 나도 방금 선택한 토글과 입력한 값을 유지합니다. 저장 중에는 추가 저장을 막으며, 재저장에 성공하면 이전 실패 안내를 지웁니다. 다른 곳에서 설정이 바뀌었다면 덮어쓰지 않고 기존 충돌 검사를 유지합니다. 입력을 버리려면 **저장된 설정으로 되돌리기**로 현재 값을 다시 읽을 수 있습니다.

요청받은 TDD 범위에서 8개 룰북의 저장 실패/재시도와 중복 제출·충돌·채팅 분리를 포함한 12개 DOM 테스트가 통과했습니다. 설치 Risu나 실제 플레이 검증은 아닙니다. 다른 UI 문제의 우선순위는 [전체 UI 소스 검토](ui-audit-0.30.12.md)에 정리했습니다.

## 구축이 끝난 뒤에는 요청할 때만

이미 구축된 채팅은 RPG 창, 미니 UI, 새로 고침으로 초기 구축 원문·로어북 목록·구축 초안을 불러오지 않습니다. 시스템 구축에 들어가도 먼저 `구축·카드 설정 열기` 버튼이 나옵니다. 그 버튼을 누른 편집 세션에서만 필요한 자료를 읽습니다. 창을 닫거나 일반 플레이 화면으로 돌아가면 큰 자료의 참조를 놓습니다.

아직 구축되지 않은 채팅의 시작 준비와, 사용자가 시작한 구축 작업은 계속 지원합니다. 설정 편집은 유지하며 실제 플레이 중 신규 인물·물품을 준비하는 원문 검색, 뉴뉴의 요청에 따른 검색까지 끈 것은 아닙니다. 모듈 활성 여부와 현재 저장 상태의 확인도 유지합니다.

## 화면에 필요한 만큼만

- 8개 룰북의 전체 창 장비·소지품 카드는 12개씩 표시하고 이름·설명 검색은 해당 인물의 전체 보유품에 적용합니다. 검색 결과를 편집하고 취소하면 같은 결과로 돌아옵니다.
- 위력·방어·수량과 편집 버튼은 바로 보입니다. 강화·파츠·기본 행동 관리 내용은 해당 물품을 펼칠 때 준비합니다. 지르코트 창고와 보관 후보도 12개씩 표시합니다.
- 플레이 설정은 짧은 설명을 먼저 보여주고 긴 규칙은 `자세히`에서 읽습니다. 설명을 접어도 토글 선택은 바뀌지 않으며 저장 실패 후 입력 유지도 지원합니다.
- 현재 상태의 체력·마력·부상은 파티 카드에서 한 번 보여줍니다. 직업·현실 생활·무림 돌파·피폭·수납·데이트 등 룰북 고유 정보와 편집 진입은 유지합니다.
- 등록 인물과 적·몬스터 기록은 20개씩 보여줍니다. 검색은 전체 등록 자료를 대상으로 합니다.
- 접힌 적 기록은 내용 카드를 만들지 않습니다. 펼친 뒤 선택한 페이지의 카드만 만듭니다.
- 구축 자료 목록도 20개씩 보여주며, 원문은 `원문 보기`를 눌렀을 때 화면에 넣습니다. 다른 페이지에서 선택한 자료는 유지됩니다.
- 저장·복구 목록과 놓치지마 상세 보고서는 해당 메뉴에 들어갈 때 읽습니다.
- 카드 설정 화면은 호스트의 전체 데이터베이스·채팅·모듈 원문을 화면 객체에 계속 보관하지 않습니다.

## 누적 실행 기록

새로 쓰는 저장 버전과 임시 저장은 현재 상태와 과거 실행 기록을 나눕니다. 기록은 채팅별로 32건씩 묶고 내용 해시로 재사용합니다. 기록 묶음 저장을 확인한 뒤 해당 저장 버전이 묶음을 참조하게 합니다. 기존 원본을 일괄 변환하거나 삭제하지 않습니다.

확인한 기록 묶음의 문자열 캐시는 4MiB, 저장 버전의 직렬화 자료 캐시는 4MiB로 나눠 합계 8MiB 상한을 유지합니다. 저장 버전 캐시에 누적 기록을 다시 합쳐 넣지 않습니다. 처음 읽는 기록 묶음은 최대 4개씩 읽습니다. 이 상한은 실제 계산 중 게임 객체나 DOM을 포함한 전체 메모리 상한은 아닙니다.

일반 화면은 현재 상태와 최근 최대 32건만 객체로 읽습니다. 구형 JSON 저장은 가능한 경우 전체 실행 기록을 파싱하지 않고 화면 부분과 최근 기록을 추출합니다. 기존 저장 버전의 체크섬과 맞지 않는 표현은 원래 전체 검증 경로로 돌아갑니다.

실제 판정·보상·누락 보완·리롤·되돌리기에서는 전체 실행 기록을 복원합니다. 행동 ID와 처치·지급 기록을 잘라 중복 보상 검사를 피하지 않습니다. 행동을 위한 상태 복사에서는 과거 영수증을 변경 불가 객체로 공유하고 수정할 게임 자료만 복사합니다. 화면용으로 읽은 상태를 그대로 저장하려 하면 차단합니다.

JSON 게임 백업은 기존 `universal-rpg-backup`, `schemaVersion: 1` 형식으로 전체 기록을 복원해 내보냅니다. 전체 백업은 여전히 전체 기록을 읽는 작업입니다. 모든 기록을 스트리밍으로 내보내는 기능까지 구현한 것은 아닙니다.

### 0.30.11 이하로 돌아갈 때

0.30.12에서 새로 저장한 내부 분할 형식은 이전 플러그인이 직접 읽지 못합니다. 교체하기 전에 0.30.12의 **저장·복구 → 이전 플러그인으로 돌아가기 → 이 채팅을 이전 저장 형식으로 변환**을 사용합니다. 0.30.12로 저장한 다른 채팅도 각각 변환합니다.

변환은 게임 값·행동 ID·체크섬·분기 연결을 유지하며 저장 표현만 바꿉니다. 중단되면 0.30.12에서 다시 실행할 수 있습니다. 완료 후 이전 플러그인으로 교체하세요. 변환한 채팅은 현재 플러그인 실행 중에는 이전 형식으로 계속 저장하고, 0.30.12를 새로 시작하면 다시 분할 저장을 사용합니다. 재사용 기록 묶음은 자동 삭제하지 않습니다.

## 배포와 진단

빌드는 앱과 UI에서 실제로 참조되는 모듈만 묶고, 배포본의 주석·불필요한 공백·지역 변수 이름을 줄입니다. 식 재작성 압축은 끄고 함수·클래스·객체 속성 이름은 유지합니다. 플러그인은 하나의 JS 파일이며 런타임 외부 코드 다운로드는 없습니다. 개발용 원본·소스맵·크기 내역은 `dist`에 별도로 생성합니다.

이번 로컬 배포 JS는 3,182,761바이트입니다. 변경 전 0.30.11 측정값 3,715,382바이트에서 약 14.3% 줄었습니다. 이 비율은 실제 실행 메모리나 로딩 시간의 감소율이 아닙니다.

호스트 진단의 `uiPerformance`에는 자료 읽기·화면 생성·미니 준비·행동 상태 복사의 횟수, 누적/최대/최근 시간이 들어갑니다. 최근 32개 종류만 보관하고 느린 구간의 이벤트도 간격을 둡니다. 게임 원문과 API 인증정보를 추가로 수집하지 않습니다. 파일 크기와 실제 실행 메모리는 다른 값입니다.
