# NyoruRPG 0.25.2 · 직접 연결·채팅 알림·창 열기

## Provider Manager 직접 연결

AI 연결에 선택 가능한 IPC 직접 연결을 추가했습니다. 현재 가동한 채팅의 룰북 도구를 등록하며 기본 대기는 600초(10분), 편집 범위는 30~3600초입니다. 보조 API 대기시간과는 별도입니다. 기존 판정·저장·actionId 영수증·카드 경로를 재사용하며 중간 processing 응답이나 모델 재호출 절차는 추가하지 않습니다.

플러그인의 현재 내부 이름은 `universal-rpg-engine`입니다. Provider Manager의 `//@allowed-ipc`에 이 이름을 추가해야 합니다. NyoruRPG 쪽 선언은 배포본에 포함됩니다. 직접 연결 그룹을 사용하면 같은 모델의 기존 NyoruRPG v3 broker 그룹은 끄고 한 경로만 사용합니다. 연결 모듈 v1은 유지합니다. Provider Manager 업데이트가 헤더를 교체하면 허용 이름을 다시 추가해야 합니다.

- 현재 채팅 토큰·전원·모듈·룰북 검사로 이전 채팅의 도구 호출을 차단합니다. 채팅 변경·전원 OFF·종료에 등록 해제와 취소를 연결합니다.
- 취소와 대기시간 만료를 해당 호출의 보조 AI 준비와 상태 적용 직전까지 전달합니다. 이미 저장한 판정은 되돌리거나 재굴림하지 않습니다.
- 등록만 초기화 순서에 대비해 2초 간격으로 최대 10초 재전송합니다. 게임 행동은 자동 재전송하지 않습니다. 등록 실패 후에는 설정의 저장·다시 등록으로 재시도합니다.
- 일반 입력은 유지하고 Provider Manager가 지원하지 않는 사전형·다형 입력 부분만 JSON 문자열로 받아 원래 값으로 복원합니다. 실제 룰북의 엄격한 입력 검사는 유지합니다. 긴 도구 설명도 입력 스키마 설명에 보존합니다.
- 진단에 등록·IPC callId/requestId·실행 단계·취소·응답 기록을 남깁니다. API 인증 정보는 등록하지 않습니다.

제공된 Provider Manager 1.16.3 소스에서 직접 연결의 기본 대기 30초와 함수별 timeoutMs 지원을 확인했습니다. 이것은 과거 MCP callback timeout의 원인을 모두 확정한 것은 아닙니다. 기존 MCP 식별자·공개 이름·저장 키와 카드 연결은 유지합니다. Provider Manager 참고 파일은 읽기만 했으며 수정·실행·재배포하지 않았습니다.

## 채팅 알림

`getRootDocument()`의 mainDom은 Risu 메인 화면 접근 허용이며 브라우저 알림/운영체제 권한이 아닙니다. 제보 문구는 이 단계 이후 알림 요소 조회에서 발생했습니다. SafeElement.setInnerHTML은 DOMPurify를 사용하고 Risu의 공유 정제 훅은 class에 x-risu-를 붙입니다. 알림 HTML과 조회 선택자에 이 접두사를 일치시켰고, 실제 권한 거부에만 권한 안내를 표시합니다.

근거: [Risu SafeElement와 getRootDocument](https://github.com/kwaroran/Risuai/blob/main/src/ts/plugins/apiV3/v3.svelte.ts), [공유 HTML 정제 훅](https://github.com/kwaroran/Risuai/blob/main/src/ts/parser/parser.svelte.ts). 실제 설치 호스트의 표시 결과는 아직 확인하지 않았습니다.

## 게임 상태 없는 창 열기

포켓리스·우분투에서 플러그인 창을 열 때 `can't access property "combat", w is null`이 발생했다는 제보에 따라, 현재 소스에서 같은 오류가 발생할 수 있는 경로를 수정했습니다.

`app.inspect()`는 아직 적용한 게임이나 진행 중인 거래가 없으면 `state:null`을 반환합니다. 그런데 현재 상태 화면의 `UI.overview()`는 이 값을 `action-gauge.active()`로 넘겼고, 이 함수는 `w.combat?.turnMode`에서 `w` 자체가 없는 경우를 처리하지 않았습니다. `?.`가 combat 뒤에만 있어 null 세계를 보호하지 못한 결함입니다.

행동 게이지 조회는 게임이 없으면 비활성으로, 전투 거리 조회는 표시할 결과가 없는 것으로 처리합니다. 모든 룰북의 플레이 화면도 게임 상태를 먼저 확인하고 준비되지 않았다면 시작·구축과 저장·복구로 연결합니다. 게임 읽기 오류는 원래 오류 메시지를 남깁니다.

앞선 0.25.1의 오류 조사에서 UI 진입과 상태 읽기 실패의 연결이 빠졌습니다. 이번에는 전체 창·시작 안내·미니보드와 룰북별 화면·공통 편집까지 소스로 이어 살폈고 다음 결함도 수정했습니다.

- 최초 정보 읽기가 실패하면 시작 안내 등이 미완성 `info`를 다시 읽어 원래 오류를 가릴 수 있었습니다. 읽기 실패 화면을 따로 두고 원래 오류·새로 고침·닫기를 유지합니다.
- 정보를 읽기 시작한 채팅과 결과의 채팅, 표시 직전 현재 채팅을 비교하지 않았습니다. 달라졌다면 혼합된 화면 대신 다시 읽기 안내를 표시합니다.
- 공통 능력치 투자·장비 착용 버튼은 저장할 때 화면을 열었던 채팅 ID를 전달하지 않았습니다. 기존 관리자 실행의 채팅 일치 검사에 이 ID를 전달합니다.
- 미니보드 닫기는 창만 숨기고 검사 알림의 `panelVisible`을 해제하지 않았습니다. 닫기와 채팅 알림 표시 상태를 함께 연결합니다.

표시를 위해 빈 게임을 자동 생성하거나 기존 세이브·사용자 편집·전원을 변경하지 않습니다. 전투 실행 규칙, 기존 MCP·결과 카드 연결, 연결 모듈 v1은 그대로입니다. 기존 사용자는 플러그인만 업데이트하면 됩니다.

확인한 범위는 소스의 null 전달·역참조 경로와 수정, 배포 파일 생성입니다. 제보자의 설치 버전·호출 스택은 받지 못했으므로 이 경로가 해당 환경에서 실행됐다고 확정하지 않습니다. 포켓리스·우분투 실사용 재현, 브라우저·모의 호스트·전투, 유료 API 및 별도 최종 검사는 수행하지 않았습니다.
