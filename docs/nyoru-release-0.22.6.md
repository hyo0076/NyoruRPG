# NyoruRPG 0.22.6

연결 모듈 v1 사용자는 **NyoruRPG.js만 교체**합니다. 시스템 재구축이나 저장 데이터 초기화는 필요 없습니다. 2026-10-01 사용자의 추가 요청에 따라 GitHub 자동 업데이트 배포에 포함합니다.

## 진단에서 확인한 내용

사용자 제공 `RPG-호스트-진단 (7).json`은 0.22.5의 에렌샤 기록입니다. 주사위 19는 서로 다른 행동 ID 7건, 여러 트랜잭션에 걸쳐 기록돼 있습니다. 따라서 단순히 새 actionId를 사용하자는 메인 AI의 제안은 충분한 해결책이 아닙니다. 일부 호출은 1~2초에 반환됐고, 두 호출은 준비에 약 25초·30초가 걸렸습니다. 모든 반복을 시간 초과 탓으로 단정할 수 없습니다.

에렌샤 코드에는 같은 인물·eventId이면 첫 act 결과를 그대로 반환하는 경로가 있었습니다. 공격·방어·기술이 달라도 반환 전에 구분하지 않았습니다. 생활 활동에도 비슷한 경로가 있었습니다. 이는 코드에서 확인한 결함입니다. 다만 해당 진단에는 **eventId와 전체 호출 인수·결과가 없어 이번 7건이 실제 그 분기를 탔는지까지 확정할 수 없습니다.** 난수 함수는 매번 보안 난수를 요청하며 고정 시드를 유지하지 않습니다.

## 룰북별 결과 재사용 경로

| 룰북 | 소스에서 확인한 경로와 처리 |
| --- | --- |
| 에렌샤 | act 및 제작·생활 활동의 사건 단위 전체 결과 캐시 제거. 새 공격·방어·작업을 별도로 실행. |
| 로맨스 판타지 | 일반 행동과 간단 전투의 전체 결과 캐시 제거. 능력치 VS의 원래 계산 및 하루 훈련 제한 유지. |
| 미연시 | 동일한 사회 엔진의 캐시 제거. 새 제안·훈련 시도는 새 계산과 반복 제안 패널티를 거침. |
| 무림 | 수련·탐구·가르침 이해·돌파·일반 판정은 새 시도로 처리. 가르침 습득 완료와 사건·전투 보상 중복 방지는 유지. |
| 공통 d100 | 전투에서 사건 ID로 과거 주사위 전체를 반환하는 동일 경로는 찾지 못함. 일반 판정은 같은 사건 ID 재사용 시 기존 `EVENT_ALREADY_CLAIMED` 차단이며, 이전 눈을 새 판정으로 반환하지 않음. |
| 얼터네이티브 헌터 | 공통 전투 경로를 사용하며 같은 결함은 찾지 못함. 경험치·획득 보상 중복 방지 유지. |

공통 탐험의 이미 조사한 장소·같은 장치 조작에 대한 제한은 유지했습니다. 이는 이전 주사위를 새로 굴린 것처럼 반환하는 방식이 아니며, 이미 처리한 내용이라는 안내를 반환합니다. 기술 정의·난이도의 재사용도 유지합니다. **정의를 기억하는 것과 실행 결과를 새 행동에 복사하는 것을 구분했습니다.**

## 놓치지마 검사

검사는 기본 OFF이며 **AI 연결 → 놓치지마 검사**로 켭니다. 새 입력 전에 검사 API를 사용합니다.

- 직전 최종 서술에 실제로 일어났지만 실행 기록이 없는 행동·소모품 사용·거래·퀘스트·사건 등을 기존 엔진으로 처리하고 저장합니다. HP나 돈을 임의의 숫자로 덮어쓰는 대신 비용·효과·수량·정산을 함께 계산합니다.
- 이미 호출된 결과와 자동 아군·적·연계 단계는 비교하여 중복 보완을 막습니다. 보완 호출도 고정 actionId를 사용합니다.
- 누락된 행동을 처음 계산한 결과가 서술의 성공 주장과 다를 수 있습니다. 실패·대기·미실행 이후의 성공을 전제로 하는 후속 보완은 중단하고 실제 결과를 보관합니다.
- 메인 AI에 수정 업무를 넘기지 않습니다. 다음 답변에는 이미 적용한 결과와 최신 상태만 전달합니다. 해석이 불확실하거나 순서를 소급 삽입해야 하는 경우는 검사 보고서에 남습니다.
- 동일 주사위 5회 이상과 이전 결과 재사용 표시는 보고서에서 확인할 수 있습니다. 반복만을 근거로 판정을 다시 굴리지 않습니다. 과거 전투 전체를 재구성하거나 저장된 실패를 서술상의 성공으로 변경하지 않습니다.

검사 AI가 모든 누락을 찾아낸다는 보장은 없습니다. 기계적으로 같은 행동이라고 판단되는 중복 후보는 보수적으로 기존 기록을 유지합니다. 수동 행동 권한·사용자 선택 대기는 검사도 우회하지 않습니다. 검사 보완은 기존 임시 저장에 기록되고 답변 확정·분기 저장 절차를 따릅니다.

## 진단과 변경 범위

다음 호스트 진단에는 사건 ID, 실제 결과, 상태 반영 여부, 동일 호출 재전송 여부와 하위 행동별 주사위를 남깁니다. 전체 프롬프트·API 인증정보는 추가로 기록하지 않습니다.

카드 배치, MCP 도구 이름·저장 식별자, 호출 완료 방식, 아군·적 자동 턴은 변경하지 않았습니다. 재호출·타임아웃 프로토콜을 새로 넣지 않았습니다. 기존 판정과 사용자 편집 데이터는 보존합니다.

첨부 진단·채팅과 관련 소스의 원인 분석, 수정 및 배포 생성을 진행했습니다. 사용자 요청에 따라 **별도 최종 검사, 자동 테스트, 브라우저, 가상 전투, 실제 RisuAI·유료 API 테스트는 하지 않았습니다.** 이번 증상의 실제 원인 확정 및 수정본 실사용 결과는 추가 진단과 사용자 테스트가 필요합니다.
