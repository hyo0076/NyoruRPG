## 전략 설계 추가 · NPC 임명과 충성·신뢰

2026-10-09 후속: 사용자는 전략 룰북의 건물·지역·장소에 아군 NPC를 임명하고 직무별 선호 스탯에 따라 효과가 달라지도록 요청했다. 같은 NPC의 여러 장소 겸직은 허용하며 효율·스트레스 패널티를 둔다. 이전 설계 문서의 일괄 중복 배치 금지는 이 지시로 대체한다.

NPC의 유저에 대한 충성과 신뢰는 각각 −100~100, 기준 0이다. 충성은 명령·업무 이행, 신뢰는 유저를 믿고 옹호하거나 의심하며 곁에 남는 태도다. 고신뢰·저충성은 태만해도 유저를 감싸고, 저신뢰·고충성은 일은 하되 유저를 감시하며 명분에 따른 배신·모략이 가능하다. 신뢰를 업무 성실성으로 바꾸지 않는다. 스트레스는 과잉 가동·겸직·연속 출전에서 증가하며 충성과 신뢰는 각각의 이유로 버티는 데 영향을 준다. 성격 태그와 각 NPC의 카르마를 이용해 실제 유저 결정에 대한 충성·신뢰 변화를 구분한다.

범위는 계속 신규 기능 설계다. 상세 계산 방향·UI·저장·롤백을 기존 설계 문서에 추가하며, 수치 계수와 스트레스 범위는 제안으로 표시한다. 이번 추가를 실행 코드에 구현하거나 새 배포·GitHub 게시로 확대하지 않는다.

같은 날 후속: 높은 스트레스에는 과로 패널티가 생기며, 유저와 실제로 만나거나 휴식·휴가로 스트레스를 회복할 수 있다. 과로로 쓰러지면 업무를 중지하고 충성·신뢰 모두에 패널티를 적용한다. 같은 쓰러짐을 조회할 때마다 재차 차감하지 않는다. 스트레스 회복과 관계 회복은 별개이며, 높은 충성·신뢰가 과로 면역을 주지는 않는다. NPC 능력치는 사용자가 의견을 요청한 상태다. 무력·통솔·지력·정무·매력·인내의 6개 기본 능력과 전문 숙련을 제안했으며, 이 목록·수치 기준·계수는 아직 사용자 확정 사항이 아니다.

사용자는 이어서 전쟁에서 NPC가 부상·사망할 수 있는지와 현재 구현 여부를 물었다. 기존 택티컬·지르코트의 부상·출혈·전투불능·사망 처리와 아직 실행 코드가 없는 전략 룰북을 구분한다. 전략에는 부대 손실 외에 이름 있는 NPC의 생명력·부상·치료·전사를 별도로 다루는 설계를 보완했다. 전투불능과 사망을 구분하고, 전사 시 생산·지휘 효과를 중지하되 인물 기록은 보존한다. 생명력 공식·전사 판정·회복 수치 등 제안은 아직 확정하거나 구현하지 않았다.

**RP의 몰입감을 위해 한 번 정한 RPG 규칙을 기억하고 실제 결과에 일관되게 적용한다.** 같은 파이어볼의 MP 비용과 피해를 AI가 매번 바꾸거나, 판정 없이 적을 처치하거나, 아군·적의 턴이 없어지는 문제를 해결한다.

- 메인 AI는 장면·행동·서술을 맡는다. MCP는 저장된 수치·규칙으로 판정하고 결과를 기록한다.
- 처음 필요한 인물·기술·효과는 보조 AI가 해석하여 준비한다. 알고 있는 것은 저장된 정의를 재사용한다. 매 행동마다 보조 AI를 다시 부르지 않는다.
- 사용자는 원문과 자연어 요청으로 준비·수정할 수 있어야 한다. 형식 오류 때문에 JSON을 직접 해독하고 수정하도록 떠넘기지 않는다.

## 전투에서 바꾸면 안 되는 동작

- 공통 d100·얼터네이티브 헌터의 `act`는 **요청 행동 전후에 필요한 아군·적의 턴을 자동으로 진행**한다. 메인 AI가 NPC 하나하나를 별도로 호출해야 하도록 바꾸지 않는다.
- 유저가 전투에 참가하지 않아도 실제 싸우는 아군·적은 판정하고 HP·비용·상태 변화를 기록한다. 관전자는 전투 참가자에 자동으로 넣지 않는다.
- 선공한 NPC가 먼저 움직이는 것 자체는 오류가 아니다. 일반 선공, 기습, 비전투 시연을 구분한다. 아직 들키지 않은 적에게 기습하면 지정한 공격자가 먼저 행동한 뒤 일반 순서로 이어진다.
- 자동 진행은 사용자에게 남아 있는 선택·미결 반응·전투 종료에서 멈추며, 관전은 기존의 제한된 턴 반복을 이어간다. 전투 전체나 다음 장면을 미리 작성하지 않는다.
- `steps`에는 자동으로 처리한 행동도 포함된다. 그 결과를 다시 호출해서 비용·피해를 두 번 처리하지 않는다. `requestedActionApplied:false`는 요청 공격·기술이 실행되지 않았다는 뜻이며, 앞서 기록된 다른 인물의 행동까지 없던 일이 되지는 않는다.
- 에렌샤와 사회 룰북은 별도 엔진이다. 공통 전투의 복구를 다른 룰북의 규칙 변경으로 확대하지 않는다.

## 함께 보존할 결정

- 일반 방어는 경감, 회피는 피해 회피이며 광역 회피에는 해당 능력이 필요하다. 실제 규칙을 바꾸지 않고 결과와 비용을 표시한다.
- 명중 후 연계와 명령 연계를 구분한다. 명령만 한 인물에게 불필요한 공격 명중 판정을 넣지 않는다. 후속 동료 공격은 동료의 일반 행동을 소모하지 않는다.
- 장비 칸은 보너스를 주는 자리다. 무기 착용으로 기술 사용을 제한하지 않는다. 아군·적·소환수·물체 대상과 조합형 효과·편집 기능을 보존한다.
- 출혈·독·보호막 등의 효과는 기존 보정과 같은 편집 흐름에서 선택·조합해야 한다. 데이터를 만들고 접힌 별도 영역을 뒤에 붙인 것만으로 기존 편집에 연결했다고 보고하지 않는다. 구축 초안과 플레이 중 스킬·장비, 세 룰북의 선택·필드·저장·표시를 함께 반영한다.
- 효과 편집은 **기술·장비 하나에 효과 목록 하나**다. 기존/새 저장 형식을 사용자용 영역으로 분리하지 않는다. 목록에는 이름·현재 수치가 보이고, 선택한 효과의 설정만 열린다. 기본 정보·효과·사용 조건은 나누어 편집하고, 선택한 항목을 편집하는 동안 다른 목록을 길게 붙이지 않는다. 옵션 존재·함수 연결·배포 생성만으로 사용 경험까지 완성됐다고 보고하지 않는다.
- 적에게 일반 인물의 MP/SP·지갑을 억지로 붙이지 않는다. 대련 때문에 기존 아군의 영구 종류와 재산을 적으로 바꾸지 않는다.
- 실제 등장한 NPC의 수치·관계 준비는 비전투 대화에서도 필요하다. “대결할 이유가 없음”을 등록·관계·성장·사건 기록 전체의 중단 조건으로 만들지 않는다.
- `rpg_play`의 편의 기능이 다른 도구의 역할을 없애는 것은 아니다. 조회·등록은 공격·회복·거래·보상 실행을 대신하지 않는다.
- 결과 카드는 `[NyoruRPG:번호]`로 해당 서술 문단 옆에 둔다. 추론 영역이나 답변 맨 끝에 모으라는 지침을 넣지 않는다.
- 연결 모듈 전환 후 룰북 지침은 시스템 구축에서 적용한 게임을 따른다(0.22.4 사용자 결정). 저장된 게임의 룰북을 임의로 전환하거나 초기화하지 않는다. 봇 상태창의 서사 정보는 유지하고 저장된 수치를 맞춘다.
- 기존 저장·소지품·성장·기술 효과는 보존한다. 없는 과거 실행 결과를 서술만으로 추정해 소급 지급하지 않는다.

## 해선 안 되는 수정

1. 한 오류를 없애려고 정상 기능이나 이미 합의한 자동화를 제거하지 않는다. **“NPC의 행동을 임의로 지어냄”과 “저장된 전투 순서에 따른 NPC 자동 행동”을 혼동하지 않는다.**
2. 입력 형식이 다르다는 이유로 의미 있는 효과를 지우지 않는다. AI 입력 정규화와 실행 데이터 검사를 구분한다.
3. 사용자 요구 없이 새 승인 단계·자동 재검수 호출·추가 설정·전역 중단 조건을 붙이지 않는다. 문제의 원인과 다른 기능까지 확장하지 않는다.
4. MCP의 보조 역할을 이야기 전개·승낙·적성 획득의 새로운 허가권으로 바꾸지 않는다. 사용자가 직접 선택하기로 한 항목은 그대로 둔다.
5. 구문 검사나 모의 실행을 실제 RisuAI·모델에서 잘 작동한다는 증거로 보고하지 않는다. 호출 시간·성공률도 측정 없이 주장하지 않는다.
6. 공개 도구 수가 적다는 이유만으로 구조가 개선됐다고 판단하지 않는다. 기능을 묶거나 숨길 때에는 기존 명령의 대체 경로, 필수 입력 전달, 다음 행동 안내를 함께 확인한다. 전달할 수 없어진 인수나 공개되지 않은 실행 코드를 “구현되어 있음”으로 넘기지 않는다. [0.17.3 기능 연결 점검](mcp-route-audit-0.17.3.md)을 갱신한다.

## 수정과 확인 방법

2026-09-29 / 0.18.8: 사용자는 카드 버그의 원인이 확정되지 않았으므로 **카드 표시를 0.17.5로 롤백**하라고 명시했다. `backups/before-combat-growth-0.18.0/src/`가 0.17.5 기준이다. 표시 훅·본문/카드 연결·출력 확정은 그 흐름으로 복원하고, 이후의 도구 완료 대기·추가 소유권 검사·미완료 답변의 누락 카드 선삽입·출력 재시도를 제거한다. 이후 추가한 게임 기능, 도구 목록 복구, 진단 보존, 저장된 실제 결과 반환은 유지한다. 카드 문제를 이유로 다시 같은 차단이나 대기를 임의로 넣지 않는다. 탐험 시간 초과가 해결됐다는 뜻은 아니다.

2026-09-29 / 0.18.7: 0.18.6의 `bootstrap.status` 단독 공개가 실제 Risu MCP 설정에서 도구가 하나만 남는 회귀를 만들었다. **플러그인 시작 시 채팅·저장 상태를 읽지 못했다는 이유로 도구를 숨기지 않는다.** 확인된 룰북 목록은 유지하고, 확인 전에는 지원 룰북의 공개 입력을 합친 목록을 제공한다. 상태를 읽지 못한 것을 특정 룰북으로 확정하지 않으며 실행은 저장된 게임으로 검증한다. 도구 노출과 게임 실행 가능 여부를 혼동하지 않는다.

2026-09-29 / 0.18.6: 사용자는 분석서의 호출·저장·표시 연결 정리를 승인했다. 요청 훅 횟수가 바뀌었다는 이유로 호출을 취소하지 않고 실제 채팅·사용자 입력·대화 이력을 확인한다. 실제 저장된 행동을 부가 요약·카드 오류 때문에 실행 실패로 돌려주지 않는다. 답변 확정 후 같은 입력의 후속 도구는 저장된 상태를 이어 쓰며 같은 호출 재전송은 기존 결과를 사용한다. 공개 목록을 읽지 못했다고 다른 룰북 목록을 내보내지 않고, 구형 직접 탐험도 현재 탐험과 같은 저장 경로로 연결한다. 카드가 먼저 그려지는 경우 진행 중인 해당 도구 결과를 기다려 표시하며 채팅 원문을 덮어쓰지 않는다. 비전투 효과 시간은 행동한 인물 기준이다. 별도 최종 검사·실사용 테스트는 여전히 실행하지 않는다.

2026-09-29: 사용자는 이전 답변에 카드가 붙는 문제가 다시 발생할 가능성을 감수하고, 출력 완료 알림만으로 진행 중인 MCP 결과를 거절하는 `RESPONSE_FINISHED` 차단을 제거하기로 결정했다. 0.18.5에서 이 차단만 제거하고 최신 선행 스킬 조건 수정, 채팅·새 요청 구분, 진단 기록은 유지한다. 선행 스킬 조건 버그가 카드 문제의 원인이었다는 것은 아직 가설이다. 카드 재발 가능성만으로 차단을 다시 넣거나 다른 전역 중단 조건을 만들지 않는다. 실사용 결과는 사용자가 확인한다.

작업 전 이번에 바꿀 동작과 유지할 사용자 결정을 확인한다. 변경 전 파일을 보존하고, 실행 코드와 연결된 도구 설명·모듈 지침·결과 안내까지 같은 의미인지 읽는다. 버그 수정에 관련 없는 룰북·UI·원본 참고 파일은 그대로 둔다.

2026-09-28의 최신 요청은 **별도 최종 검사도 생략**하는 것이다. 필요한 소스 읽기·수정과 배포 파일 생성만 진행하고, 반복 정적 검수·추가 비교·해시 대조를 최종 단계에 붙이지 않는다. 브라우저, 가상 전투, 모의 호스트, 실제 RisuAI 및 유료 API 검사도 실행하지 않는다. 실제 대화 검증은 사용자가 한다. 배포 생성과 실사용 확인을 구분해 보고한다.

0.17.1에서 잘못 넣은 “계속/관전일 때만 NPC 한 번 자동 행동” 제한은 0.17.2에서 되돌린다. NPC 턴 함수는 변경 전 0.17.0과 대조하고, 비전투 구분·임시 전투 편·현재 실행 수치 조회 수정은 유지한다. 보존본은 `backups/before-call-flow-0.17.1/`(0.17.0), `backups/before-auto-turn-restore-0.17.2/`(이번 복구 전 관련 파일)이다.

현재 NPC의 자동 기술 선택은 저장된 사용 가능 공격 중 위력이 큰 기술을 고르는 기존 정책이다. 실제 호출을 하지 않은 메인 AI의 서술까지 플러그인이 강제로 실행하는 구조는 아니다. 이 한계를 다른 자동 기능을 삭제하는 근거로 삼지 않는다.

## 0.18.0에서 사용자가 요청한 변경

- 기본 자동 아군·적 턴은 유지. 지휘관 모드 또는 행동 모드를 사용자가 켜면 해당 선택 경계에서 멈춘다. 턴테이블 기본 ON, OFF에서는 각자 행동 횟수를 센다.
- 방어/회피는 배타적 선택에서 **회피 판정 → 실패·잔여 피해의 방어**로 바뀐다. 광역 회피는 해당 기술이 필요하다.
- 공통 d100·헌터에서 한 번의 기회는 **전투마다 1회**. 전멸 시 구원투수를 실제 등록·행동시킨다. 게임오버 없음은 치료소·현재 XP 소실. 기본 전멸은 사망이며 뒤늦은 서술로 취소하지 않는다. 죽음 면역 패시브가 우선한다. 에렌샤는 원래 아바타 부활 규칙을 유지한다.
- 숙련도 직접 성장 편집은 d100·헌터만. 에렌샤의 분야별 숙련도/그레이드로 덮어쓰지 않는다.
- 이전 저장 정의를 사용자 동의 없이 새 카탈로그 효과로 덮어쓰지 않는다. 새 카탈로그는 새 구축/새 등록에 쓰고, 기존 기술은 항목별 편집한다.

## 0.19.0 사용자 결정

공통 d100·헌터·에렌샤에 상시/기술 소환, 타격별 명중, 명중 후 후속 기술, 일시/영구 자원·능력치 변화, 조건 진입 자동 발동, 투척 소모품 효과, 장비 내구도·수리를 추가한다. 연속 공격·연계는 저장된 정의로 같은 호출에서 계산하며 동료 일반 행동을 소모하지 않는다. 마모·수리 비율은 요청한 예시를 기본값으로 사용하되 장비별 편집한다. 처치한 몬스터는 등록 목록에서 제외하되 과거 결과는 보존한다. 사용자가 0.18.8 카드 표시를 잘 된다고 확인했으므로 호출/카드 연결을 다시 바꾸지 않는다. 이번 명중 판정 사진은 실제 첨부되지 않았으며 결과를 추정하지 않는다.

## 0.20.0 무림 결정

무림은 인물 레벨·경험치 없이 생명력/기력, 외공/내공 및 여섯 보조 능력, 23경지를 사용한다. 공통 저장 형태의 level=1은 호환용이며 표시·성장에 쓰지 않는다. 현재 경지가 초절정(8) 이상일 때 돌파 실패가 사망이다. 절정 후기에서 초절정으로 처음 오르는 실패는 주화입마다. 영구 기초 수치로 수행 방향별 조건을 판단한다. 천재는 최초 고정·일반 상태 문맥에서 비공개이며 사용자가 별을 눌러 보고 편집한다. 시간 미지정 수련도 길어질 수 있다. 고등급 비전은 같은 수련에서 더 많은 숙련을 얻는다. 명시하지 않은 콤보는 열린 초식·기력·저장 연결에서 고른다. 교전 성장은 타격 수로 중복 지급하지 않는다. 기존 다른 룰북의 성장 및 0.18.8 카드/호출 흐름을 바꾸지 않는다.

## 0.21.0 사용자 요청과 적용 범위

에렌샤 기술·숙련도 수동 추가, 본명/닉네임 한 인물 연결, 사용 횟수 0·빈칸=무제한, 켜진 턴테이블·아군/적 자동 턴, 퀘스트 상태 전달을 유지한다. 무기 마모는 요청한 기능이므로 전부 없애지 않는다. 자기 HP 소모·독 피해를 방어구 피격 마모로 처리하지 않는다. 구축 완료 뒤 플레이 편집은 이미 적용한 초안을 다시 적용하는 흐름으로 연결하지 않는다.

기본/정밀 구축/검사 API 분리는 사용자 요청이다. 놓치지마 검사는 이번에 명시적으로 요청한 선택 기능이며 기본 OFF다. 지난 최종 서술의 누락 기록만 보완하고 이미 계산한 결과를 서술에 맞춰 덮어쓰거나 미실행 공격을 소급 판정하지 않는다. 다른 플러그인보다 먼저 실행한다고 약속하지 않는다. 뉴뉴는 기본 연결을 사용하며 기술은 항목별 편집기에서 저장하고 끄면 대화를 삭제한다.

0.20.2의 15초 처리 중/재호출 안내를 제거하고 실제 callSerialized 완료 응답으로 복구한다. 사용자에게 재호출을 요구하는 우회책을 다시 붙이지 않는다. 이 복구만으로 이전 외부 콜백 타임아웃 원인이 해결된 것은 아니다. UI는 사용자가 붙여 준 refined CSS를 기준으로 적용한다. 최신 GitHub preview/nyoru-ui.css는 접근 시 404여서 임의로 다른 디자인을 만들지 않는다. 최종 검수·브라우저·모의 호스트·실제 Risu·유료 API·하위 에이전트는 이번에도 실행하지 않는다.

0.21.1은 사용자가 미반영 항목 보완을 승인했다. 뉴뉴의 제안은 기술 외 항목도 기존 편집·관리자 저장 경로로 연결하고 JSON을 직접 편집하도록 요구하지 않는다. 에렌샤 재구축에서도 명시된 본명·닉네임을 같은 인물로 연결한다. 검사는 전투 밖에서 실제 사용한 직접 소모품을 저장 규칙으로 보완할 수 있지만 과거 주사위·전투 결과를 새로 만들지는 않는다. 다른 플러그인 훅의 우선순위는 보장하지 않는다. 완료된 장소 생성 재사용은 허용된 호출의 결과를 보관하는 것이며, 미래 장소를 추측해 추가 API를 청구하는 기능이 아니다. call 12의 답변 완료/도구 반환 순서만으로 고정된 30초 제한을 확정하지 않는다. 카드 및 MCP 완료 전달 흐름은 유지한다.
