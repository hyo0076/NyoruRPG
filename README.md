## 시작

1. RisuAI 플러그인에서 기존 엔진을 `NyoruRPG.js`로 업데이트합니다.
2. 기존 사용자는 모듈을 켜 둔 채 **시스템 구축 → 기존 모듈을 연결 전용으로 전환**을 한 번 누르고 Risu를 새로 고침합니다. 기존 모듈 ID와 활성화 연결을 보존하므로 새 파일을 다시 가져올 필요가 없습니다. 처음 설치하면 함께 받은 `NyoruRPG.risum`을 사용할 봇/채팅에 연결합니다. 이후 일반 업데이트는 플러그인만 교체합니다.
3. **채팅 삼선 메뉴 → NyoruRPG → AI 연결**에서 API 주소·모델·키를 입력하고 **연결 설정 저장**을 누릅니다. API 키와 추가 인증 헤더는 이 기기에 보관하고 재시작할 때 불러옵니다.
4. 새 채팅은 **OFF**입니다. 시작 안내의 **네**를 누르고 게임 백업 JSON을 첨부하거나 **없어요, 새로 시작할게요**를 고릅니다. 안내를 닫았다면 채팅 메뉴의 NyoruRPG에서 다시 열 수 있습니다.
5. 새로 시작하면 **룰북 → 추가 요청·에렌샤 닉네임·테마 → 로어북 → 시작 인물 → 구축 시작** 순서로 준비합니다. 헌터·에렌샤는 사용자 페르소나만 골라도 되고, 다른 봇은 능력치와 세계관 자료를 함께 선택하세요. 추가 요청은 선택 사항이며, 시작 인물은 한 명이 기본입니다. 자료 선택은 구축에 전달할 내용만 정하며 Risu 로어북 활성 설정은 바꾸지 않습니다.
6. **이런 내용은 어떠냥?**에서 초안의 수치·기술·효과를 확인하고 필요하면 편집하거나 수정 요청합니다. **확인, 이대로 가동**을 누르면 저장과 함께 ON이 됩니다. 백업도 내용을 확인하고 **확인, 백업으로 가동**을 누릅니다.
7. 이후 평소처럼 채팅합니다. 사용하지 않을 때는 전체 창 위쪽의 **⏻ ON**을 눌러 끕니다. OFF에서는 RPG 도구·진행 지침·상태 주입과 자동 검사를 중단하며, 다시 켜면 기존 게임을 이어갑니다. 로판·미연시는 새 인물의 사회 능력치와 처음 필요한 행동을 준비합니다. 공통 RPG는 새 인물·기술의 수치를 준비합니다.

기존 세이브가 있는 채팅은 이번 업데이트에서 자동으로 OFF로 바꾸지 않습니다. 전원 상태는 채팅별로 저장하고 게임 롤백·백업 가져오기로 변경하지 않습니다. 이전에 저장한 결과 카드는 읽을 수 있습니다.

공통 RPG의 ‘봇 자료에서 자동 연결’은 수치가 있는 봇의 대응을 읽고, 수치가 없는 설정에는 내부 능력치를 만듭니다. 예전 헌터 연결로 저장한 게임은 그대로 읽지만 새 선택지에는 독립 헌터 룰북만 표시합니다. 경제 시뮬레이션은 포함하지 않습니다.

## 0.21.1 · 미반영 항목 보완

뉴뉴의 수정 제안을 기술 외에 장비·인물·룰북별 관계/퀘스트·전투 옵션까지 연결했습니다. 에렌샤 재구축에서도 본명·닉네임과 기존 ID를 연결하고, 구축 초안 편집 상태와 플레이 편집을 분리했습니다. 놓치지마 검사는 실제 호출 인수를 함께 비교하며, 전투 밖의 직접 소모품 사용 누락을 저장된 규칙으로 보완합니다.

완료된 탐험 장소 초안을 같은 조건의 답변 재생성에서 재사용합니다. 재호출 프로토콜과 카드 배치 변경은 없습니다. **첫 장소 생성의 외부 콜백 타임아웃이 해결됐다는 뜻은 아닙니다.** [변경 내용과 남은 한계](docs/nyoru-release-0.21.1.md)

에렌샤 기술/숙련도 추가, 사용 횟수 0·빈칸의 무제한 처리, 본명·닉네임 연결, 턴테이블 설정과 공격 주체 안내, 퀘스트 문맥을 보완했습니다. 공통 d100·헌터·무림도 기술 목록에서 새 기술을 추가할 수 있습니다. 직접 편집 후 시스템 구축을 다시 적용하는 것처럼 보이던 완료 초안을 정리했습니다.

**AI 연결**에 기본/정밀 구축/검사용 연결과 Gemini Vertex를 추가했습니다. **놓치지마 검사**는 기본 OFF이며, 켜면 다음 입력 전에 지난 서술의 누락 기록을 보완합니다. **뉴뉴 AI**에서는 질문하거나 기술 제안을 받아 기존 편집창에서 저장합니다. 끄면 대화는 삭제됩니다.

## 0.12.7 · 플레이 화면 정리

기존 플러그인 틀을 유지하면서 플레이 화면을 카드 중심으로 정리했습니다. 로판의 ‘마음의 거울’은 다른 인물→선택한 인물의 관계만 표시합니다. ‘인물의 바탕’은 명예·카르마·성향을 좌·중앙·우에 배치합니다. 미연시는 날짜·체력·소지금·능력치와 성장을 ‘상태’로 합쳤습니다. 공통 d100·헌터도 현재 상태와 소지품에서 소지금을 확인합니다. 수치 내역은 펼쳐 보고 기존 편집·배분·착용 기능을 그대로 사용합니다.

공통 d100·헌터 지침에 비전투 장면에서도 실제 등장한 인물을 등록하도록 명시했습니다. 네 룰북의 기존 인물 준비와 본문 중간 카드 배치 경로를 사용하며, 추가 API 호출이나 게임 재구축은 필요하지 않습니다. 실제 신규 인물을 처음 수치화할 때의 기존 API 호출은 발생합니다.

설계 버튼이 채팅 정보 객체를 문자열 ID와 비교해 같은 채팅도 변경됐다고 처리하던 오류를 수정했습니다. 실제로 다른 채팅으로 이동한 경우의 보호는 유지합니다. 제안이 생기면 현재 채팅의 설계도를 새로 읽어 자동으로 열고 해당 제안으로 이동합니다. 그 화면의 수락·거절 버튼으로 선택하며, 저장 중에는 두 버튼을 잠시 비활성화합니다. 채팅 본문의 카드는 기존 모양을 유지합니다. 기존 수락 대기 설계는 다시 생성하지 않고 선택할 수 있습니다.

## 0.12.5 · 룰북 선택 오류와 NPC 간 판정

모듈 선택값을 읽지 못했을 때 공통 d100으로 간주하던 코드와 그 값으로 도구 호출을 막던 검사를 제거했습니다. Risu가 토글에 따라 펼친 모듈 지침을 그대로 전달하고, 실제 계산은 저장된 게임의 룰북으로 처리합니다. 지침을 플러그인이 다시 선택하거나 자동 전환하지 않습니다. 기존 게임은 재구축할 필요가 없습니다.

로판·미연시에서 NPC도 행동자와 상대가 될 수 있습니다. 관계는 A→B와 B→A를 별도로 기록하고 해당 상대의 관계만 판정에 사용합니다. NPC끼리의 장면에 무관한 유저 관계를 새로 만들지 않습니다. 명예 보정은 행동자의 명예와 이번 장면의 공적 평판 관련성을 기준으로 계산하며, 같은 행동을 재사용해도 이전 장면의 공적 여부를 물려받지 않습니다. 승패만으로 명예를 지급하거나 차감하는 규칙은 추가하지 않았습니다.

## 0.12.4 · 모듈 룰북 선택과 서사 다이스 테마

모듈 토글에서 공통 d100·헌터·로판·미연시의 지침을 직접 선택합니다. 선택한 룰북만 메인 AI에게 전달하며 다른 룰북으로 자동 전환하지 않습니다. 모듈 선택과 시스템 구축에 적용된 게임의 룰북을 같게 맞춰 주세요. 테마는 서사 다이스와 같은 카툰·로멘스·판타지·사이버 4종입니다. 초기값은 공통 d100과 카툰입니다.

## 0.11.1 · 미연시 제안과 거절

미연시의 하루 행동 횟수 제한과 표시를 제거했습니다. 기존 게임은 재구축할 필요 없이 다음 처리부터 적용하며 능력치·관계·날짜·체력·소지금·과거 기록을 유지합니다.

행동하는 인물만 **보정 없는 1d100**을 굴려 상대 난이도보다 높으면 성공합니다. 난이도는 기본 100에서 제안에 쓰는 능력치·호감·취향·카르마 적합성 등을 반영해 계산합니다. 경계도나 친밀도 부족은 난이도를 올립니다. **난이도는 100을 넘을 수 있고, 이때는 100이 나와도 성공하지 못합니다.** 카드의 판정 근거에서 각 항목이 난이도를 얼마나 바꿨는지 확인할 수 있습니다.

같은 제안을 재차 요구하면 판정 전에 호감도가 낮아지고 경계도가 올라갑니다. 성공해도 이 불이익을 취소하거나 호감 보상으로 메우지 않습니다. 말만 바꾸거나 새 요청 ID를 사용해도 같은 제안이면 같은 목적으로 분류합니다. 반대로 단순한 맞장구나 다른 질문을 같은 장면이라는 이유로 재시도로 묶지 않습니다.

제안의 분류와 상대 취향은 처음 준비해 저장하고, 수치 계산은 코드가 담당합니다. 새 제안의 의미를 보조 AI가 잘못 분류할 가능성은 남아 있으며 카드에 해석 근거를 표시합니다. 실제 API·RisuAI 실행 검사는 하지 않았습니다.

## 0.11.0 · 얼터네이티브 헌터

**시스템 구축 → 얼터네이티브 헌터 → 시스템 구축하기 → 적용**으로 시작합니다. STR·CON·AGI·INT·SEN과 한 개의 레벨을 사용합니다. HP=CON×10, MP=INT×10, SP=AGI×10, 다음 레벨 경험치=현재 레벨×100입니다. 시작 능력치는 현재 레벨을 포함하고, 이후 레벨이 오를 때만 다섯 능력치 +1 및 배분점 +2를 더합니다.

첨부 카드의 원본 인물 53명은 수치·기술을 미리 보관합니다. **등록 인물**에서 확인하며 실제로 등장할 때 활성화합니다. 같은 인물을 다시 부를 때 자원이나 소지품을 초기화하지 않습니다. 명시된 원문 스탯은 없으므로 인물별 수치는 랭크·직업에 따른 고정 제안값입니다. 사용자 페르소나와 원본에 없는 새 인물은 선택한 자료로 준비합니다. 원본 NPC의 개별 커스텀 변경은 이 내장 수치에 자동 반영되지 않습니다.

헌터 초안을 적용하면 **이 채팅의 상태창 방식은 메인 AI, 스탯 표시는 켜짐**으로 설정합니다. 원본 Lua의 별도 상태창 AI와 중복 생성하지 않습니다. 도구가 현재 레벨·경험치·배분점·능력치·자원·장비·소지금 값을 제공하고 메인 AI에 원본 `☆` 상태창에 그대로 표시하도록 지시합니다. 날짜·시간·장소·퀘스트는 서사에서 유지합니다. 스탯 없는 상태창 옵션은 없습니다. 플러그인의 별도 끝 상태표도 생략합니다.

원화와 선택적 Coin은 각각 보관하며 임의 환산하지 않습니다. 피해 계수·d100 보정·보상 등 원문에 없는 실행 규칙은 보완값으로 고정합니다. 두 랭크 이상의 격차가 정면 공격을 바꾸면 원래 주사위와 적용 이유를 함께 반환합니다. 패시브는 별도 행동으로 사용하지 않으며, 마나 이전·조건부 중첩·회수 같은 미지원 특수효과와 낮은 MP/SP의 피로 묘사는 자동 계산 효과로 취급하지 않습니다. 자세한 범위와 53명 수치는 동봉 문서에서 확인할 수 있습니다.

구문·모듈 연결·배포 파일을 점검했습니다. 실제 RisuAI에서 상태창이 표시되는 과정과 메인 AI의 지침 준수는 실행 확인하지 않았습니다.

- **시스템 구축**: 자료 선택과 세계관 설정, 초안 확인·편집·적용. 자료 행을 눌러 선택하고 **원문 보기** 버튼으로만 원문을 펼칩니다.
- **장비·소지품**: 소지금, 장착 비교, 착용·해제. 각 아이템의 **편집**에서 종류·수량·가격·탄약·회복량·장비 효과를 항목별로 고칩니다. 판매·거래는 채팅 중 MCP로 처리하며 별도 수동 거래 화면은 없습니다.

인물을 준비할 때 기술 설명과 공격·회복·방어·회피·상태 효과의 수치를 함께 저장합니다. 아직 수치가 없는 이전 기술이나 나중에 생긴 기술은 처음 사용할 때 준비합니다. 단순 기본 공격이나 이미 준비한 기술은 보조 AI를 다시 호출하지 않습니다. 계산할 수 없는 특수 효과는 서사 설명으로 남기며 자동 적용했다고 표시하지 않습니다.

## 0.7.0 변경 · 이름으로 행동하고 저장된 규칙으로 진행

메인 AI는 `act`에 인물·행동·대상 이름을 보내며, 프로그램이 등록 확인부터 실제 기술·비용·피해·NPC 턴까지 연결합니다. 새 인물과 기술은 보조 AI가 준비하고 저장합니다. 아는 이름과 별칭은 저장된 정의를 사용하며, 처음 만난 표현을 같은 기술로 해석하면 그 별칭도 저장합니다. 자료 변경만으로 매 행동 전에 보조 AI를 호출하던 경로는 제거했습니다.

새 등장 인물은 기술 수치까지 함께 준비합니다. 새 적은 HP·피해·명중률·기술 횟수만 사용하고, MP/SP·지갑·성장 화면에 넣지 않습니다. 공통 모드에서는 이전에 저장된 쿨다운도 사용을 제한하지 않습니다. 새 기술에 임의의 숙련 피해 증가·비용 할인을 붙이지 않으며, 기존 기술의 명시적으로 저장된 성장 공식은 보존합니다.

행동 결과마다 표시 표식을 돌려주고, 메인 AI가 해당 행동 문단 뒤에 넣도록 연결했습니다. 선공 순서·피해·HP·반응 비용은 저장된 결과로 표시합니다. 누락된 표식만 답변 저장 시 뒤에 보완합니다. 잘못 서술한 처치·보상을 프로그램이 자연어 전체에서 감지해 다시 작성하는 기능은 아닙니다.

탐험은 처음 장소를 준비한 뒤 위치·경로·사건을 저장하며, 조우 방에 들어갈 때만 적을 준비합니다. 기본 NPC 진행은 저장된 사용 가능 공격 중 위력이 큰 기술과 현재 상대를 고르는 간단한 프로그램 정책입니다. 위임되지 않은 사용자 선택에서는 멈춥니다.

새 세계관은 원·달러 등 선택한 자료의 화폐를 준비합니다. 같은 이름·종류의 알려진 물품은 기존 가격과 효과를 재사용합니다. 장비 칸을 생략하면 프로그램이 배치하며, 양손 무기도 한 칸의 보너스 장비입니다.

기존 게임의 HP·기술·재산은 초기화하지 않습니다. 이미 저장된 적 구조와 화폐를 추정해서 바꾸지는 않으므로 간단한 적 구조는 새로 등장한 적, 새 화폐 기준은 새 구축부터 적용합니다. 화면에서는 기존 적의 MP/SP·지갑도 숨깁니다. 자세한 호출 예시와 범위는 `진행 구조 변경.md`를 참고하세요.

## 0.6.5 변경 · 방어와 회피

방어는 명중한 피해에서 저장된 경감량을 빼고, 회피는 단일 공격의 피해를 0으로 만듭니다. 둘 다 추가 주사위를 굴리지 않습니다. 일반 회피는 광역에 사용할 수 없으며, 별도로 준비한 광역 회피 기술만 가능합니다. 공격이 빗나가면 반응 비용을 쓰지 않습니다. 반응은 자기 턴 시작마다 회복합니다.

광역 기술 여부를 광역 회피 능력으로 잘못 사용하던 생성 코드를 분리했습니다. 이미 저장된 기술의 수치와 특수 회피 정의를 일괄 재작성하지는 않습니다. 새로 준비하는 기술부터 별도 속성으로 구분합니다.

공격에 기본 방어·회피 또는 반응 기술 이름을 함께 전달할 수 있습니다. 미리 고른 반응이 불가능하면 공격 판정은 보존하고 현재 가능한 반응을 반환합니다. 미처리 공격이 하나라면 반응 호출에서 공격 ID를 생략할 수 있고, 처음 요청한 턴 종료는 마지막 반응 뒤에 이어 처리합니다. 위임하지 않은 사용자 인물의 선택을 자동으로 정하지 않습니다.

피해 카드에 `피해 − 실제 경감량`, HP 전후와 반응 비용의 자원 전후를 표시합니다. 완전 회피·전량 경감으로 0이 된 피해에 취약 효과가 다시 피해를 더하지 않도록 했습니다. 피격 난이도 보정과 피해 경감은 별개로 설명합니다.

기존 채팅은 다시 구축할 필요 없이 이어갈 수 있습니다. 이번 배포 범위는 방어·회피와 그 반응 처리입니다. 예시는 `방어·회피 변경.md`에 있습니다.

## 0.6.4 변경

답변이 저장될 때 플러그인이 판정·피해·RPG 상태를 붙입니다. AI가 긴 카드 문자열을 복사하지 않습니다. 카드에는 실제 HP 감소와 이전/이후 HP, 보호막 흡수가 보이고, 펼치면 계산 위력·방어·저항 내역을 확인할 수 있습니다. 기존 메시지의 카드에는 당시 저장되지 않은 피해 수치를 지어 넣지 않습니다.

공통 위력을 기술에 중복 합산하던 계산을 수정했습니다. 장비는 능력치 보너스 칸이며, 기술에 무기 장착을 요구하지 않습니다. 양손 무기도 한 칸을 선택해 장착합니다. 일반 활은 화살을 바로 소비하고, 탄창형 무기는 장전 방식을 유지합니다.

스탯 화면에 기술 효과량·비용·상태 효과·재사용 수치를 표시합니다. 이미 준비한 기술은 한글·영문 병기 이름을 맞춰 재사용합니다. 새 적은 채집 재료를 함께 준비하며, 같은 종류의 적도 각각 별도 개체로 등록할 수 있습니다.

선택된 반응과 턴 종료를 공격 호출에 함께 전달하고, 여러 등장 인물을 묶어서 준비할 수 있습니다. 도구 응답은 관련 인물·변경 결과·다음 차례 위주로 줄였습니다. 서술만 끊겼다면 AI가 마지막 실행 기록을 읽어 재굴림 없이 이어 쓸 수 있습니다. 실제 소요 시간 개선은 아직 측정하지 않았습니다.

기존 채팅은 새로 구축할 필요 없이 업데이트 후 이어갑니다. 수정은 다음 행동부터 적용하며 과거 결과·HP·경험치·누락된 과거 전리품을 소급 변경하지 않습니다. 이전 양손 무기의 중복 슬롯은 다음 엔진 행동에서 한 칸으로 정리됩니다. 과거 백업을 가져오면 남아 있는 실행 기록에서 카드를 복원하며, 그 시점의 자원 스냅샷이 없는 상태창은 추정해서 만들지 않습니다.

## 기존 기록

0.6.3은 화면 구성과 디자인을 변경했습니다. 메뉴는 스크롤 중에도 유지하고, 같은 화면을 갱신할 때 펼친 원문과 스크롤 위치를 보존합니다. 로어북은 체크박스만 눌러 선택하고, 나머지 행은 원문을 펼칩니다. 버전은 화면 맨 아래에 표시합니다. 별도 iframe을 만들거나 외부 화면을 삽입하지 않습니다. RisuAI API 3.0이 자체적으로 제공하는 플러그인 격리 문서는 LongMemory와 같은 방식으로 사용합니다.

0.6.2부터 API 키와 인증 헤더는 RisuAI의 `getLocalPluginStorage()`에 저장합니다. 일반 설정·게임 백업·초안에는 넣지 않고 기기 사이에 동기화하지 않습니다. 이전 버전은 키를 저장하지 않았으므로 업데이트 후 한 번 입력·저장해야 합니다. 키와 추가 인증 헤더를 모두 비우고 저장하면 이 플러그인의 기기 인증 정보가 삭제됩니다. 다른 플러그인의 저장 항목은 건드리지 않습니다.

기기 저장소는 암호화 금고가 아니며 RisuAI의 다른 플러그인과 공유되는 저장소입니다. API 호출에는 지정한 서버로 인증 정보가 전송됩니다. 기기 저장소를 지원하지 않거나 저장에 실패하면 이를 표시하고 일반 동기화 저장소에 대신 키를 쓰지 않습니다.

0.6.1은 탄약 이름을 프로그램 내부 식별자로 변환하고, 무기·탄약·기술의 연결을 보관합니다. 기술 준비와 아이템 획득 시 현재 장비와 탄약 목록을 AI에 함께 전달합니다. 다른 이름을 같은 탄약으로 연결하려면 AI가 기존 탄약 또는 호환 무기를 가리켜야 하며, 구경만 비슷하다는 이유로 합치지는 않습니다.

0.6.0에서 탄약 형식 오류로 구축이 멈췄다면 업데이트 후 같은 채팅의 **다시 시도**를 누르세요. 원문과 선택 인물이 그대로이면 완료된 인물 자료를 재사용해 조립합니다. 처음부터 생성할 필요는 없습니다.

0.5.0의 숫자 기록과 이전 RPG 저장은 삭제하지 않습니다. 새 공통 규칙으로 강제 변환하지도 않습니다. 이전 규칙이 적용된 채팅은 기존 경로로 열리므로 **공통 d100은 새 채팅에서 시작**합니다. 0.7.0부터 원문 변경만으로 매 행동 전에 보조 AI를 호출하지 않습니다. 대화에서 발생한 원본 스탯 변화는 메인 AI가 `rpg_play.refresh`로 전달해 연결하며, 특정 봇의 Lua 상태창을 직접 읽고 쓰는 검증된 연동은 아닙니다.

## 확인 범위

이번 배포는 **코드 검토·JavaScript 문법 검사·빌드와 포장 확인**을 했습니다. 브라우저/가상 호스트 검사, API 호출 시험, 실제 RisuAI 실행은 하지 않았습니다. 수치 밸런스도 실사용 미검증입니다. 자세한 계산식과 자동화 범위는 `설계와 수치 기준.md`를 참고하세요.
