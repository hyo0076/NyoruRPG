# 개인 중계기 · AI 프록시 연결

중계기가 메인 AI에게 도구 목록을 전달하고, AI가 요청한 도구를 플러그인에서 실행합니다. 결과를 받은 AI가 최종 답변을 작성합니다.

## 기존 중계기에 적용

1. 중계기 실행창을 닫습니다.
2. 새 ZIP 안의 프로그램 파일을 **기존 `server.cjs`가 있는 폴더**에 덮어씁니다. `web` 폴더도 합칩니다.
3. 기존 `start.cmd`를 실행합니다. 첫 줄에 **Nyoru 개인 MCP 중계기 0.1.1**이 나옵니다.
4. 연결 안내 페이지를 새로 고치고 **Consumer key → 도구·주소 확인**을 누릅니다.

기존 `data` 폴더와 연결키를 그대로 사용합니다. 0.1.1부터 반복되는 도구 결과를 줄여 AI 입력량을 절약합니다.

## 플러그인·HTML에서 도구 등록

사용할 프로그램의 중계기 설정에 기본 주소 `http://127.0.0.1:18765`와 **Publisher key**를 넣고 연결합니다. 도구 그룹 이름을 기억해 둡니다.

프로그램에 연결 방식 선택이 있다면 **AI 프록시**를 고릅니다. NyoruRPG에서는 **AI 연결 → 개인 HTTP 중계기 → 프로바이더 연결 → AI 프록시**입니다.

안내 페이지에 **Consumer key**를 넣고 **도구·주소 확인**을 누르면 등록된 그룹과 도구가 표시됩니다.

## Provider Manager 설정

연결 안내 페이지에서 사용할 도구 그룹을 고르고 **AI 프록시**을 선택합니다.

Provider Manager의 **프록시 추가**에 입력합니다.

| 항목 | 값 |
| --- | --- |
| 이름 | `Nyoru Relay` |
| 프록시 URL | 연결 페이지의 AI 프록시 URL |
| 인증 토큰 | 실행창의 **Consumer key** |

사용할 모델을 편집합니다.

- **형식:** OpenAI 호환 · Chat
- **네트워크:** 커스텀: Nyoru Relay
- **도구 사용:** 사용 안 함

API 주소·API 키·모델 ID는 지금 사용하는 값을 유지합니다. 프록시의 인증 토큰 칸에 API 키를 넣지 않습니다.

예를 들어 도구 그룹이 `nyoruRPG1`이면 프록시 URL은 `http://127.0.0.1:18765/ai/nyoruRPG1`입니다. 기존 MCP 서버 주소는 보관해도 됩니다.

이 주소는 **모델의 네트워크**에 연결합니다. MCP 서버 URL이나 MCP 전용 네트워크 칸에 넣지 않습니다. 모델의 도구 사용을 꺼도 중계기가 등록된 도구를 AI에게 전달합니다.

## 채팅에서 사용

평소처럼 답변을 생성합니다. 도구 처리가 끝난 뒤 답변을 한 번에 표시합니다. Provider Manager의 ‘도구 호출 중’ 문구는 표시되지 않을 수 있습니다.

연결 페이지에서 **도구·주소 확인**을 다시 누르면 다음 횟수가 갱신됩니다.

- **AI 요청:** 프로바이더의 요청이 중계기에 도착
- **도구 실행 요청:** AI가 도구 사용을 선택
- **결과 수신:** 플러그인이 도구 결과를 반환
- **답변 완료:** 중계기가 최종 AI 답변을 받음

중단되면 같은 화면에서 오류 코드와 **최신 진단 내려받기**를 확인할 수 있습니다.

## 기존 연결로 돌아가기

모델의 네트워크를 기존 값으로 바꾸고, **도구 사용**에서 기존 MCP 그룹을 다시 선택합니다.

## 연결 오류 확인

| 표시 | 확인 |
| --- | --- |
| AI 요청 횟수가 늘지 않음 | 모델 네트워크의 프록시 선택, 기본 포트 `18765` |
| `AI_TOOL_CONFLICT` | 모델의 **도구 사용 → 사용 안 함** |
| `AI_NO_TOOLS` | 플러그인의 도구 등록, URL 끝의 그룹 이름 |
| `AUTH` | 프록시 인증 토큰에 **Consumer key** 입력 |
| `AI_CHAT_FORMAT` | 모델 형식을 **OpenAI 호환 · Chat**으로 선택 |

공개 HTTPS API의 OpenAI 호환 Chat 형식과 텍스트 답변을 지원합니다. Gemini도 API 제공자가 이 형식을 지원하면 사용할 수 있습니다.
